## Outcome and non-goals

The approved [tables-v2 mock](../design/mocks/proposals/tables-v2.html) is applied
to every list:

- **Column layout:** the name column is on the left. Every other column is
  centred, sized to its content and evenly spaced. This applies to the SLI,
  SLO, datasource and agent lists, through the shared `ui-list-table` class and
  the SLO subgrid.
- **SLI list:**
  - The name and its datasource.
  - Health in data-state words.
  - The strip, without exact values.
  - Last sample as one value and its age.
  - SLOs as a count, or "Create SLO".
- **SLO list:**
  - Status as a chip only.
  - Objective.
  - Budget · 7 d, then Budget left.
  - Burn rate, 1 h only.
  - Budget runs out.
  - Rows open on click and allow text selection.
- **Focus:** fields show one accent border instead of the offset ring.
- **Records:** catalogue example, design guide, ADR-0032 and mock index.

Not in this task:

- Linking the SLO count to an SLO list filtered by SLI, which needs a backend
  filter.
- Stacking the agent list at 360 px. It still scrolls sideways, as before.
- The agent detail's datasource table. Its first column is state, not a name.
- Timeline exact-value tables, which are ledgers rather than lists.

## Implementation evidence

- **Tests:**
  - A new vocabulary test covers all six SLI states.
  - The SLO row test covers click navigation, and no navigation after a text
    selection, an inner link click or a modifier click.
  - The SLI list test asserts no exact-values disclosure and the "6 SLOs" link
    with names in its tooltip.
  - The SLO status tests assert the chip only, with the reasons in the tooltip.
- **Verifiers:**
  - The SLI verifier now checks the count link and the last-sample tooltip
    instead of the list's exact-values table. It follows the count to the SLI's
    objectives and on to the SLO.
  - The SLO verifier uses the renamed `app-slo-link`.
  - The datasource and agent verifiers navigate to their lists. They measure
    every non-name cell within 1 px of its column centre at 1440 and 1024 px in
    both themes, and capture each list at 1440, 1024 and 360 px.
- **Defects found and fixed while verifying:**
  - My first-line alignment shrank stacked SLO rows to half the card at 1024 px.
  - A leftover minimum width made the SLI table overflow at 1024 px.
  - A verifier step I added went back twice without waiting, so the second step
    raced the first.
  - A chip reason was cut off because its percentage cap could not widen a
    content-sized column.
- **Separate, earlier issue:** the performance verifier still expects the SLO
  count subline that ADR-0031 removed.

## Greptile review follow-up

  when the list was empty or its first read failed. Both now keep a refresh-only
  toolbar row in those states. New unit tests cover a failed read, then an empty
  list, then the list loading for datasources, and an empty agent list then
  loading.

  the agent name with the `StatusChip` instead of the removed `.ui-mark__row`.
  It is syntax-checked but not run, since the Compose journey runs only on
