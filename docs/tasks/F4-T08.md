## Outcome and non-goals

Implement the reviewed slice A persisted authority and revision-fencing foundation.
Maintenance changes must be SLO-scoped, immutable, audited, idempotent and subject
to historical permissions checked at server transaction time. No stale worker may
publish results under a newer exclusion snapshot.

This plan does not redefine maintenance as an alert-only feature or reduce
SPEC-0016. Public API/UI, production adoption and performance acceptance remain pending.
Public parity, overlays, report evidence and all accepted calculation/lifecycle
semantics remain required before feature completion. Do not edit the F4-T05
worktree; it is owned by the primary for integration/publication.
Occurrence-based alert AC-07 can be verified through A+B and engine integration
without completing composite/slice models, imports or the full public maintenance
UX. Those separate dependencies retain their accepted contracts.

## Implementation decisions

- Migration 0054 backfills exclusion state zero and initializes it with each new
  SLO root, so zero-to-first revision can be fenced without a missing-row race.
- Mutation order is session authority, replay advisory lock, maintenance identity,
  sorted SLO roots, then sorted exclusion-state rows. Existing SLO metadata writes
  lock a single SLO; service catalog paths take their catalog/service locks before
  SLO creation/dependency checks and do not request a maintenance root afterward.
- Source invalidation bounds and a work version commit with each change. Worker
  claim/lease execution, rolling-window expansion and production invalidation
  consumers are slice B; stale acknowledgement cannot delete newer pending work.
- Revision/scope/change UPDATE is prohibited. DELETE remains possible for a future
  bounded retention transaction after its 400-day and retained-reference checks;
  no automatic cleanup or public delete operation exists in slice A.
- Snapshot reconstruction is an internal repeatable-read primitive. Its query
  growth and fragmented-mask admission need slice B measurement before production
  adoption; this task does not claim a bounded alert evaluation path already exists.
- Internal list uses 2N+1 queries (up to 401 at limit 200); public exposure requires
  batching and measured latency. No public maintenance endpoint is added.
