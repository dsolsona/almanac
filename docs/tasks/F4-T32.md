## Outcome and interfaces

One explicit processor turn connects durable claims, horizon gaps, pinned cutoffs,
canonical evidence, repeated-cutoff ranges, atomic publication and pending/failure
deferral. All admission, lease, concurrency, horizon, retry and exhaustion limits
are mandatory caller inputs; this does not adopt public defaults. The caller owns
the tick/clock and cancellation. Do not register a background production loop.

Claim only a wave that can execute immediately, bound waves and total work per
turn, and preserve once-per-policy-per-tick fairness. Pending aggregates do not
consume failure attempts or advance boundaries. Real failures accumulate durable
bounded retry state; exhaustion stops claims and remains explicit unavailable
processor health, preserving last known occurrence state. Do not fabricate SLO
evidence from an engine exception. The retry transaction preserves its pending
cutoff and records audit atomically; the later management caller owns session,
role, replay receipt and completion checks. No public bypass is introduced.

## Acceptance

- Real source counts produce one occurrence; a second worker/tick cannot duplicate
  the evaluation. No-data intervals preserve an existing occurrence.
- A dirty shared source defers its original pinned boundary while another policy
  progresses. After publication it retries the same boundary before later work.
- Duplicate cutoffs record ranges, never evaluations or freshness claims.
- Beyond-horizon work records a gap atomically before the retained head advances.
- Concurrent turns have disjoint claims and bounded concurrency. Cancellation
  leaves leased work reclaimable; no in-memory queue is authoritative.
- Injected actual storage failure rolls back publication, records bounded retry
  metadata and stops at caller-defined exhaustion. Pending consumes no attempts.
- No production scheduler, destinations, public API/UI, nonzero-mask adoption or
  sustained capacity acceptance is claimed by these focused cases.

### Pending retry timing correction

Independent review identified that calculating retry availability before admission
and locking could make an ordinary pending deferral fail with `ErrAlertInvalid`.
A real cursor lock and atomic clock reproduce it: a 10 ms retry interval elapses
during a controlled 20 ms wait (red, 0.446 s). Deferral now receives the explicit
retry duration and computes availability after locking, with the existing lease,
claim and once-per-tick fences retained. No schema, admission or default changes.
The regression asserts the original scheduled boundary and cutoff remain pinned,
the claim is released, failure attempts stay zero and the full retry interval
starts at the post-lock time. The earlier expired-lease regression still passes.

### Resource and database backpressure correction

The processor originally treated only aggregate pending and stale work as
deferral. Two real PostgreSQL regressions demonstrate that temporary database
backpressure instead spent the failure budget. With the existing DerivedTraffic
250 ms lock timeout, a publication blocked on a fixture advisory lock returns
SQLSTATE `55P03`, records failure attempt 1 and exhausts an explicit one-attempt
test budget (red, 0.746 s). Filling the existing derived pool produces the same
incorrect exhaustion after its actual bounded admission refusal (red, 0.645 s).
The latter fixture waits for the pool's cancelled-acquisition counter before
restoring capacity, allowing the processor to persist its outcome without a
sleep-based release or changed production limit.

Backpressure now follows pending deferral with a controlled
`database_backpressure` reason. The original boundary/pin remain unchanged, the
claim is released and failure attempts stay zero. If capacity remains unavailable
even for the deferral write, the error is returned and the existing lease remains
reclaimable; no failure attempt is invented. Cancellation still leaves work for
expiry/reclaim. Unknown database errors and inconsistent facts retain failure
accounting. Explicit source aggregate exhaustion is deliberately excluded from
this classifier: its separate canonical adapter owns per-window
`calculation_failed` evidence, rather than indefinite pending work.

Canonical reads also revealed a classification loss: `operationError` sanitized
SQLSTATE `40001`/`40P01` into indistinguishable ordinary errors. A focused
regression fails for both in 0.016 s. The sanitizer now preserves only a safe
retryable-conflict sentinel while keeping its exact existing displayed message;
the original PostgreSQL error, details and query fields are not retained. No
other consumer's retry policy changed. Because this sanitizer is shared, the
verification selection includes the existing operation timeout, cancellation,
SLO evaluation retry and operational-read serialization tests alongside the
processor cases, rather than a broad application suite.
