# F4-T54: Manage maintenance from the CLI

- Status: in review
- Governing contracts: [SPEC-0016](../specs/0016-maintenance-exclusions.md) AC-04
  and [SPEC-0010](../specs/0010-api-and-cli.md)
- Dependency: [F4-T53](F4-T53.md), PR #131
- Worktree: `.worktrees/maintenance-cli` on `codex/maintenance-cli`

The `maintenance` command accepts a protected authenticated profile. It uses
the accepted maintenance API for `list`, `get`, `timeline`, `create`,
`update`, `end`, `cancel` and `withdraw`. List and timeline offer bounded
pagination. Get accepts an optional historical revision. Writes accept protected
JSON input or stdin and require the caller's idempotency key. All writes except
create require the exact ETag returned by the API.

The command preserves the common JSON envelope and exit codes. Validation
happens before profile access. The client reports uncertain writes with
reconciliation guidance and leaves replay in the caller's control. Alignment
and revision conflicts provide safe bounds and revision guidance.

The executable objective journey validates CLI create and replay, timeline,
update, stale write, cancellation, historical reads and list through the
ordinary HTTPS backend and PostgreSQL. The API checks in the same journey cover
prospective end and withdrawal. Production UI work follows separately.
