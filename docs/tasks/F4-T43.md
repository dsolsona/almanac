## Outcome and boundary

One unwired shared totals entry point consumes exact eligible/excluded populations
plus a bounded certificate of excluded coverage. It produces the same result as
the existing raw-mask evaluator without receiving the complete fragment list.
Do not add SQL, schema, storage consumers, public API, runtime registration,
production defaults, or an alert-specific quality/calculation formula.

## Confirmed exact interface

```go
type ExclusionCoveragePoint struct {
    At time.Time
    ExcludedBefore uint64
}

type WindowCoverage struct {
    LatestEligibleEnd time.Time
    Points []ExclusionCoveragePoint
}

func EvaluateOperationalCoveredTotals(context.Context, WindowInput, WindowTotals, WindowCoverage) (WindowResult, error)
func EvaluateOperationalCoveredTotalsSummary(context.Context, WindowInput, WindowTotals, WindowCoverage) (WindowResult, error)
```

Each point is an exact cumulative excluded whole-interval count at its boundary,
from one immutable mask and grid. The common prefix baseline is arbitrary and
cancels in differences. This is a bounded storage-supplied certificate, like the
existing exact totals, not independent authentication of a persisted mask.
Source/definition/exclusion identities and database publication fencing remain the
storage caller's obligation. The future compiler obtains each rank with its
indexed predecessor lookup; no scan of all fragments is required.

Accept exactly the deduplicated, strictly time-ordered required boundary set:

1. Effective eligible start, effective retention start and evaluation end, using
   the same validity/retention rounding and clipping as the raw evaluator.
2. Latest eligible interval end and that endpoint minus one cadence. Their rank
   difference must be zero; the suffix through evaluation end must be fully
   excluded. The latest endpoint may precede the window when fully excluded.
3. When observations exist: first observed start and its end, last observed end
   and its start. Both individual intervals must have zero excluded count.

There are at most nine points, independent of declaration count, overlap,
fragmentation or elapsed time. Reject missing, duplicate, extra, unaligned,
nonrepresentable or out-of-order points; decreasing ranks; or rank increments
larger than the whole-interval distance between adjacent points. Equal instants
are one point, not duplicate entries. Compute differences with checked arithmetic
without signed-duration saturation or conversion overflow.

The same points establish excluded expected and retained interval counts, hence
expired excluded counts. They also establish excluded intervals within the
observed first/last span, so observed count cannot exceed eligible span capacity;
one observed interval must have exactly one cadence between its bounds. This
retains endpoint inclusion and span-feasibility checks that would be lost if only
two exclusion totals and a freshness timestamp were supplied. Cross-consistency
of all prefix differences rejects contradictory subrange claims.

Reject simultaneous raw observations or a nonempty raw exclusion mask. Existing
`WindowTotals.Excluded` remains the numeric/count population input. Absent
excluded event totals remain unknown; no inference of zero from a coverage count.
Receipt metadata remains optional. Validate all ordinary count/rational/time
constraints and observation bounds, with cancellation and no mutation/aliasing of
caller-owned slices, rationals or timestamp pointers.

## Shared implementation shape

Extract only the coverage selection from the existing shared window result:
raw masks compute their current counts/endpoint; the new entry point supplies its
validated counts/endpoint. Both flow through the same `WindowSweep.result`
quality, freshness and exact arithmetic. Reuse totals validation rather than
copying an independent maintenance evaluator. Existing raw/totals APIs and their
validation behavior remain unchanged. The new summary API defers formatting via
existing `WithValues`, preserving exact rational results.
