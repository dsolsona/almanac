## Outcome and scope

Expose the existing authentication service through a bounded HTTP handler, with
generated contracts, protected cookies, session-bound CSRF and strict origin/source
handling. Prove the real HTTPS/API/PostgreSQL journey before runtime/UI/CLI wiring.
This task does not enable backend server modes, add an ordinary management API or
claim browser acceptance. Subsequent runtime wiring must enforce single backend
ownership and startup readiness before exposing this handler.

[ADR-0016](../adr/0016-authentication-retry-behavior.md), accepted2026-10-26, explicitly
excludes authentication from management-command receipts. A supplied Idempotency-Key
header returns501 `capability_unavailable` before service work; never silently replay
authentication or store recoverable session secrets to simulate receipts. Document
and test this boundary in OpenAPI. Clients recover uncertain outcomes through context
and deliberate sign-in, without automatic mutation replay; those clients follow later.

Own `internal/authhttp/`, API contract/generation configuration and generated outputs,
a non-mutating session inspection in storage/application service, fixed Makefile test
selections and only the generated-interface adaptation needed in `internal/uihttp/`.

## Interface and transport boundary

Create `authhttp.New(service *authentication.Service, options Options) (http.Handler,error)`.
Options contains `PublicOrigin string`, `TrustedProxyCIDRs []netip.Prefix`, and
`Now func() time.Time`. Require a nonnil service/clock and one canonical HTTPS origin
without credentials, path, query or fragment; reject invalid ports and wildcards.
Copy/validate prefixes and serialize clock calls. Constructor creates a random
32-byte private HMAC key; it is not an encryption key or persisted session secret.
No public injection of a signing key or bypass/test switch.

The handler owns exactly four POST routes below, and no health/static endpoints.
Unknown routes are 404; unsupported methods are 405 with Allow: POST, without
redirects, body decoding or service calls. Reject encoded/dot-segment aliases.
All responses use Cache-Control: no-store and X-Content-Type-Options: nosniff.
No CORS allowance. Before cookies/body/service use, require exactly one Origin
header equal to PublicOrigin; missing, null, duplicate and cross-origin are 403.
Never infer the public origin from Host or forwarding headers.

Direct requests require r.TLS. For a direct peer within an explicitly trusted
prefix, allow TLS termination only with exactly one X-Forwarded-Proto: https.
The same trusted peer may supply exactly one canonical IP in X-Forwarded-For;
require this single value for the forwarded path, reject chains/commas/ports/zones,
and use it for login admission. For untrusted peers ignore all forwarded headers
and use RemoteAddr, which must parse as a valid IP:port. Untrusted plaintext fails
403. No trust defaults, including loopback. The UI proxy will be wired separately;
its existing strip-all behavior remains intact in this increment.

Require application/json (optional charset=utf-8 only), no Content-Encoding,
maximum4096 body bytes, one object, exact declared members and types, no duplicate
members or trailing JSON. Empty bodies/null are invalid. Preserve password bytes.
Before reading, set a5second read deadline with http.ResponseController using wall
time (not the injected domain clock); restore the deadline after successfully
consuming the bounded body. Use MaxBytesReader so oversized requests inform the
server to close; failure paths must not remove bounds on draining unread bytes. Failure
to set the deadline fails closed with503 before service work; middleware wrappers
must support Unwrap. A stalled body returns408 `request_timeout`, with no detached
reader goroutine. Unit recorders can expose SetReadDeadline to test the boundary;
real TLS tests must prove a stalled chunked body terminates. Runtime still owns
header, connection, write and shutdown timeouts before production exposure.
Generate Go/TypeScript types from OpenAPI; never edit generated output. The shared
generated ServerInterface gains the four operations; the UI health implementation
delegates each to its existing fixed backend proxy. It never implements local
authentication. The auth adapter can register its four exact handlers directly
without registering the generated operational health routes.

## Routes and response contracts

All JSON properties use snake_case. Problem bodies contain code, message,
request_id and field_errors (always an array; empty when not applicable). Generate
a fresh random 16-byte hex request ID; never echo attacker-controlled IDs or bodies.
Return X-Request-ID. Do not log secrets, body, cookies, tokens or arbitrary errors.

| Route | Body | Success |
| --- | --- | --- |
| `/api/v1/auth/context` | `{}` | 200 `{csrf_token, session}`; session is null or safe identity |
| `/api/v1/auth/login` | `{login, password}` | 200 `{csrf_token, session}` and fresh session cookie |
| `/api/v1/auth/password` | `{current_password, new_password}` | 200 `{csrf_token, session}` and replacement cookie |
| `/api/v1/auth/logout` | `{}` | 204, clear session and pre-auth cookies |

Safe identity fields are user_id, login, role, restricted. Never return the raw
session secret, verifier, storage session ID, credential revision or epoch in JSON.
`__Host-almanac-session` is Secure, HttpOnly, SameSite=Lax, Path=/, no Domain,
with expiry equal to the service's absolute expiry and Max-Age at most43200seconds.
Clear with the same security attributes and Max-Age=-1. Reject duplicate cookies
with either security-sensitive name; do not select the first ambiguous value.

Context is a read-only bootstrap operation: it never changes application data or
session last-seen time, and requires the exact Origin and JSON boundary but no prior
CSRF token. Add `storage.InspectSession(ctx,url,digest,now)` and
`Service.Inspect(ctx,secret)` with the same current authority and expiry validation
as AuthenticateSession/Authenticate but no TouchSession. Share the existing internal
validation flow without weakening Authenticate's monotonic idle update. An invalid
or expired session is cleared and returns anonymous context; storage outages are503,
never anonymous success. Restricted identity is permitted only as authentication
context for password change/logout, not as application-data access.

Anonymous context creates/reuses a canonical random32byte pre-auth cookie named
`__Host-almanac-preauth`, with the same cookie protections and Max-Age600seconds.
This cookie grants no identity or initial-owner authority. Successful login clears
it. Login requires its CSRF token and rejects a present session cookie with409
`session_present` (client refreshes context or logs out first); never silently switch
accounts and leave an abandoned authenticated session. Password change requires a
session cookie and its bound token. Logout accepts a correctly bound session or
pre-auth token, calls service.Logout when a session exists, then clears cookies;
unknown/already-revoked sessions are idempotent. Storage failure returns503 and
does not pretend server logout succeeded.
When both cookie names are present, logout requires the session-bound token; a
pre-auth token is accepted only when no session cookie exists. Never let a login
context token authorize logout of an existing authenticated session.

## CSRF implementation choice

Implement the standard session-bound HMAC token pattern using crypto/hmac and
SHA-256, not a general cryptography framework. Its input uses a fixed version,
purpose (`login` or `session`), current opaque cookie value and random nonce,
with length-prefix encoding to avoid concatenation ambiguity. The transmitted
token contains only nonce and MAC, each32bytes, encoded as canonical unpadded
base64url of the concatenated64bytes. It never embeds the session cookie value.
Validate exact length/canonical encoding before hmac.Equal, and require exactly
one X-CSRF-Token header for login/password/logout. Different sessions, purposes,
nonces, tampered bytes, duplicate headers and missing cookies must fail403
`csrf_invalid` before password work or session mutations.

Context can mint a token without invalidating existing tokens, preserving tabs.
Login/rotation mint tokens for the fresh session; old tokens cannot authorize the
replacement. The process-private key means a restart invalidates CSRF tokens but
not persisted login sessions: refreshing context recovers safely. No unbounded
in-memory token registry or new deployment secret is introduced. This is a
coordinator implementation choice within the accepted token/origin requirement;
its restart cost is one context refresh, with no automatic replay of mutations.
Reference: [OWASP CSRF prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

## Error mapping

Use400 `invalid_request` for malformed inputs,413 `request_too_large`,415
`unsupported_media_type`,403 `origin_rejected`/`secure_transport_required`/
`csrf_invalid`,401 `unauthenticated`,409 `session_present`,429 `rate_limited`,
503 `authentication_unavailable`. ErrAttemptExpired is401 with no secret output.
On a proved current password, new-password policy failures are422
`password_policy` with a field error for new_password; unchanged is422
`password_unchanged`. Common/structural password-policy errors are safe; unavailable
policy data and other operational errors are503. Never expose raw error strings.
Retry-After is a positive integer ceiling of the typed duration in seconds.
Cookie issuance and response success happen only after service success. Failure
must not clear/replace a valid session or fabricate a successful mutation.

## Acceptance and verification

1. Real TLS HTTP client/cookie jar plus real service/Argon2/PostgreSQL completes
   context→restricted login→password rotation→normal context→logout. Old password
   and old session fail; response JSON contains no credential material. Client trusts
   the test server certificate explicitly; never disable production security.
2. Origin, direct/forwarded TLS and source-address matrices reject spoofing,
   duplicate headers, forwarding chains and invalid IPs. Two forwarded addresses
   behind an explicitly trusted proxy retain separate source budgets; untrusted
   forwarding never evades the real shared source budget.
3. CSRF missing/tampered/noncanonical/duplicate/wrong-purpose/cross-session tokens
   fail before service mutation. Old tokens fail after rotation, two valid tokens
   work across tabs, and a replacement handler key requires context refresh while
   the persisted session remains valid. No automatic mutation retry.
4. Cookie creation/replacement/deletion flags, exact expiry, duplicate-cookie
   rejection, no raw-secret JSON, no CORS and no-store apply on successes/errors.
5. Real wrong-password/unknown-user/throttle cases map safely, with exact positive
   Retry-After ceiling and no session issuance. New policy rejection preserves the
   current session; operational/schema failure is503, not401/anonymous success.
6. Strict decoding covers oversize chunked bodies, duplicate/unknown keys, invalid
   UTF-8, wrong types/null, unsupported encodings/media, trailing JSON and unsafe
   paths/methods. Bound bodies before expensive service work.
7. InspectSession has real DB tests for current authority/expiry/role restrictions,
   no last-seen writes, and no idle extension by repeated context requests. Existing
   Authenticate/session tests still pass. Cancellation propagates and work is bounded.
8. Generated contracts remain reproducible and existing UI proxy/health behavior
   stays intact. Extend fixed unit/race/integration package lists with authhttp only;
   integration `all` remains explicit serial packages and the fixture guard remains.
