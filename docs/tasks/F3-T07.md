## User acceptance checklist

- Open Create SLO and immediately see a usable form and visible loading state for
  unavailable choices. Attribute slow reads with evidence; do not hide delay behind
  a blank page or claim a backend speedup from a loading-state change.
- Enter an ordinary target/window, select an SLI and optionally include existing
  history. Use concise, understandable labels; explain collection alignment only
  when correcting an invalid value. Preserve explicit retrospective consent,
  idempotent retry and navigation after sign-out.
- See one compact, aligned overview toolbar. An empty list has one clear empty
  state, without three empty tables or meaningless pagination. Populated urgency
  groups retain exact values and supported filters.
- Open detail with one title/context row and reference-like spacing. Routine
  reading shows concise user-facing labels; technical calculation metadata belongs
  in its disclosure.
- Open each Table action with mouse or keyboard and see its result immediately
  beneath the relevant lane, including an explicit empty state. The action exposes
  its open state and target; populated tables preserve exact values and paging.
- Empty plots use readable ranges and honest waiting/no-data explanations. Missing
  budget is neutral; actual negative budgets remain exact and visibly distinct.
- Compare the running list, editor and detail against slo-tracker side by side in
  both themes and at mobile widths. Record differences rather than equating a
  rendered screenshot or passing suite with visual acceptance.
