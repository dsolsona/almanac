## Interfaces and visible content

Create shared exports under `web/src/components/ui/`:
- Button: native button attributes, variant primary/outline/ghost/danger, default
  type=button, disabled and accessible pending state (pending cannot invoke action).
- TextField: id/label/hint/error and native input attributes; correct label/id and
  aria-describedby; invalid styling and disabled behavior.
- SelectField: labelled native select, options {value,label,disabled?}, hint/error.
- StatusBadge: healthy/warning/breached/no-data/stale with visible text and distinct
  non-color shape/mark. Do not use brand orange to imply warning.
- Panel: semantic section with heading and children; no decorative nested cards.
- Dialog: native dialog with labelled title, close button, Escape/focus return;
  controlled open/onClose state and triggerRef for explicit restoration.
- ThemeToggle: light/dark control with accessible state; default system preference
  then persisted user choice. Guard storage failures; update root class/color-scheme.

Create `web/DESIGN_SYSTEM.md`: exact semantic token map, typography, spacing/focus,
component usage and catalogue instructions, clearly separate implemented controls
from future charts/complex controls. Wordmark ALMANAC in Bevan 400; system sans body,
monospace technical labels and controls; numeric tabular figures. No unapproved logo.

Catalogue layout: masthead, compact section navigation, introductory title, palette
and typography specimens, buttons, form controls, status, panels and working dialog.
Examples include normal/disabled/pending/invalid/empty/loading/error/long text states.
Actions only change local demo state with honest feedback. Compose catalogue from
shared exports; do not make a separate imitation. Include keyboard skip link, bounded
prose width, reduced-motion and responsive single-column layouts. Demo copy identifies
local examples and does not claim actual data, authentication or backend operation.

Production root is only a minimal brand shell stating the application is being built;
no catalogue link, route, demo content or hidden environment flag exposes the catalogue.
Use a build-time DEV-only dynamic import so Rollup eliminates the entire catalogue
and its CSS/fixtures in production. Unsupported production paths show an honest not
found state; no dev-only feature can be activated by a query parameter.

## Fixed commands to create and verify

Root Makefile has these narrowly defined targets (no arbitrary command passthrough):
- `make setup`: install locked web dependencies (initial lock creation explicit) and
  Playwright Chromium; no OS package installation or global tools.
- `make build`: typecheck and build production assets; no implicit install.
- `make verify`: typecheck, component tests, build and production-exclusion check.
- `make verify VERIFY_MODE=unit`: component suite; optional TEST_FILE selects a test
  filename safely quoted as one argument, never interpreted as shell code.
- `make verify VERIFY_MODE=browser`: browser checks only, one local Vite server on
  127.0.0.1:5198 with reuse disabled, Chromium and bounded workers. It must not rebuild
  or run unrelated suites. Browser readiness uses Playwright condition waits.
- `make preview`: local Vite development catalogue on 127.0.0.1:5198, strict port.
- unknown VERIFY_MODE fails; zero selected tests fails; no hidden downloads in checks.

Add npm lockfile, TypeScript config, package scripts, component-test setup and
Playwright config. Build/test outputs stay ignored. Document commands only once they
run. Note setup is explicit and can require network; tests should run offline afterwards.
