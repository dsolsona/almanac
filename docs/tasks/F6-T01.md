## Outcome and non-goals

Shared controls that every later screen in plan 0025 consumes, demonstrated with
all states in the local catalogue in both themes at 360/1024/1440 px, with the
design guide updated. No feature screen changes. No backend or contract change.
`StatusBadge` and the SLO-local status mark remain in place until F6-T02/T03
replace their consumers.

Controls delivered in `web/src/components/ui/`:

- `StatusMark`: shape plus label plus optional one-line reason; tones healthy
  (filled circle), warning (triangle), breached (square), stale (open circle),
  none (dashed open circle).
- `SegmentedControl`: single-select radiogroup of buttons with optional counts,
  disabled options with a title, roving tabindex and arrow keys.
- `ChoiceChips`: preset chips plus a dashed "Custom…" chip that reveals an input,
  applies as you type, relabels itself and collapses on Enter or blur; invalid
  custom values show an error under the field.
- `Combobox`: labelled text input with a filtered listbox whose options carry a
  status mark, a secondary line and a disabled state; arrow, Home/End, Enter and
  Escape; a no-match row with an optional action; the selection collapses to a
  `SelectionSummary` with a Change action.
- `SelectionSummary`: status, title, badge, detail line, optional message and
  action; warning variant.
- `TextareaField`: labelled textarea with hint and error, matching `TextField`.
- `PageHeader`, `SearchField`, `Pager`: the list composition (title, mono
  summary, updated time, actions; search with `/` shortcut; position, per-page,
  previous/next).
- Token `--card-inset` (24 px, 14 px below 860 px) in `tokens.css`.

## Acceptance and expected cases

- AC-01: catalogue demonstrates every control and state (default, selected,
  disabled, invalid, empty match, warning summary) using the real exports; the
  production build excludes the catalogue (existing check).
- AC-02: both themes use tokens only; contrast of every status tone against the
  surface is at least 4.5 (extend the existing browser contrast check to
  `.ui-mark--*`).
- AC-07: keyboard: segmented and chips move with arrows and select; combobox
  opens with typing or ArrowDown, moves with arrows, selects with Enter, closes
  with Escape, skips disabled options; Change returns focus to the input. No
  horizontal overflow at 360 px.
- AC-11: geometry matches the mocks: 38 px controls, 3 px corners, chip and
  segment fonts in mono, status shapes 11 px, card inset 24/14 px.

User acceptance checklist:

- Starting state: `make preview` catalogue at `/design-system#operational`.
- Ordinary input: pick a datasource by typing "prod", arrow down, Enter; summary
  card appears with Change; click Change and the input returns with focus.
- Custom chip: click "Custom…", type 99.7, press Enter; chip reads "Custom · 99.7%".
- Invalid: type 100 in the custom target; error text appears under the chips.
- Navigation: catalogue nav link "Operational" scrolls to the section.
- Reference comparison: side by side with `docs/design/mocks/sli-create.html`
  Source section and `slo-create.html` Objective section, both themes, 360/1440.
- Container deployment: not applicable (no product page change); catalogue is
  dev-only.
