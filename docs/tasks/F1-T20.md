## Delivered change

Settings uses the approved tabs, account form, role chip, theme selector and password
footer action. Users has separate name/email columns, status/role chips, real last
sign-in, filter-bound cursor paging, selectable full-row navigation and compact
profile/account-access forms. Creation shares a one-time setup link instead of
asking the administrator for a password.

Migration 0042 adds profile/lifecycle metadata without replacing existing passwords
or login aliases. Versioned API and CLI commands share transactionally checked
authority, last-admin protection, audit, revocation and one-time challenge handling.
Password changes preserve exact protected-file bytes and recover replacement
session context after uncertain responses. Uncertain creation preserves its draft
and original command key for a deliberate receipt retry.

## Diagnosed failures and corrections

- Email and legacy username initially had separate attempt budgets; both now use
  the stored login's shared admission key, with a PostgreSQL regression.
- Native dialog Tab could leave the modal; the shared control now wraps its visible
  enabled controls, verified in the real browser.
- The old ingestion migration test removed migration records without undoing the
  new user columns. Its reconstructed old schema now removes migration 0042 too;
  the production migration remains strict about duplicate columns.
- The launcher announced startup before recording the attached child PID. Moving
  the announcement after assignment closes the Ctrl-C cleanup race exposed by its
  existing PTY check, without changing a timeout or weakening the check.
- Review found password-file newline trimming, discarded password-change recovery,
  and destructive Refresh after uncertain creation. All were corrected and the
  read-only recheck found no remaining concrete issue in those corrections.
- Concurrent catalogue/E2E execution deleted E2E trace files because their artifact
  directories overlap. The successful full run was sequential; the testing guide
  now records this constraint. Earlier failures remain in the execution history.
