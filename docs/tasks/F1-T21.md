## Outcome and edit scope

A reproducible dependency base, independent CoW worker disks, authenticated/trusted
Codex, guest-only Docker, GitHub capability and named lifecycle commands. Script,
focused Python test, Make targets and affected documentation only. No Go changes,
application behavior, memory snapshots or pane orchestration.

## Acceptance and expected cases

- Build a base once; rebuild without changing existing workers.
- Launch two workers with inline/stdin prompts and independent dirty source
  snapshots; inherit Docker images/dependencies without another `make setup`.
- Confirm fresh SSH/machine identities, Docker/code isolation and distinct PR branches.
- Authenticate Codex, execute its tools, run containers and reconnect to its terminal.
- Transfer GitHub login privately; configure HTTPS origin and Git author identity.
  Verification must not push or open an unsolicited PR.
- List running/stopped/partial workers; stop/start without losing work; delete one
  explicitly named disposable worker while preserving other VMs and shared bases.
- Reject stale dependencies, unsupported CoW, active seed tasks, unsafe paths,
  unknown PIDs, partial images and failed shutdowns while preserving data.
- Preserve prompt bytes through Bash and Make, including shell/Make metacharacters.
- Generate and print a random two-word name for unnamed setup/run/base calls;
  reserve names atomically and preserve explicitly named workers on collisions.

## Execution and evidence

Focused check: `make shell CMD='python3 scripts/firecracker-setup-test.py && python3 scripts/check-docs.py'`.
Host checks: `bash -n firecracker-setup.sh` and `git diff --check`.
Application suites are not required for this tooling change under the testing guide.

Latest focused check passed in 2.76 seconds, including 190 Markdown files and
1,371 local links. Bash syntax and whitespace checks passed in under a second.

The focused test covers real reflinks where supported, clone write isolation,
SSH key/config generation, dependency mismatch refusal, base publication/rebuild
and failure recovery, sanitization, Git snapshot copy/collection, credential stdin
transport, deletion, concurrent address allocation and prompt transport. SSH,
mount and installation boundaries use fixtures; these do not establish real boots.
The Make prompt test exposed function expansion; preserving the supplied value
without recursive Make expansion corrected that boundary.
An offline service-symlink regression also caught following a guest directory
link during host edits; replacing the link without dereferencing it passed.

Live SSH inspection timed out. Host listing required sudo for older root-owned PID
files; fingerprint authentication timed out and the command was cancelled without
lifecycle changes. New starts give PID-file ownership to the launcher.

Shutdown warning follow-up: the reported `vm-stop` emitted a missing-bus error
before success. Host process inspection and the guest's Firecracker log confirmed
the VMM had exited successfully with code 0. A read-only package inventory of its
stopped disk found systemd 255.4 and no D-Bus daemon. Upstream systemd first tries
logind, logs the connection failure, then falls back to its private manager socket.
Stop now queues `reboot.target` directly with the same normal irreversible,
nonblocking shutdown transaction. The regression reproduced the warning before
the change; the focused checks passed afterward in 2.57 seconds, including docs.
Bash syntax and whitespace checks passed. The guest was not restarted for a live
test of the new command; that shutdown cycle remains unverified.

Random-name follow-up: unnamed setup/run/base now reserve adjective-animal names
with atomic directory creation. Explicit names and legacy defaults for existing
lifecycle operations are preserved. Focused checks passed in 4.03 seconds,
including eight concurrent unnamed launches, a repeated random sequence that
skips an existing worker, and all three Make creation entry points. These naming
checks use the real parser/filesystem with guest work stubbed; no VMs were booted.
