## Evidence and scope

The preceding control attributes 3,451 waiting extrema attempts to one canonical
calculation each, totaling 47.166 s of query duration. None of those attempts
publishes an hour. The possible multi-hour rollback mechanism therefore does not
explain this run. The remaining 1,333 extrema canonical calls take 14.954 s and
belong to successful turns. Full traces remain in the dependency worktree.

A private, isolated PostgreSQL reproduction has a clean first window and first
pending row at ordinal 237 of 240. Twelve executions return identical rows;
the actual worker preserves its cursor and publishes no rows while pending, then
advances after the source is rebuilt. Automatic planning remains custom for all
12 calls; execution/planning are both material, with no basis to change global
plan mode. The reproduction passes in 0.627 s. Two failed launches are retained:
one shell quoting failure and one incorrect container overlay path that ran no
tests. Neither is evidence of a passing reproduction.

A separate read-only payload check finds private budget-cache data is only about
6.4% of the stored overview payload. Dropping it is not the next primary fix;
required sparkline data and public responses remain intact.

The history loop currently computes its minimum wait from the beginning of the
turn. A pending calculation longer than ten milliseconds consumes that wait, and
another due SLO is attempted immediately. Per-cursor backoff therefore does not
bound aggregate unsuccessful work across a fleet.

## Intended correction and acceptance

After an unsuccessful history attempt, wait at least 100 ms from completion,
without holding a database connection. This caps unsuccessful turns at ten per
second per history worker independently of the number of pending SLOs. Successful
work continues draining immediately; each cursor keeps its existing durable
retry, failure, lease and fairness rules. Source/current processing is independent.
No window is skipped, reordered or considered clear without full evidence, and
earlier inconsistent facts still take precedence over later pending input.

- Reproduce the missing post-attempt pause with a deterministic clock and real
  PostgreSQL pending work; retain the failure before correction.
- Verify the returned schedule is at least completion +100 ms, the claim is
  released, attempts are preserved and the cursor does not advance.
- Verify successful history drains without that pause, and blocked/no-work cursors
  retain the existing bounded scheduling behavior.
- Verify clean source publication resumes exact history and no partial hour appears.
- Preserve the earlier-facts failure regression, lease fences and cancellation.
- Run the same frozen 200-SLO control with unchanged workload and acceptance
  budgets. Record seed duration and deferred-work/ready-publication counts; do not
  treat lower retry counts alone as proof of acceptable readiness or page latency.

Refactor one history turn to accept an explicit clock and return its next wakeup,
as the existing current/source worker does. First preserve old scheduling in that
helper so the regression can fail on the observed behavior. Then make the bounded
post-attempt scheduling correction. No schema, API or architectural dependency is added.

Focused checks use `make shell CMD='go test -tags=integration ./internal/storage
-run … -count=1 -timeout=120s'`; exact selections and results follow after the test
names exist. Modern Go 1.27.3 guidance and relevant explanations were read via the
catalog before Go edits (0.366 s including launch).
