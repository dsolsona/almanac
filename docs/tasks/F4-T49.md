## Outcome and boundaries

Append optional `WindowEvidence.Maintenance` to internal format-1 evidence with
`omitempty`. Preserve the requested exclusion authority separately from the actual
computed revision/build, complete-window compatibility proof, and original reused
partial-hour keys and their proofs. The canonical adapter constructs these fields;
this task does not modify calculation, processor, schema, public API or defaults.
Nil provenance remains valid for legacy evidence and unavailable no-math results.

The pure kernel validates structural identity, revision ordering, proof kinds and
bounds, source generation ordering, and relevant unique hour keys. It cannot
authenticate stored builds, SLI bindings or exact compatibility certificates;
those remain storage responsibilities. The producer attaches only hours actually
consumed by each window. Nondividing-grid proofs may extend past a physical hour;
structural validation does not invent a cadence absent from compacted summaries.
Current and last-breaching recovery evaluations independently retain their masks.
Returned evidence owns its nested provenance rather than aliasing input memory.

Compaction preserves four optional actual endpoints per condition: first/last
short-window and first/last long-window maintenance evidence. Changes to provenance
do not change the existing unchanged-outcome compaction rule. No intermediate
provenance or numeric values are inferred. The strict authenticated range decoder
validates each endpoint against its saved snapshot and window duration. The series
reader compares nested values semantically, rather than pointer addresses, while
retaining its existing digest, identity and documented normalization checks.

## Acceptance and verification

- Pre-extension input structs encode to exactly the same bytes and SHA-256 after
  decoding/re-encoding through the extended format, including recovery inputs.
- Malformed build identities, revision/proof mismatch, incomplete proof bounds,
  duplicate/out-of-window reused hours and future source generations are rejected.
- Exact genesis (implicit or explicit build), same-revision proof before index
  catchup, and semantically equal timezones remain valid.
- Current/recovery and reused-hour nested values survive evaluation without aliases.
- Compaction of changing actual mask provenance retains only true endpoints and
  does not prevent valid compaction or invent counts at omitted cutoffs.
- Real PostgreSQL journal persistence, compaction and authenticated range reads
  retain those fields; malformed endpoint summaries fail decoding.
