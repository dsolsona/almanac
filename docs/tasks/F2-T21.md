## Outcome and non-goals

Make ordinary agent registration understandable and usable, preserve a coherent
authenticated workspace while navigating, and display technical endpoint text
literally. Restore the accepted visual hierarchy using shared components, themes
and responsive navigation. Do not implement unavailable product destinations or
change machine-identifier, authentication or authorization contracts.

## User acceptance checklist

- A signed-in administrator enters display name `Local`, sees the suggested editable
  identifier `local` before submission, registers successfully and sees the persisted
  agent and its one-time token. An explicitly chosen identifier survives subsequent
  display-name edits. Invalid or duplicate identifiers identify the field and how
  to correct it; submission uses the visible value without hidden normalization.
- Navigate Agents → Datasources → Agents and through details/back/history while the
  authenticated shell remains mounted. No document reload or repeated authentication
  splash occurs for ordinary internal navigation. Real loading/failures remain
  visible in their content region without obscuring unrelated navigation.
- Type `http://localhost` in the datasource endpoint field and verify both its exact
  DOM value and literal punctuation on the rendered page. Typing/caret movement and
  error recovery work normally.
- Compare desktop and mobile light/dark pages against the accepted visual design:
  product-first grouped menu, active/context indication, page title/actions,
  readable form/list hierarchy, consistent controls and account navigation.
- Exercise the actual container deployment after onboarding, including registration,
  navigation and persistence. Use isolated Compose resources, preserving operator data.

## Ownership and checks

Registration implementation owns agent form/client and related backend fixes only
when evidence requires them, agent browser regressions and container registration
acceptance. Shared UI implementation owns authentication shell routing, shared
navigation/styles, datasource composition and literal technical-input presentation.
Coordinate shared helper changes explicitly. The coordinator owns guidance,
integration and the independent final user pass.

Use the exact existing invocations in [command discipline](../commands.md), including
focused agent UI tests, full `make verify`, `make verify VERIFY_MODE=go-race`, the
recorded real integration command and `make verify VERIFY_MODE=compose` as applicable.
Reproduce real journeys before broad checks. Preserve first failures and do not
raise timeouts, weaken assertions or substitute mocked acceptance for real services.
