## Outcome and scope

Normal authenticated navigation and live collection remain usable under the
declared workload. First establish the cause of each failure using the
[ranked inventory](../evidence/alert-performance/README.md), then implement the
smallest correction with a reproducing test. Initial scope is diagnostics and
isolated regressions; expand exact production edit scope only after diagnosis.
This task does not implement alert evaluation or change mathematical/security
contracts, destinations, UI design or accepted performance budgets.

## Acceptance and expected cases

- An authenticated user can inspect session context while ordinary authorized
  reads are active. Inspection must not extend idle lifetime. Revocation, disabled
  users, credential/installation changes and expiry must remain effective.
- A 20-row SLO list preserves exact values, staleness, counts, filters and keyset
  behavior. Improve actual cold and in-app journeys; SQL-only improvement does not
  close the browser gate.
- Every due live interval arrives within the canonical allowances and accepted
  ingestion remains successful. Preserve absolute and relative latency gates.
- Current work with ready inputs progresses despite unrelated historical work;
  pending source evidence is never interpreted as clear or successful.
- Test errors, incomplete work and unavailable evidence stay visible. Validate the
  normal isolated deployment with default authentication after focused fixes.

## Diagnostic evidence

Two rollback/read-only overview experiments used the existing generated page query
and the retained corrected 200-SLO database. Ten concurrent connections each used
one repeatable-read snapshot; eleven alternating-order pairs per connection
included six warmup rounds and five recorded rounds. Every pair checked identical
typed public JSON. These probes omit HTTP authorization/counts and browser work.

- Separate projection payload and metadata, then merge typed values in Go:
  50 samples per variant; query mean **91.800 → 57.926 ms**, query p95
  **139.168 → 92.989 ms**; total query/decode/encode mean **117.544 → 86.573 ms**,
  p95 **187.049 → 183.148 ms**. Decode variability offsets some database benefit.
  This does not establish a useful tail-latency fix under the failing workload.
- Classify failed/stale state from scalar booleans instead of extracting it from
  metadata JSON, with both variants using the same fixed clock five minutes ahead
  to exercise stale rows: query mean **86.201 → 81.208 ms**, p95
  **159.359 → 153.314 ms**; total mean **114.928 → 102.461 ms**, p95
  **222.905 → 191.647 ms**. The first probe failed with SQLSTATE 42703 because sqlc
  expands CTE column lists; the private probe was corrected to propagate its new
  columns. That failed attempt and both result sets are retained. Generated
  application sources were not edited. No production alternative was adopted.
