## Scope and acceptance

- An editor selects a preset or a custom range and previews the existing backfill workflow. A range before the first measurement boundary offers an explicit earlier-history choice and displays the query, datasource and effective earlier range. Ordinary requests keep repairing eligible gaps.
- Preview makes no change. Confirmation persists the authorization alongside the job and extends only initial measurement history, clipped to known retention and cadence. A disconnected range would extend validity across unselected slots, so it must reach the existing history boundary. The live collection boundary and existing SLO evaluation dates stay fixed.
- Where the agent cannot execute the original revision, return an actionable explanation without changing validity. Existing observations remain intact and an identical request replay returns the original job.
- Reuse bounded backfill batches and the historical traffic pool. Apply provider retry guidance across the datasource's historical chunks, including other queued jobs, while live ingestion retains its existing priority.
- Verify the full 28-day admission and bounded chunk geometry in PostgreSQL, and exercise collection, preview, keyboard navigation, desktop and mobile rendering against the isolated deployment. Record any load acceptance gaps.
