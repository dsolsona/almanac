## Outcome and boundaries

An administrator registers an agent, launches the separate `almanac-agent` binary
with its protected token file and verified backend TLS, and sees its capabilities,
heartbeat and applied configuration state. Reconnect, duplicate-process conflicts,
expiry and revocation produce distinct observable outcomes. Authentication alone
does not imply healthy collection. No backend source collection, broker, distributed
connection registry, datasource provider execution or historical-job implementation.

### Reviewed phase-1 interface

All protocol counters and revisions are canonical decimal strings to avoid JSON
number precision loss. Every envelope has `kind`, `message_id`, `session_generation`,
and typed `payload`; generation `"0"` is reserved for initial/unconfirmed hello,
including lost-welcome replay. Same-process resume hello carries its known positive
int64 generation; all non-hello messages require a positive generation. Hello
carries a nonzero 32-byte base64url resume proof and fresh nonce; the proof stays in
process memory. Welcome echoes the nonce, returns current ownership renewal sequence,
and grants a durable lease bound to authenticated agent ID, generation, positive configuration revision, and uniquely
keyed SLI ID / measurement revision pairs. Heartbeat renewal begins with expected
sequence zero and uses a distinct nonce-correlated `heartbeat-ack`. Configuration-
changed, configuration-applied/failed, shutdown, and revoked have bounded typed
payloads and safe enums. Diagnostic/history kinds remain unsupported in this
increment.

The typed HTTP snapshot contract uses `GET /api/agent/v1/configuration`, a positive
configuration revision, an ETag bound to agent ID/revision, 304 without a body when
unchanged, and an `assignments` array. This increment supports only empty assignments
until datasource configuration has an accepted schema. Empty assignments cannot be
paired with query authority. Unknown kinds and invalid enums fail closed; unknown
optional fields remain compatible.

The backend/agent implementer owns protocol and backend runtime files. A future
consumer task may own web/CLI presentation; it must not edit protocol/schema/storage
or generate conflicting API definitions. Coordinator owns interface review, merge
ordering and verification scheduling. Do not dispatch a second implementer yourself.

## Required contracts

Read the governing records fully. Use the accepted Coder WebSocket v1.8.15 pin,
verified TLS, explicit protocol negotiation and bounded message/queue budgets.
Tokens never appear in URLs. Protocol version, software version, capability formats,
configuration revision, measurement revision and ownership generation are distinct.
Define first-handshake generation semantics explicitly without pretending that an
unowned process already has a generation. Unknown mandatory operations fail closed.

Use F2-T13 transaction-local ownership checks; a credential alone cannot replace
an unexpired owner. Keep resume proof only in process memory. Persist execution
grant evidence and bind it to configuration and allowed measurements before issuing
authority; ownership alone does not grant query permission. Empty assignment is
valid configuration but authorizes no SLI queries. Advertise only implemented
provider operations, never a future provider merely because the backend recognizes it.

Fetch coherent configuration snapshots with ETag and acknowledge successful atomic
application. Reconnect reconciles current desired configuration before new dispatch.
Honor lease nonce/monotonic anchoring, 10s heartbeat/30s unreachable defaults,
revocation detection bounds, bounded reconnect backoff and cancellation. Retain
separate reachability, scheduling and accepted-observation freshness fields;
unimplemented/no-assignment signals remain absent with an explicit explanation.

Use one active backend and separate agent binary under ADR-0008. CLI configuration
must support backend address, protected credential path and explicit trust roots;
no inbound agent listener or PostgreSQL access. Define exact flags and response
schemas during interface review, before consumer implementation.

## Acceptance

- Actual separate agent and backend processes communicate over TLS, fetch/apply
  a real versioned snapshot and report current capability/heartbeat state.
- Real UI/CLI status distinguishes never-connected, connected, unreachable and
  incompatible; it never invents successful collection or observation timestamps.
- Copied token/new process cannot displace an unexpired owner; same-process resume,
  rotation, revocation, stale grant/nonce and expiry obey accepted fencing rules.
- Protocol mismatch, unknown mandatory kind, malformed/oversized messages, slow
  peers and queue saturation fail visibly and remain bounded. Shutdown joins workers.
- Reconnect reconciles desired configuration; receipt is not application. Empty
  configuration grants no execution permission and unsupported work cannot run.
- Real early journey and detailed deterministic boundary tests, including secret
  redaction, precede full candidate gate. Preserve first failures and their causes.
