# F4-T56: Inspect maintenance on SLO timelines

- Status: in review
- Governing contracts: [SPEC-0016](../specs/0016-maintenance-exclusions.md),
  [SPEC-0017](../specs/0017-slo-timeline-annotations.md)
- Implementation plan: [0046](../plans/0046-maintenance-management.md)
- Dependency: [F4-T55](F4-T55.md)
- Worktree: `.worktrees/maintenance-annotations` on `codex/maintenance-slo-annotations`

Use the authenticated, UTC-range overlay read to mark effective maintenance on
the rolling-budget, burn and attainment charts. Keep the numerical series and
its calculation status intact. Match the requested SLO and range before
displaying metadata. An unavailable metadata layer leaves calculated series
usable with a visible refresh message.

Display a shared band label across the affected charts. Inspection at a
position within the half-open band shows the original start, end and title,
even when a rolling value remains available. A separate list exposes complete
bounds and navigation to the owning maintenance record. The charts render at
most 200 bands. Additional records remain navigable by cursor in the list.

Typecheck and 29 focused unit tests passed in 2.96 seconds. Thirteen browser
checks passed in 26.7 seconds across both themes, 360/1024/1440 widths, and
touch. The checks exercise hover throughout a band, exact bounds, keyboard
selection, and verify that the lower budget tooltip paints outside the card.
The first concurrent run exposed a shared Playwright output directory conflict
during teardown. Running the checks sequentially avoided that interference.

The isolated HTTPS and PostgreSQL journey passed in 4.4 seconds, or 7.2 seconds
including onboarding. It checks that the saved window appears on three graphs
and that keyboard navigation opens the owning record. See the
[deployed timeline](../design/mocks/maintenance/production/slo-maintenance-timeline-dark.png).
The fixture creates a new SLO without retained measurement history. The
separate chart fixture verifies overlays and tooltips with measured points.
The seeded-fleet timing gate remains open.

The chart requests an overflow summary with its first overlay page. On a
range with more than 200 windows, one counted marker replaces the final
individual band and represents that window and all later windows. PostgreSQL
aggregates the count and clipped bounds in the same authorized snapshot as
the first page. The dotted marker shows the extent of the grouped windows,
while individual shaded bands show exact exclusion intervals. Its keyboard
action opens the paginated list and focuses its disclosure. Sparse ranges
and list pagination use the existing page behavior.

The dense browser fixture first reproduced 200 individual bands and no
overflow marker. The focused tests now check 199 bands, an exact count of
two more windows, keyboard navigation and the 201st window on the next page.
Screenshots show the marker in [desktop light][cluster-light] and
[mobile dark][cluster-dark]. PostgreSQL tests verified the clipped bounds,
scope, exact-limit behavior and separate cursor page. The executable journey
verified the authenticated response with fractional UTC bounds. Build,
PostgreSQL, executable and four browser checks took 67.4 seconds together.
