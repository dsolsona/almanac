## Outcome and boundaries

Prepare one exact physical start-hour population for a particular SLO definition,
measurement, immutable completed mask and canonical source-hour generation. Store
separate eligible/excluded sufficient statistics. Never overwrite canonical source
measurements, rebuild expired measurements, or derive alert-specific quality/math.
Consumers and scheduling remain unwired. Fully eligible hours can continue using
canonical aggregates; this primitive prepares partial masks and supports complete
exclusion/empty populations without fabricating success.

## Confirmed transaction contract and interfaces

Preparation is one caller-owned **READ COMMITTED** transaction with explicit
admission/context/deadline and clock. Acquire SLI SHARE first, then SLO SHARE,
exclusion-state SHARE, completed-build SHARE, and canonical hour SHARE. Read facts
only afterward. Existing ingestion takes SLI UPDATE; it cannot insert a dirty-row
phantom while this bounded turn holds SHARE. READ COMMITTED is deliberate: a
repeatable-read snapshot established before a lock wait could miss a writer that
commits during that wait. Window consumers retain their existing RR contract.
There is no equality requirement against the global SLI generation or current
exclusion revision. Historical complete builds remain valid after authority moves.
On error the caller must roll back; on success commit immediately after the final
clock fence. No implicit retries or transaction/admission defaults.

Implemented internal interfaces:

```go
type maintenanceHourKey struct {
    SliID, SloID, BuildID pgtype.UUID
    DefinitionRevision, MeasurementRevision, SourceGeneration int64
    HourStart time.Time
}
type maintenanceHourInput struct {
    maintenanceHourKey
    RetentionStart, Deadline time.Time
}
type maintenanceHourPopulation struct {
    Good, Total *big.Rat // exact observed contribution, not an invented missing population
    Expected, Observed, KnownEmpty, ZeroTraffic int64
    FirstObservation, LastObservation, LatestReceipt *time.Time
}
type maintenanceHourRecord struct {
    Key maintenanceHourKey
    ExclusionRevision int64
    PreparedAt time.Time
    Eligible, Excluded maintenanceHourPopulation
}
func prepareMaintenanceHour(context.Context, pgx.Tx, maintenanceHourInput, func() time.Time) (maintenanceHourRecord, error)
func readMaintenanceHour(context.Context, *dbgen.Queries, maintenanceHourKey, time.Time) (maintenanceHourRecord, error)
```

`SourceGeneration>0` requires the exact canonical source hour; `0` is the explicit
absent-hour identity. A fresh read of zero identity rejects any new aggregate,
canonical row or dirty work. A legitimate retained hour with none of these produces
zero observed/empty counts and correct expected coverage; shared math yields
`no_data`/`excluded`, never Healthy by inference. Missing prepared source with raw
facts or dirty work is pending; exhausted source work remains explicit source
failure. A requested generation mismatch is stale. Expired/insufficient retained
raw is unavailable, not zero and not permanently retried as source preparation.
An existing valid prepared record is preserved/reusable without rescanning raw.

Hour start is a whole UTC physical hour. Revision/cadence/SLI identity comes from
the immutable SLO definition and measurement. Definition/measurement validity and
window retention clipping stay with the window planner: these are whole physical
start-hour sums, never an arbitrary partially clipped window. RetentionStart is an
explicit preparation input proving the requested raw hour is still admitted; it
is not a new retention policy or part of immutable numeric identity. Deadline is
also not part of persisted identity. Neither may change a stored sum.

## Bounded reads, completeness and persistence

Read canonical rows ordered by start with `LIMIT 3601` before processing; reject
more than 3600. The defensive calculator cadence is whole seconds, at least one second. Current
public datasource configuration still requires at least 15 seconds; this task does
not change that constraint. An hour
owns starts in `[hour,hour+1h)`, including an interval ending after the hour. Validate
actual epoch alignment and exact cadence; do not split or prorate 70-second rows.
Read at most one coverage predecessor plus starts inside the hour via existing
`(build_id,starts_at)` PK and a bounded forward limit with an overflow sentinel.
Validate disjoint/aligned fragments before merging with ordered starts. Fragment
work is bounded by the one-second domain, independent of total declaration count.

Compare the unpartitioned raw observed/empty/zero counts, exact good/total and
observation bounds against the locked canonical hour before publication. Compare
source first/last interval bounds as well. Missing failed rows cannot invent
measurements; all missing/failed/incomplete coverage remains absent from numeric
observed populations and excluded completeness. A mismatch returns unavailable
and writes no summary. Partial/expired raw never replaces an existing retained
population. Source aggregate absence with nonempty raw is pending, not zero.

Canonical receipt repair already locks SLI then hour; it cannot race this turn.
Canonical rebuild does not take SLI, so the hour SHARE lock protects publication
against replacement. Retention does not take SLI: its parent observation-table
ACCESS EXCLUSIVE lock conflicts with the bounded raw SELECT's ACCESS SHARE held
through commit. A completed drop observed before the read is detected by the
retention bound/completeness comparison. Source-hour deletion is blocked by its
row lock. These are actual synchronization paths, not assumed SLI coverage.

Migration 0063 stores typed fields keyed by
`(slo_id,definition_revision,measurement_revision,build_id,hour_start,source_generation)`.
Store SLI and mask revision provenance, prepared time, expected eligible/excluded
start counts and both populations' exact sums/counts/observation/receipt bounds.
Reference the immutable definition/measurement/build. Records are immutable and
idempotent under the same key; divergent duplicate data is an error. No foreign
key to a mutable/reclaimable canonical aggregate is added. A read validates source
readiness/current hour identity in its caller's snapshot before returning a row.
An old row remains stored when the source changes but cannot masquerade as a newly
requested population.

Numeric sums are sums of observed contributions. Excluded whole-population totals
remain unknown unless every expected excluded interval is observed, matching the
shared evaluator. Known-empty/failed/missing excluded intervals must not make that
value known merely because the stored contribution sum is zero. Receipt maxima
include observed and known-empty contributions only; failed/incomplete and the
other population cannot influence eligible receipt metadata.
