## Outcome and non-goals

ADR-0034, which the maintainer approved in Crit on 2026-11-06:
- Retries continue on a schedule and stop only after 7 days of continuous failure.
- One rule decides which errors are temporary.
- Inconsistent aggregates are never stored, and are rebuilt if found.
- A periodic consistency check runs, with per-SLO state metrics and a log line.
- Every failure carries its cause in logs, traces and stored reasons.

Not in this task: the open questions of ADR-0034, which are a single table for intervals and counts,
explicit marking instead of triggers, dropping the interval end, removing detail-range history jobs
and tiered retention.

## Root cause

The performance seed wrote interval records and their values in separate commits. The aggregator ran
in between and stored hours whose intervals counted as observed but whose totals were zero. Only
inserting a record marks its hour dirty, so the later values never rebuilt it. Every calculation that
read those hours then failed with `slo: inconsistent operational facts: zero total but not every
observed interval is zero traffic` until its work stopped for good.

## Execution and verification

- [x] Reproduce: `TestIntegrationDerivedDataHealsWhenValuesArriveAfterAggregation` failed with the
  production error before the fix.
- [x] The aggregator stores no hour with observed intervals that lack values. It defers the hour
  without counting an attempt.
- [x] One temporary-error rule (`derivedTemporary`), used by all five queues. Temporary errors are not
  logged as failures.
- [x] Retries:
  - after 2, 4, 8 and 16 seconds, then every 5 minutes for a day, then hourly;
  - stopped after 7 days of continuous failure;
  - restarted when the SLI receives observations, a dirty hour gets new data, or "Retry now" is used
    (migration 0041, `failing_since`).
- [x] Safety net: a calculation that finds inconsistent aggregates marks the hours it read for
  rebuilding (`MarkDerivedHoursDirty`).
- [x] Consistency check every minute (`checkDerivedConsistency`):
  - it restarts stopped work whose SLI has new observations;
  - it classifies each SLO as up to date, catching up, failing or stopped;
  - the states are exported as `almanac_derived_slos{state}`, with one log line while anything is
    behind.
- [x] Errors:
  - log lines include the SQLSTATE and message, or the named consistency check;
  - spans record the error;
  - stored reasons name the class of error.
- [x] The performance seed writes each day's records and values in one transaction.
- [x] A flaky storage test is fixed. The `ANALYZE` under a 250 ms lock timeout raced autovacuum,
  which only yields after 1 s.
- [x] Gates on the final tree:
  - `make test` passes in 22 s.
  - `make test-integration` passes in 69 s, and in 105 s with `RACE=1`.
  - `make test-e2e` passes all 9 journeys in 164 s.
  - `make test-perf` passes. All 20 SLOs show the exact expected budgets. Every page is under
    300 ms at the 95th percentile, cold, against the 1,000 ms budget.
- [x] One e2e run failed because Playwright could not write its trace onto the macOS bind mount
  (EACCES), not because of a journey. PR #64's harness now writes raw results to the container
  volume, and the rerun passed.
- [x] Stacked PR.
