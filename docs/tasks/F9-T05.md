## Outcome and non-goals

The SLO overview pages with an opaque keyset cursor straight from the current
projections, with per-request group counts, and the snapshot tables, admission lock,
fingerprint and byte budgets are removed. Row content, ordering, filters, page
sizes and the UI are unchanged.

## Interfaces and edit scope

- Query `ListSloOverviewPage(query_text, service_id, urgency, after_rank,
  after_sort_name, after_id, limit+1)` ordered by `(urgency rank, sort_name, slo_id)`
  with the inline `current_state` classification from today's materialization
  query, and `CountSloOverviewGroups(query_text, service_id)`.
- Cursor: base64 JSON of the last row's `(urgency, sort_name, id)` plus the filter
  digest, validated on read; mismatch returns the existing invalid-cursor error.
  Previous-page cursor is produced the same way with reversed scan.
- API contract review: remove `snapshot_id` under ADR-0042's accepted removal
  option; no UI consumer uses it. Per-row generation evidence stays. Overview
  `resource_limit` responses go away. Cursors are bounded to 2,048 bytes.
- Remove: snapshot reserve/materialize/read/delete functions, HMAC cursor code,
  `almanac_slo_overview_snapshots`, `_snapshot_items`, `almanac_slo_projection_payloads`,
  `almanac_slo_history_admission` if still present (next free migration number;
  recheck the integrated tip), their cleanup in maintenance,
  the fingerprint query and its tests.
- Allowed paths: `internal/storage/**`, `internal/slohttp/**`, `api/openapi.yaml`,
  generated Go/TS, CLI client validation, SLO client/pager error handling and
  affected fixtures/tests/specs.

## Acceptance and expected cases

- 25 SLOs with mixed urgency: page sizes 10 and 20 return rows in the accepted
  order with correct next/previous cursors; group counts equal the filtered totals.
- Filter and service scope are bound into the cursor; a cursor from another filter is rejected.
- An SLO whose urgency changes between page 1 and page 2 appears on the page its
  new urgency orders it into; the test documents this as expected.
- Role revocation between pages is denied on page 2.
- List renders in < 1,000 ms (preferably 500 ms) cold at the perf fleet; `make test-perf`.
- Browser journeys for list paging, filtering and deep links pass unchanged.

User acceptance checklist:

- Starting state: seeded stack with more than 20 SLOs.
- Expected: paging forward and back, filters and urgency chips behave as today.
- Invalid input: a tampered cursor shows the existing "list changed, refresh" state.
- Navigation: deep link to page 2 restores the same page through history.
- Container journey: `make test-e2e`.
