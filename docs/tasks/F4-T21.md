## Runner protocol

Entrypoint, on the prepared client: `node web/perf/alert-navigation.runner.ts`.
It needs Node 26, the repository's existing Playwright dependency and its Chromium
installation. The client code does not invoke Docker, PostgreSQL, fixture helpers or controller
resource samplers. Run it inside the development container through the documented
Docker workflow, including on a separate machine; the direct Node command above
is the container entrypoint, not a host-execution requirement.

Input is UTF-8 JSONL. First line, at most 1,048,576 bytes excluding LF:

```json
{"type":"start","runID":"nonsecret-run-id","baseURL":"https://example.test:18188","fleet":{"slis":[],"slos":[]},"storageState":{"cookies":[],"origins":[]}}
```

The empty arrays illustrate field names only and are not a valid fleet. Supply
exactly 200 unique `{id,good}` SLI entries (`good` integer 0–10,000), and 200
unique `{id}` SLO entries in the original fixture order. IDs are UUIDs; the
`Performance SLO N` row name indexes the SLI good count, matching the existing
independent budget oracle. Run IDs are 1–64 ASCII letters, digits, `_` or `-` and
must not contain secrets. HTTPS baseURL must be an origin, with no credentials,
query, fragment or non-root path. Storage state is the ordinary Playwright object,
not a filename: at most 100 cookies scoped to the selected host and ten origins
matching the selected origin. Cookie/local-storage values stay in memory only.
Do not put the actual input in logs, command arguments or published evidence.

Review correction: cookies must have `secure:true`. Browser and API requests now
verify TLS; API redirects are rejected. Browser redirects retain normal TLS,
cookie-domain and Secure-cookie checks. For an ordinary trusted server, no extra configuration is
needed. For a self-signed fixture, supply its **public leaf certificate** through
`NODE_EXTRA_CA_CERTS=/private/path/fixture.pem` when starting Node, before reading
the private start message. Node reads that trust file at process startup for API
verification; the runner validates one certificate (at most 16 KiB), hostname and
validity, then derives its public-key SPKI pin for the disposable Chromium process.
The file must not contain a private key. Use the fixture's certificate obtained
through a trusted channel, never a certificate downloaded without authentication
from the endpoint being verified. Changing the environment after Node starts does
not establish API trust. Certificate and redirect failures fail the diagnostic;
there is no fallback that disables validation. This follows the scoped fixture
trust described in [F1-T18](F1-T18.md).

The transport helper is included in emitted source hashes. This change does not
make older cohosted navigation evidence into remote-client acceptance. Focused
ephemeral TLS tests exercise real Chromium and Playwright API requests with
trusted/untrusted/wrong certificates and a blocked HTTP redirect, without the
Almanac application or its retained fixture.

Second line, at most 1,024 bytes, is
`{"type":"stop","runID":"nonsecret-run-id"}`. EOF also requests graceful stop.
EOF may terminate the final JSON line without LF. No second start, other messages,
unknown fields or additional lines after stop are accepted. Protocol failures
abort active work and report fixed codes. Stop is not cancellation: each healthy
API user finishes at least ten cycles and continues until both browser completion
and stop. Failed lanes are retained, not retried or replaced. Cancellation begins
at 295 seconds, reserving cleanup before a 300-second hard process deadline.

Output JSONL contains `browser-done`, then `result`, with run/source identity,
timings, browser journey trace IDs, API status/counts and safe lane outcomes.
Invalid input before start emits only a failed result. `fulfilled` describes a
settled lane, not latency acceptance; final `failures` separately retain every
count/status/latency failure. All profiles say `client-only-diagnostic` and
`capacityAcceptance:false`, even when client checks complete successfully.
No screenshot, trace ZIP, request body, response body, cookie/header or raw error
text is written. A hard-killed or disconnected runner may have incomplete output;
the controller must treat a missing final message as failure, not infer completion.

API samples keep monotonic elapsed duration plus client wall-clock start/end;
browser samples keep reported journey duration, trace ID and client completion
time. No samples are filtered against backend timestamps here. Remote/server
clocks are not assumed synchronized. Primary integration must align trace/phase
evidence before making overlap claims. Source hashing happens before work; no
synchronous controller snapshots run on the client event loop.
