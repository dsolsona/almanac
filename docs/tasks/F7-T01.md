## Outcome and non-goals

Three small Dockerfiles replace the root `Dockerfile`: `deploy/app/Dockerfile`
(embedded UI and the `almanac` executable on a minimal runtime, the published
application image), `deploy/agent/Dockerfile` (`almanac-agent` on its own
minimal runtime with only certificate roots, the published agent image) and
`deploy/dev/Dockerfile` (the development image: pinned Go and Node, the
generators, Playwright Chromium, the PostgreSQL client, ripgrep, procps and the
pinned VictoriaMetrics binary; a `dev` user whose numeric identity is a build
argument; caches under `/cache`; never published).

Every base and fixture image is pinned by its multi-architecture index digest,
so Docker resolves the host platform: Go, Debian and PostgreSQL were previously
pinned to amd64-only manifests. `scripts/check-image-pins.py` runs at the start
of `make verify` and fails when two files pin one image differently or a
reference has no digest. `make images` builds the three images locally;
`make publish IMAGE_REGISTRY=<prefix>` builds and pushes `almanac` and
`almanac-agent` for `linux/amd64` and `linux/arm64`.

The local stack builds its app image from `deploy/app/Dockerfile`; a new
`agent` Compose service (profile `agent`) builds the agent image, and
`make agent` starts the local agent from that image instead of the app image,
which no longer ships `almanac-agent`.

Not in this task: the development Compose file, the platform check in
`make setup`, the Makefile split between host and container, and the removal
of the Linux lane (F7-T02 and F7-T03). `make build` still compiles host
binaries until F7-T03 renames it.

## Implementation evidence

- Candidate: `design/platform-agnostic-verification` at the commit after `25c5a44`.
- Images on this arm64 host, all `arm64/linux`: `almanac-local:dev` 42.6 MB
  (prints `almanac dev …` for `version`), `almanac-local-agent:dev` 36.9 MB
  (its executable has one command, `run`; the image's default command is
  `run`, which exits 1 with the executable's safe message when the required
  flags are absent), `almanac-dev:latest` 909 MB (versus 5.5 GB for the
  retired lane image): user `dev` with the host's uid/gid (501/20), go1.27.3,
  Node 26.8.1, sqlc 1.31.1, oapi-codegen 2.8.0, go-modern-guidelines 0.1.1,
  VictoriaMetrics 1.155.0, psql 15.19, Chromium 1248 under `/opt/ms-playwright`,
  `/workspace` and `/cache/*` owned by `dev`.
- Pin check: consistent across seven files; a divergent Go digest in
  `deploy/agent/Dockerfile` fails with the file and line (restored). The lane
  scripts and `deploy/verification/Dockerfile` were repinned to the index
  digests so the check holds until F7-T03 deletes them.
- `make verify`: pin check first, then typecheck, 362 web cases, build and
  exclusion check pass; the Go stage still fails on macOS on the Linux-only
  packages (pre-existing; it runs in the dev image from F7-T02).
- `docker compose -f compose.yaml config` valid with and without the `agent`
  profile; `node --check` and `sh -n` pass on the changed scripts.
- Environment: the first two dev image builds failed on a full host disk
  (Colima's sparse data disk could not grow; the VM reported I/O errors and
  the daemon lost blobs). After freeing space, removing 18 stale almanac
  images, 41 volumes and the host `.local/go` cache, and restarting Colima,
  the build succeeded. The first user-creation attempt also failed because
  the host gid 20 already exists in Debian; the Dockerfile now reuses an
  existing group or user id.
- Limitations: the Compose journey and the real integration suites were not
  re-run (they are the subject of F7-T02 and F7-T03); `make publish` is
  untested against a registry until one is named.
