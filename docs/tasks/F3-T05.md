## User acceptance checklist

- Run the operational SLO database case or executable lifecycle case directly,
  preserving real PostgreSQL/API/agent behavior and original deadlines.
- Receive a check result with the actual selected cases, source fingerprint,
  duration, exit status and retained artifacts, including failures.
- Reuse current database evidence after a CSS-only change and current production
  browser evidence after a storage-test-fixture-only change. Changed backend code
  invalidates affected database and journey evidence.
- Attempt a handoff with missing, failed or stale required evidence: it must fail.
- Attempt a repeated broad gate without a matching focused result and recorded
  affected boundary: the active task guard must refuse it.
- Preserve task-wide correction history across different errors and checkouts;
  after two failed handoffs, require a recorded change in delivery approach.

## Outcome and scope

A small extension of existing Make verification tooling: fixed focused modes,
machine-readable source-bound receipts, a shared local active-task state, and
rerun/handoff checks. No new service, dependency, arbitrary test regex, command
passthrough or product behavior. Existing full checks keep their scope and failure
semantics. Local state is editable; this is an operational guard against accidental
loops, not a tamper-proof security boundary.

One implementer owns the complete failing real journey through handoff. Coordinator
review and final integration remain independent. A new error or correction brief
does not reset the increment's count. Focused entry points and their actual command
authorization must be ready before further runtime correction loops.
