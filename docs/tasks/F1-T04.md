## Bounded outcome

A real Go executable serving the embedded production React assets and a fixed-origin
backend API proxy in UI-only mode. Operational health and graceful shutdown work.
No database, credentials, authentication, agent, alert worker or management CRUD is
simulated. Backend/alerts/combined modes fail explicitly until their later task;
the binary must not advertise successful backend startup or readiness.

## Contracts

Module `github.com/dsolsona/almanac`, Go1.27.3. Read the full Modern Go Guidelines
list for that target before Go edits; consult applicable explanations. Use
encoding/json/v2 for new handwritten JSON and net/http method-aware routes.

- `almanac version [--output=json]`: version/build metadata, a single JSON document
  when selected; diagnostic output stays on stderr. `almanac help` and `--help`
  describe implemented commands and explicit component limitations. Exit0 success,
  2 usage/config errors, 1 runtime failures. No prompts.
- `almanac serve --components=ui --backend-url=http://127.0.0.1:8081` starts UI mode.
  Default listen127.0.0.1:8080; configurable `--listen`. Default component selection
  remains backend,ui,alerts per spec, but fails with an actionable unsupported-mode
  error before binding. Reject unknown/duplicate/empty component names. Only exact
  ui selection is implemented in this task. Never collect external metrics.
- Strict bounded JSON config file via `--config`; at most64KiB, unknown/duplicate
  keys and malformed/trailing JSON rejected. Fields: listen, components,
  backend_url, shutdown_timeout. Precedence defaults < file < ALMANAC_LISTEN,
  ALMANAC_COMPONENTS, ALMANAC_BACKEND_URL, ALMANAC_SHUTDOWN_TIMEOUT < explicit flags.
  Config file is optional, but ui mode requires backend_url. Shutdown default30s;
  require positive duration at most2m. Validate all configuration before listening.
  Never print effective credentials/querystrings; errors should identify field,
  not echo rejected secret-bearing input.
- Backend origin: http/https with host; reject userinfo, non-root path, query,
  fragment and unsupported schemes. Use one immutable parsed target; proxy only
  `/api/v1/` management paths. No arbitrary destination, `/internal/`, `/api/agent/`
  or CONNECT/TRACE forwarding. Reject decoded dot segments/path bypass attempts.
  Forward auth/cookies as supplied; backend owns authorization. Strip untrusted
  forwarding headers using ReverseProxy Rewrite; preserve request cancellation.
  Bound response-header wait and dial timeout. Upstream errors are redacted JSON503,
  never an HTML success page or leaked URL/error. No redirect-following to an
  arbitrary origin in readiness checks.
- GET `/livez`: JSON200 `{status:"ok",component:"ui"}`. GET `/readyz`: poll configured
  backend `/readyz` with short bounded timeout (at most2s), no redirects; only200
  is ready, otherwise JSON503 `{status:"unavailable",component:"ui"}`. Liveness
  remains healthy during backend outage. Other methods return405.
- Define health responses and safe proxy problem in `api/openapi.yaml` (3.0.3),
  examples and anonymous operational access. Generate Go types and standard HTTP
  health routing with pinned oapi-codegen2.8.0; generate TS types with
  openapi-typescript7.13.0. Do not hand-edit generated output. This is the operational
  contract only, not a fabricated management API.
  Proxy errors follow SPEC-0010: stable code, safe message, server-generated
  request_id and field_errors (empty for an upstream outage). CLI JSON output
  includes a schema_version so automation can identify its contract.
- Embed only built web/dist via `web/assets.go`; serve root and actual assets with
  correct types, no directory listings, immutable caching for hashed assets and
  no-cache index. Unknown paths/missing assets return404, including /design-system;
  no SPA catch-all exposing development content. No Node runtime to serve the UI.
  API/proxy and health routing take precedence over static serving.
- Signals stop listeners, drain in-flight HTTP work within configured timeout,
  force-close after timeout, and return nonzero on actual listener/runtime failure.
  Use structured slog lifecycle messages without credentials. Unit tests use
  controllable contexts and short explicit test deadlines, not long sleeps.

## Tooling and verification

Project-local Go1.27.3 and Modern Go Guidelines0.1.1 are supplied via setup; Go
generator2.8.0 and TS generator7.13.0 are pinned. Setup is the only network-capable
dependency installation step. Builds/tests set GOTOOLCHAIN=local and GOPROXY=off
with the project caches and fail clearly if setup/build prerequisites are missing.
The TypeScript generator lives in tools/openapi/ with TypeScript5.9.3 because its
declared peer range excludes the UI's TypeScript7.0.2; never bypass peer validation
or downgrade the application toolchain. Its generated declarations are typechecked
by the application's compiler.

- Extend `make setup` to install both toolchains by default; retain explicit
  SETUP_MODE=web/go, UPDATE_LOCK=1 only for intentional npm lock updates.
- `make generate`: regenerate only checked-in operational API outputs with pinned
  installed tools; no network. Full verify checks generated drift without silently
  accepting modifications (temporary comparison or read-only check).
- `make build`: build production web once, then bin/almanac with embedded assets.
- `make verify`: existing web checks plus Go formatting/vet/tests/build and generated
  consistency. Keep browser matrix separate. `VERIFY_MODE=go` selects Go checks;
  optional GO_PACKAGE selects one repository package, safely quoted and validated.
  Zero selected tests fails. `VERIFY_MODE=go-race` exercises concurrent shutdown/proxy
  tests with race detector. Fixed-purpose runners only; no arbitrary shell arguments.
- Tests: config precedence/unknown/oversized/duplicate keys, bad component lists and
  origins, CLI output/exit codes; real httptest upstream proxy/path/auth/cancellation,
  readiness outage/redirect rejection, liveness, real embedded root/assets/404,
  graceful cancellation and bounded shutdown. No mocks pretending to prove DB/auth.
- Record binary size and gzip size plus web assets size; note this is the UI-only
  foundation, not the final server-with/without-UI release packaging benchmark.
