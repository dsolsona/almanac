## Outcome and scope

Current publication can use source aggregates rebuilt in the same scheduler turn,
without first writing an avoidable waiting deferral. Exactly one bounded source
batch precedes current/metrics; failed or leased source work cannot skip them.
The public worker interface, deterministic calculations, retry and publication
fences remain unchanged. Alert engine/fallback adoption and performance acceptance
remain separate work.

## Acceptance checklist

- Start with accepted observations in dirty source hours and a due SLO. One turn
  publishes exact current counts after source acknowledgment, with no waiting row.
- Historical backlog exceeds 100 keys: healthy current still publishes after one
  source batch, without draining old history first.
- Source preparation fails or is leased: independent current work stays available;
  missing data never becomes success. Existing retries and repair wakeups survive.
- Explicit clock moves across a cadence/validity boundary during source work:
  current selection uses fresh time; empty/backed-off loops retain bounded sleep.
- No browser interaction changes. PostgreSQL tests exercise production scheduler
  and publication paths in disposable development-fixture databases. Full-load
  currentness/ingestion/navigation are not established by these focused tests.
