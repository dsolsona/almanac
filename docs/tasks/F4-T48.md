## Outcome and exclusions

Persist the shared evaluator's admitted preparation requests before its parent
pending boundary is released, and execute restartable bounded resource turns.
Each immutable target remains fixed even when live authority advances. A pending
dependency never becomes successful numerical evidence or consumes a failure
attempt. Shared artifacts may finish after one policy is disabled; occurrence
publication still belongs to the existing policy/source fences.

Initial implementation is limited to internal enqueue/claim/run-turn/ack APIs,
SQL/schema and focused correctness tests. No Runtime registration, production
pool/batch/retry defaults, public API, policy dependency table, notification path,
calculator adoption or capacity claim. The primary owns actual alert/viewer hooks,
normal deployment and release acceptance. No preparation execution inside ingestion.

## Inspected producer and contract constraints

F4-T47 was frozen and hash-verified before implementation. Its request has `Kind`,
`RequestedRevision`, `BuildID`, `Hour maintenanceHourKey`, `Start/End`, and optional
`Comparison *maintenanceEvaluationBuildPair{FirstBuild,SecondBuild}`. The caller's
`maintenanceEvaluationInput` supplies SLO/SLI/definition/measurement identity.
A bare request cannot authenticate that scope. Normalization uses the frozen producer, including `source_window`.

`source_hour.Hour.SourceGeneration` is the cached aggregate generation, not the
current canonical dirty target. Canonical source requests must route by
SLI/measurement/hour to the existing dirty protocol. Only `scoped_hour` requires
an immutable exact generation. `comparison` never substitutes for an independently
needed urgent scoped-hour request.

ADR-0051 remains proposed in source; its implementation authorization does not
accept the whole scheduling/public profile. SPEC-0021's pending section and
ADR-0051 retain timer-based ordered retries without a new blocked-policy dependency
table. This plan preserves that mechanism. A successful artifact turn may return
an optional coalesced hint for the next scheduler tick, but cannot force another
attempt in the same tick. Losing the hint never loses durable work/cutoff. Stronger
publication retry semantics and final wording reconciliation belong to adoption.

## Implemented private interfaces

```go
type maintenancePreparationScope struct {
    SloID, SliID pgtype.UUID
    DefinitionRevision, MeasurementRevision int64
}
type maintenancePreparationPriority string // live or historical; explicit origin

type maintenancePreparationLimits struct {
    MaxRequests, MaxSourceHours int
}
// Resource phase: validate, normalize/deduplicate, admit, capture fixed-R pins.
func prepareMaintenanceEnqueue(context.Context, pgx.Tx,
    maintenancePreparationScope, []maintenanceEvaluationPreparation,
    maintenancePreparationLimits, time.Time) (maintenancePreparedEnqueue, error)
// Queue phase only: no subsequent resource or policy locks inside this helper.
func enqueueMaintenancePreparation(context.Context, pgx.Tx,
    maintenancePreparedEnqueue, maintenancePreparationPriority, time.Time) error

func prepareMaintenanceCompatibilityAt(context.Context, pgx.Tx,
    pgtype.UUID, int64, time.Time) (dbgen.AlmanacMaintenanceBuild, error)

type maintenancePreparationTurnOptions struct {
    MaxLive, MaxHistorical, Concurrency, PageLimit int
    Lease, OperationBudget, PendingRetry, FailureRetry time.Duration
    MaxAttempts int32
    RetentionStart time.Time // canonical retention authority, supplied by caller
}
func (*Runtime) runMaintenancePreparationTurn(context.Context, time.Time,
    maintenancePreparationTurnOptions, func() time.Time) (maintenancePreparationTurnResult, error)
```

Resource preparation requires READ COMMITTED and obtains SLI SHARE then SLO
NO KEY UPDATE before reading current binding. It is a final write/fence seam,
separate from the evaluator's RR calculation snapshot. No resource lock is
acquired after the queue-only phase starts.

The prepared enqueue value has private fields, owns normalized targets and is
valid only in the transaction that captured its pins. Implementation may combine
the two phases internally where the caller already owns all earlier authority
locks; it must retain the documented phase ordering. No generic arbitrary executor
callback, new pool or independently chosen numerical default is required.

Claim and completion helpers remain private, with job ID, token, epoch and lease
expiry in the claim. Limits are mandatory and validated against implementation
safety caps before allocation or SQL. The existing compiler/comparison page cap
is 1000; no other proposed numerical cap here is a production setting. Runtime's
existing derived pool of two and finite admission remain unchanged.

## Durable identity and normalization

Migration 0066 proposes one global preparation table with UUID job ID, kind,
typed immutable resource columns, priority, status, available time, last-claimed
tick, lease token/epoch/until, failure count/safe reason and timestamps. Use full
natural-key uniqueness with nulls handled explicitly, not a digest alone or an
opaque payload as the authority. Check constraints enforce the required fields
for each kind. Resource identity/provenance cannot change in an UPDATE.

| Request | Durable identity / execution |
| --- | --- |
| mask | `(SLO, requested R)`; capture that exact R using existing `captureMaintenanceBuild(...,&R,...)`, then claim/advance its existing compiler lease in bounded pages |
| compatibility | `(SLO, target R)`; fixed-R compiler input pin plus contiguous compatibility catch-up; add `prepareMaintenanceCompatibilityAt`, never call current-capturing preparation for a historical job |
| scoped_hour | Exact existing `(SLO, definition, measurement, build, hour, source G)` plus validated SLI; execute `prepareMaintenanceHour` under its RC contract |
| comparison | Canonical direct pair of two complete same-SLO build IDs; execute bounded persisted pairwise comparison, never transitive/hash inference |
| source_hour / source_window | No duplicate resource queue: normalize to admitted distinct canonical SLI/measurement/hour keys/ranges and call the existing dirty-work enqueue protocol; do not preserve cached G as its target |

Deduplicate source ranges and charge every distinct hour before expanding them.
Reject oversized/malformed batches atomically, rather than enqueue a successful
prefix. Existing `MarkDerivedHoursDirty` is not reused: its conflict update can shorten
failure backoff. Insert only missing canonical dirty keys for genuinely
unprepared hours, using current source authority and ON CONFLICT DO NOTHING.
Preserve healthy aggregates and every existing attempt, lease and deadline.
No source request may reset exhausted canonical work or create an alternate live
result buffer. The existing source worker owns execution and conditional ack.

Job identity excludes policy ID and requested priority. Multiple policies/current
and historical masks deduplicate by actual shared resource. Repeated enqueue may
promote historical priority to live, never demote it or rewrite its target. An old
exclusion R used for current recovery is LIVE. Do not infer priority from R or
hour age. Terminal unavailable/exhausted/obsolete records do not silently reset
when a reader repeats the same request; audited retry/retention lifecycle remains
an explicit later consumer contract. Durable completed artifacts are idempotent.

## Transactions, locks and parent connection

Observed existing lock graphs:

| Path | Existing order / ownership |
| --- | --- |
| Alert publication | SLI → SLO → source-generation → exclusion-state → policy → cursor → occurrence (`alerts_journal.go`) |
| Alert cutoff/range head | SLI → SLO → policy → cursor; persisted `pending_cutoff` survives ordinary deferral (`alerts_ranges.go`, `alerts_cutoff.go`) |
| Maintenance capture/writer | SLO root → exclusion-state → input guard → build; compatibility then takes its authority row (`maintenance_compiler.go`, `maintenance_compatibility.go`) |
| Scoped-hour preparation | RC; SLI SHARE → SLO SHARE → exclusion-state SHARE → build SHARE → source-hour SHARE, facts read after lock waits (`maintenance_hours.go`) |
| Canonical source worker | Short dirty claim; calculation transaction without dirty-row lock; generation+lease-epoch conditional ack (`derived_batch.go`) |
| Comparison turn | Comparison row lock, bounded immutable union reads, atomic cursor/state; no SLI/SLO acquisition (`maintenance_comparison.go`) |

The queue must not introduce job-row → SLI/SLO/build/resource lock edges. A short
claim transaction commits/releases its connection before execution acquires any
resource locks. Resource-owned publication is committed before a short conditional
job ack; neither resource work nor queue ack acquires policy/cursor locks.
A crash between publication and ack replays an idempotent artifact operation.

For the future alert integration, use a single pending-publication transaction:
acquire SLI/SLO authority in the necessary strength from the beginning, validate
binding, capture fixed-R pins/resources before policy/cursor/queue locks, then
lock/revalidate policy and claimed cursor (including epoch/token/version,
scheduled head, original pending cutoff and post-wait lease clock), enqueue
prepared jobs/canonical requests, and defer the same cursor atomically. If the
parent fence fails or the transaction rolls back, pins/new jobs and cursor release
all roll back. If enqueue cannot be admitted, do not clear the claim as if requests
were saved; lease expiry preserves the original due head. Do not upgrade a held
SLO SHARE lock to capture's NO KEY UPDATE after another reader could do the same.
This is a required integration seam; current `deferAlertWork` alone has no request
argument and does not supply this atomicity.

Viewer preparation similarly belongs to the authorized read's transaction/final
session authority validation, or an explicitly authenticated follow-up transaction
that revalidates session and resources. `alertReadTransaction` currently exposes
only q to its callback; do not add unauthenticated post-return writes or mutate
inside an actually read-only transaction. No viewer or engine callsite is wired in
this initial storage scope. Tests can exercise the transaction seam directly.

Canonical dirty enqueue and new queue upserts happen only after all required
resource locks, in deterministic key order. No path holding a queue row may later
request source/policy locks. Queue-only claim/ack therefore cannot invert the
existing parent or source graphs.

## Execution, outcomes and clocks

- Claim only immediately runnable bounded waves. Separate caller-supplied live
  and historical allowances provide explicit progress/fairness; no implicit new
  policy count, worker count or timer is selected. One job attempt per supplied
  tick. A waiting job releases its claim/connection and cannot hot-loop.
- Each claim increments an epoch and owns a token with finite lease. Completion,
  defer and failure updates require exact token/epoch and a still-live deadline
  read after lock acquisition. Enqueue priority promotion does not replace a
  claim or change immutable keys. Expired acknowledgements cannot remove newer
  demand or another worker's claim.
- Execute compiler claim/page, compatibility page, scoped-hour build or comparison
  page under its own existing fences. A compiler lease conflict or an unfinished
  page is pending progress, not a failed attempt. Queue lease loss may leave a
  valid shared artifact committed; stale queue ack is rejected and replay sees it.
- Pending dependencies, database admission/lock pressure and cancellation do not
  consume failure budget. Safe actual execution failures advance bounded attempts;
  exhausted work is recorded distinctly from unavailable history/corrupt evidence.
  Never derive SLO matching/unmatching truth from these statuses.
- Scoped-hour stale G is terminal obsolete for that fixed key. Do not retarget to
  a newer G or change the original alert cutoff. Return a scheduler hint; the
  ordered parent timer re-evaluates the same cutoff in a fresh snapshot and emits
  a new exact-G request. The same applies to genuinely obsolete bindings; changing
  only current exclusion authority does not obsolete a still-needed historical R.
- Use explicit clock callbacks, context deadlines and operation budgets bounded
  by the claim lease and existing DB settings. Read clocks after waits. Do not hold
  one derived connection while acquiring a second. No detached unbounded cleanup.
  Shutdown leaves unfinished claims recoverable by lease expiry.
- Disable/supersede fences the parent's occurrence/cursor as today. It does not
  cancel globally shared jobs merely because the originating policy stopped.
  Artifact completion never itself publishes an alert transition.

## Implementation and verification evidence

Migration 0066 adds only `almanac_maintenance_preparation`, its partial due index,
and an immutable-identity/terminal-state guard. Typed natural keys use `UNIQUE
NULLS NOT DISTINCT`; completed/cancelled shared inputs are retained by existing
resource fences and build references. No second canonical-source queue exists.
Natural keys exclude policy identity, priority and scheduling clocks. Reenqueue
can only promote priority; it cannot reset leases, attempts, deadlines or terminal
health. Compatibility capture uses the exact requested revision, not latest.

Safety caps are implementation admission bounds, not production defaults: up to
960 requests, 10,000 normalized source hours, 1,000 jobs per priority per turn,
one or two executing jobs (the existing derived pool), pages of at most 1,000,
a lease of at most five minutes, operation budget at most five seconds and the
lease, and retry delays at most 24 hours. Every caller supplies its actual smaller
admission and retention boundary. No capacity inference is made from these caps.

The full Go 1.27.3 guideline list was read through
`make shell CMD='make generate GENERATE_MODE=go-guidelines'` before Go edits.
SQLC was regenerated with
`make shell CMD='make generate GENERATE_MODE=sqlc'`.

## Independent review correction

The review found a mixed-revision lock inversion: enqueue captured compatibility
R1 and locked the shared compatibility authority before capturing build R2,
while a concurrent R2 catch-up owned build R2 and waited for that authority.
A controlled real PostgreSQL interleaving reproduced enqueue SQLSTATE `40P01`
in the 1.570s red selection. Resource preparation now captures/locks **all**
requested builds first, then ensures/locks the compatibility authority once after
the resource loop. The standalone fixed-R compatibility capture helper retains
its existing one-build order and semantics.

The same selection added cancellation during an actual compiler row-lock wait:
the resource transaction rolls back, the durable claim retains zero failure
attempts, and a later turn resumes after lease expiry. This passed before and
after the ordering correction and fills the previously unverified execution
cancellation case without introducing a production hook.
