## User acceptance checklist

- Add a point or duration note to an explicit SLO scope; see it on the shared
  timeline and in an accessible event list with real persisted data.
- Inspect and correct a note, recover from version conflicts without losing safe
  input, and delete it through an audited tombstone.
- Use UI/API/CLI with equivalent permissions and idempotent retries; retain
  automation external-ID uniqueness and immutable revision history.
- Filter and navigate dense overlapping events without silently dropping any.
- Change range/timezone and use keyboard/mobile/both themes without hover-only
  access. Event-read failures leave numerical graphs usable.
- Verify annotation changes leave attainment, budgets and burns unchanged.

## Outcome and boundaries

Deliver SPEC-0017's complete contextual annotation lifecycle as a usable increment.
This remains required F3 work. It was separated from F3-T03 so the fourth numerical
graph can ship as a complete increment without waiting for a second domain.
Do not fabricate notification incidents or implement mute, silence or maintenance
semantics through annotations. Do not add automatic vendor integrations, recurring
events, attachments or external URL fetching.

## Readiness and interfaces

Before dispatch, coordinator reviews exact OpenAPI/service/CLI contracts for explicit
scope, actor attribution, expected versions, point/duration overlap, bounded cursors,
revision history, tombstones, external IDs and idempotent conflicts. Reuse accepted
contracts and existing audit/authentication/receipt patterns; do not invent a second
annotation model. Preserve 400-day audit/history retention and disclosure of future
events as contextual planned records.

Assign a real database/browser lane and ready fixed focused verification before
implementation. One owner delivers backend/API/CLI/UI and regressions through a
working journey; coordinator independently reviews it. Use an active verification
plan and retain task-wide correction history. Broader checks run on the stable
integrated candidate under the existing testing strategy.

## Evidence

Not implemented. Required cases include role/scope restrictions, forged actors,
late retries and tombstones, revision races, range overlap, dense overflow,
