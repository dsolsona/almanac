## Outcome and non-goals

The suite in ADR-0033:
- `make test`, `make test-integration`, `make test-browser`, `make test-e2e`, `make test-perf`,
  `make check` and `make coverage`.
- CI on every pull request.
- The old runner, custom browser scripts and performance harness deleted.

Not in this task:
- Web coverage, which needs the `@vitest/coverage-v8` dependency installed through `make setup`.
- Permission-failure journeys, which wait for multiple users.

## Evidence so far

- **Integration, one invocation with parallel tests**, before removing the browser journeys: 173
  tests, 1 failure, about 131 s. The command package set that time, with its browser journeys taking
  up to 67 s each. Storage took 51 s.
  - The failure was the browser agent-lifecycle script reading a response body under load. That is
    the same class as the open "body_read_failed" investigation in F3-T08, and that script is being
    deleted.
  - An earlier run of the storage package in one process failed once and has not recurred. Its cause
    is unknown.
- **End-to-end:** `make test-e2e` passed all 9 journeys in 157 s, including building and starting
  the fresh stack. The time is mostly the first SLO evaluation, about 1.5 min.
- **Findings while writing the journeys:**
  - VictoriaMetrics hides samples from the last 30 s of queries. The preview test stamps its sample a
    minute in the past.
  - A local agent shares the app container's network namespace, as `make agent` does, so it must be
    restarted after the app restarts. The old Compose check did the same.
  - Forms preselect the only agent or datasource.
- **Performance:**
  - The first run found that decimal good counts left 4 of 20 SLIs without an observed interval. The
    fixture now uses whole counts out of 10,000.
  - The next run reached the SQL history step and stopped when the Mac's disk filled. See the next
    section.

## Blocked

On 2026-11-05 the Mac's disk filled to 147 MB free while the performance fixture was writing. The
Colima VM's containerd then reported input/output errors on its blob store and metadata database.

`fstrim` returned about 2 GB, so 2.2 GB is free. Docker still cannot list images or remove
containers.

Recovery needs two things the maintainer owns: free space on the Mac, and `colima restart`, which also
restarts other projects' clusters and the `make run` stack. The `almanac-e2e` stack and volumes are
left in place. Remove them once Docker works with `make shell SOCKET=1 CMD='sh scripts/e2e.sh down'`.
