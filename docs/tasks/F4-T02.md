## Outcome and scope

Produce reproducible evidence for accepting or rejecting bounded raw substitution.
Use an integration-test-only SQL candidate and the existing exact evaluator. No
production call site, schema, generated query, UI or observation semantics changes.
The candidate replaces dirty aggregate contributions, never repairs them. Compare
against independent raw-observation totals and the existing batched query.

## Pinned candidate and workload

- Default windows: 5 min, 1 h, 30 min, 6 h; 60-second cadence for contention.
- At most 8 distinct dirty hours and 7,200 raw interval visits per batch (including
  raw edges; overlapping windows may conservatively charge a row more than once).
- At most 4 windows per candidate batch, 2 concurrent candidate database operations,
  250 ms admission allowance, 1 second statement timeout, 2 seconds operation deadline.
- A budget rejection returns pending with no partial totals. Terminal source
  exhaustion remains failure. Snapshot consistency includes readiness and counts.
- Correctness includes 15/60/70/7,200-second cadences, mixed and all-dirty windows,
  quality/null cases, revisions, concurrent publication/ingestion and cancellation.
- Contention: 200 independent SLIs, 60-second cadence, four-window mix; one comparison
  across rollover with 3 days of backfill and live collection. Record actual runner,
  offered query/backfill load and all unfinished operations. Browser evidence must
  measure authenticated rendered SLO navigation, not substitute API timings.
- Exclusions are currently unsupported by this calculator (`exclusion_revision=0`);
  record that gap, preserve later alert acceptance, and do not invent support here.

Contention entry point: `make shell SOCKET=1 CMD='E2E_CONFIG=playwright.alert-calculation.config.ts sh scripts/e2e.sh'`.
The experiment seeds 200 SLIs/SLOs and one day of history with minute-17 holes,
then fills those late holes and adds three older days under live collection.
Two query connections each run 100 batches at four controlled cutoffs (58/59/00/01
around a historical UTC hour), pacing at 250 ms after each paired baseline/candidate
query. This is at most 8 batches/s, a closed-loop load with actual throughput
reported; it does not establish open-loop queue admission latency. Each pair uses
one repeatable-read transaction, alternates execution order and has a 1-second
statement limit. Ten browser users each exercise ten cold/warm list/detail cycles
(100 samples per journey) during the load. No wall-clock engine rollover is claimed.

## Limits of this fixture

The two closed-loop query workers bound concurrent SQL work, but do not exercise a
production pool or prove the proposed 250 ms admission allowance. PostgreSQL's
250 ms lock timeout is a separate control. The Go adapter uses a 2-second context;
the contention wrapper uses a 1-second statement timeout for the complete paired
query and independent reference. Neither is an alert-commit measurement.

Live observation counts/receipt delay establish continuity, not ingestion handler
p95 or its ratio to an ingestion-only baseline. The stock isolated stack does not
expose the private ingestion metrics listener. These measurements cannot establish
SPEC-0019's ingestion latency budget. Emitted `raw_rows` in the contention output
are contribution counts; separate EXPLAIN checks include filtered/rechecked rows,
but do not prove every possible PostgreSQL plan obeys a physical-row cap. Missing
acceptance evidence must remain explicit in the adoption recommendation.

## Result and recommendation

The experiment is reviewable; **candidate adoption is not justified**. The
[recorded contention result](../evidence/alert-calculation/README.md) preserves
the exact measured source hashes, runner, numerical results and failed work.
All 800 paired batches completed, with 236 baseline-pending batches resolved by
the candidate. Offline decimal/raw-metadata verification passes all 3,200 windows.
Candidate query p95 was 46.066 ms, versus 41.962 ms for the baseline. This excludes
admission and says nothing about alert-commit latency.

The combined fixture failed: nine completed first list renders took 7.941–8.610 s,
all ten browser users eventually failed, and there are no completed detail samples.
Only 190/200 SLIs supplied fresh live intervals during the measured 180.894 s;
maximum observed receipt delay was 140.517 s. Backfill exceeded its 180-second
process deadline and raised an unhandled input-pipe EPIPE. Both query workers
completed and their raw output was preserved. Playwright reported 2 passed / 1
failed in 5.7 minutes, with the measured test taking 3.0 minutes.

This does not establish fallback as the cause or prove data loss. The backfill
fixture's 12,000-row hourly transactions mark all 200 SLIs together, unlike normal
bounded ingestion. Source-generation lock duration is a concrete confounder to
investigate. The exact completed backfill count and rejected navigation spans were
not captured. Retain the accepted calculator; next evidence needs bounded backfill,
ingestion-only latency and server/browser traces, plus admission/physical-plan
bounds. Do not increase deadlines or adopt a detection target from this run.

The post-run harness correction handles input-pipe errors, records process
deadline/exit metadata and emits progress after each committed backfill batch.
This is diagnostic work only; no second contention pass or workload fix is claimed.
The measured SQL remains unchanged.

Final focused integration verification passed in 3.323 s. EXPLAIN observed zero raw
visits for rejected work and 455 for admitted work, including rows removed by
filters/rechecks. The independent delta review found no remaining actionable
findings in the three corrected areas; its disclosed measurement gaps remain.
Direct TypeScript checking of the new harness was attempted but cannot complete
with the current toolchain: Node type definitions are absent and ordinary app
typechecking excludes performance files. No dependency or compiler checks were
weakened. Playwright source loading is checked separately.

Final Playwright listing loaded all three intended tests successfully (onboarding,
seed, calculation); it is syntax/discovery evidence only. Documentation validation
passed 232 Markdown files / 1,746 local links in 0.704 s including container startup,
and the staged whitespace check passed. Ordinary application, broad browser and
performance suites were not rerun: this branch adds experiment-only code and
records, with no production behavior changes. The failed contention run and
unavailable harness typecheck remain visible; no green adoption gate is claimed.
