## Outcome and non-goals

`compose.dev.yaml` defines the development stack: a `postgres` fixture
(PostgreSQL 18.6 by index digest, tmpfs data directory, listening on port
15487, no published port, autovacuum activity logged), a `victoriatraces`
fixture (tmpfs, loopback port 19428, the sink the journeys export traces to
and read them back from; the host runs had silently used the operator's
local stack for this) and the `dev` service built from
`deploy/dev/Dockerfile` for the host user's uid/gid, which shares the
fixture's network namespace so the fixed loopback URL on port 15487 works
unchanged. The checkout is the only host mount (`/workspace`); the Go module
and build caches, the npm cache and both `node_modules` directories are named
volumes. The dev service has no Docker socket. `ALMANAC_TEST_DATABASE_URL` is
preset inside the container.

`make setup` builds the dev image, pulls the fixture image, fails when either
image's platform differs from the daemon's, and warms the Go module and npm
caches inside the container (`UPDATE_LOCK=1` refreshes the web lockfiles
first). `make shell` starts the fixture and opens a shell in the dev container;
`make shell CMD='…'` runs one command there. `make stop-dev` takes the dev stack
down (its fixtures hold no data); `make stop` keeps stopping only the local
stack. (A first version made `make stop` down the dev stack too; Compose
also tears a project down by name when the named file is missing, which
removed the Compose verifier's own project inside its build context.)

Every Makefile target and verification script resolves Go, gofmt, sqlc,
oapi-codegen and go-modern-guidelines from the image's PATH, with no
`.local/bin` toolchain, no `.local/go` caches and no `scripts/setup-go.sh`.
The database fixture check queries the live server for the fixed database,
role, server version, loopback address and port; it never starts containers.
The integration runner identifies the fixture by its server start time and
version instead of a Docker container id. The VictoriaMetrics fixture of the
SLI journey always starts the baked binary; the `docker run` path and the
Linux lane marker (`ALMANAC_LINUX_VERIFICATION_CONTAINER`,
`/etc/almanac-linux-verifier`) are gone from the Go tests and the Makefile.
The Compose verifier writes its build context under `.local/tmp` instead of
the system temp directory.

Not in this task: `scripts/verify.py`, the Compose journey socket mode, the
deletion of the lane scripts and `deploy/verification/`, the command catalog
rewrite (F7-T03, F7-T04). The `linux` and `linux-sli` modes are no longer
reachable through `make setup` from this task on; F7-T03 deletes them.
