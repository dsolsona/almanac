## Outcome and method

The CI split server approaches its two-logical-CPU ceiling. Historical work is a
large elapsed-time contributor, but spans cannot identify CPU cost. Profile the
actual hour builder on one ready real PostgreSQL fixture before choosing pacing,
batch-size or computation changes. No capacity claim or timing-budget amendment.

A private integration probe uses the existing 60-second-cadence observed fixture,
fixed time and one-hour SLO. It repeatedly builds the same complete historical
hour for fifteen seconds after setup, profiling only that section. Every result
must serialize identically. The process profile measures Go CPU; PostgreSQL work,
pool contention and the whole mixed workload remain outside it. No E2E stack reset.

## Checks and limits

- `make shell CMD='go test -tags=integration ./internal/storage -run "^TestIntegrationBackgroundCPUProbe\z" -count=1 -timeout=60s -v'`

  affected deployment journey and a frozen workload control. Slower historical
  progress must still meet closed-hour readiness; accepted work cannot be skipped.
