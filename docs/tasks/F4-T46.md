## Outcome and implementation boundary

Retained evidence keeps its actual computed revision. Reuse under a requested
maintenance revision requires a complete indexed absence proof over the complete
source window, or an exact immutable union-equivalence certificate. No growing
revision-chain walk, earlier-start scan or broad work-queue envelope is a proof.
Future/narrow edits must leave distant source ranges immediately usable. Unchanged
overlapping coverage requires exact union comparison, not declaration metadata.

Start with a PostgreSQL prototype of built-in multicolumn GiST over a timestamp
range and revision range, together with the existing SLO/revision btree strategy.
Inspect actual planner choice on many unrelated SLOs/revisions without disabling
sequential scans. This isolates index strategy before changing writers. No new
PostgreSQL extension or architectural dependency is authorized by this prototype.
The prototype is not the 100/200-policy workload or a navigation latency result.

The later persisted form records at most two disjoint conservative changed-input
ranges for a declaration/scope mutation, using the old/new interval symmetric
difference. Metadata-only changes record an explicit analyzed empty change set.
These facts must commit atomically with the existing authority event. Existing
history needs bounded, pinned preparation and a contiguous indexed-through fence;
missing history cannot be interpreted as no changes. Migration 0064 is reserved
after the separately owned partial-hour 0063 contract. No production consumer
switches while the preparation/index/certificate protocol remains incomplete.

## Acceptance before adopting a persisted strategy

- Compare independently expected empty/changed results for old/new/scope and
  overlapping declarations, metadata-only edits and distant windows.
- Actual SQL plans prune both window and revision dimensions with SLO identity;
  inspect visited rows/buffers, not just the presence of an index definition.
- Missing/unprepared change history yields explicit unavailable preparation.
- Relevant concurrent mutations fence publication; unrelated source writes do
  not restart immutable mask compilation or invalidate distant source ranges.
- Exact unchanged-union proof retains new provenance without recalculating an
  entire retained year. Never infer equivalence from a hash or coverage flag alone.
- Preserve old computed identities and original evidence, including current and
  last-breaching masks evaluated against the same present source facts.

All execution uses the Docker catalog and disposable fixtures. Begin with

Run focused changed behaviors, preserve failures and record actual durations and
plans. No broad suite, production registration, performance-target relaxation,
operator preview/data changes or additional PR per internal layer.

## Confirmed implementation plan (isolated persisted stream)

Worktree `.worktrees/maintenance-compatibility`, branch
`codex/maintenance-compatibility`, base `a69dbb3`. Root prototype and compiler/math
files are copied dependencies; migration 0063 is copied solely to preserve the
migration suffix. This stream owns migration 0064, new compatibility/comparison
queries and Go/tests, affected generated output and this plan extension.

Private interfaces proposed before implementation:

- `prepareMaintenanceCompatibility(ctx, tx, sloID, now)` captures the existing
  compiler build/input pin at current R under SLO→exclusion-state→input-guard
  ordering, then initializes/locks the compatibility authority. Returns build ID
  and fixed target R. No compiled union is required for raw-event catch-up.
- `advanceMaintenanceCompatibility(ctx, tx, buildID, pageLimit)` uses that durable
  pin and authority row lock to analyze one bounded contiguous raw page. Returns
  scanned count, indexed-through and preparation state. Bounds are explicit,
  cancellation propagates, cursor+rows commit atomically. No worker registration,
  scheduler defaults or independently expiring pin is introduced.
- `readMaintenanceCompatibility(ctx, tx, sloID, computed, requested, start, end)`
  requires repeatable-read, validates C≤R≤authority and (when C<R)
  indexedThrough≥R, and
  returns a typed proof retaining original C, requested R, checked window and
  proof identity/kind. A GiST hit is changed unless a completed direct pair
  certificate proves identical complete unions. Pending/missing history never
  produces compatible. Equal revisions are checked before constructing C+1.
- `prepareMaintenanceComparison(ctx, tx, firstBuild, secondBuild, now)` validates
  two complete, same-SLO immutable builds and persists a direct canonical pair.
  `advanceMaintenanceComparison(ctx, tx, comparisonID, pageLimit, now)` locks its
  row, reads ≤limit union intervals from each indexed start cursor, and commits
  exact pairwise bounds comparison plus cursor/state atomically. Only terminal
  equality after both streams end is reusable. Each call advances or terminates;
  interruption rolls back, resumed work needs no in-memory array/hash baseline.
  A fenced cancellation terminally stops a pending comparison.

### Atomic event analysis and retention

Add one lazy per-SLO authority row with stable positive int64 identity ordinal,
contiguous indexedThrough and unavailable marker. An AFTER INSERT event trigger
analyzes a contiguous next event in the writer transaction; noncontiguous legacy
input stays unprepared until pinned catch-up. Reuse the existing
`almanac_slo_exclusion_snapshot_idx` for the previous same-declaration event.
An explicit change-set row records even zero ranges. Its FK pins the source event;
referenced immutable declaration versions remain protected by existing provenance
FKs. This prevents later analysis silently treating a deleted predecessor as no
old membership. Unanalyzed history is protected by the compiler capture protocol.
A gap detected during catch-up is unavailable and cannot advance across the gap.

Each old/new interval symmetric difference has at most two disjoint ranges.
Scope removal uses old bounds, scope addition new bounds; equal bounds produce
an explicit empty set regardless of metadata. Conservative declaration changes
may overlap another declaration and therefore require the direct exact union
comparison before claiming globally unchanged coverage.

Use built-in 3D GiST `(scope_key,input_range,revision_key)`, keyed by the stable
ordinal, never a lossy UUID hash. Encode point `n` as `[n,n+1)`, with an unbounded upper endpoint only when
`n=MaxInt64` (there is no larger bigint value). Encode revision span `(C,R]`
as `[C+1,R+1)`, using that same MaxInt64 upper case. Validate equality before
computing C+1. Avoid inclusive discrete upper endpoints, whose canonicalization
would itself overflow. UUID remains the authority identity and query additionally
filters it.

Coverage DELETE must reject every row of a complete build until a future explicit
bounded reference-retention protocol replaces the guard. No existing cleanup
caller deletes those rows. This initial restriction and analyzed-event FKs retain
inputs used by completed proofs; they are not a claim of implemented retention.

### Verification

Fail first on absent persistent schema/behavior; then focused PostgreSQL race
cases: independently expected old/new/empty/scope ranges; direct absence and distant
future changes; legacy catch-up with fixed pins and missing revisions; concurrent
writers and stale RR; overlapping unchanged versus different complete unions;
restart, rollback, cancellation and strict page bounds. EXPLAIN the actual generated
absence query on representative indexed data without disabling sequential scans.
Reuse root's completed 200k-row prototype as strategy evidence, not a new benchmark.
No broad application, performance, operator fixture or public API checks.

## Reviewed same-revision correction

Independent review found that a valid retained/compiled R1 read with C=R1 and
legacy index cursor zero incorrectly returned pending. A later unavailable history
gap also incorrectly blocked that identical immutable mask identity. The new real
PostgreSQL regression reproduces both failures in 0.469 s, while the existing
future-revision, read-committed and genuine-difference guards remain successful.

The correction moves only the same-revision result ahead of index preparation,
after resource, requested/current authority and RR validation. It performs no
changed-input/C+1 query. Differing revisions still require prepared history.

Focused correction green: four top-level cases plus four subcases pass under race
in 2.298 s:

```sh
make shell CMD='gofmt -w internal/storage/maintenance_compatibility.go && go test -race -tags=integration ./internal/storage -run "TestIntegrationMaintenanceCompatibility(SameRevisionBeforeCatchup|Proof|Snapshot|MissingHistory)" -count=1 -timeout=5m -json'
```

The original red and corrected output are retained separately. SQL, migration and
generated sources are unchanged by this correction; no broader check was run.
