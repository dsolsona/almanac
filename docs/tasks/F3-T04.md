## User acceptance checklist

- Open SLIs and browse the reference's dense ruled rows: health, name/context,
  type, datasource, recent measurements, last sample and linked SLOs.
- Search/filter across all matching records, not just a loaded page. Follow the
  datasource/SLO links, return with browser history, paginate and reload.
- Create a supported two-query count SLI with ordinary PromQL, using explained
  measurement selection and labelled line-numbered monospace query editors.
  Understand the actual supported value interpretation before saving.
- Correct an invalid query/input while preserving safe fields. Unsupported
  fraction/threshold modes explain availability and cannot submit an invalid definition.
- Distinguish no data, zero traffic, source failure, stale observations and an
  agent that is connected but has not returned a measurement.
- Verify normal Compose creation through an actual agent-collected result and
  side-by-side SLI list/editor comparison in both themes at 360/1024/desktop widths.

real list data and shared controls. No collection scheduling, cadence, historical

not authorization to implement F5 fraction/threshold execution. Folder/label
organization is not invented in a presentation-only increment.

Coordinator-approved list/API contract (2026-10-29): extend `GET /api/v1/slis`
with bounded `q` search and optional datasource ID filtering, applied before cursor
and page limit. Search covers stable SLI name, display name and datasource display
name. Bind normalized filters into new cursors; preserve existing blank-filter
cursors. Keep the existing `1..200` page limit and `(created_at,id)` order. Add
optional list projection fields for datasource display name, recent measurements,
and linked SLOs. Return the last 12 completed cadence intervals for the current
measurement revision, using interval start and cadence from the datasource and
retention plus evaluation-valid boundaries. Reuse canonical observation/attempt
precedence and explicit coverage states; do not scan full history or query sources.
The maximum is 2,400 recent sample points at page size 200. Return at most five
linked SLO summaries in stable order plus exact total count; show `5 of N` when
truncated. Remove the per-row latest-accepted timestamp query by projecting the
existing bounded aggregate in the list statement. The authenticated list query is
one bounded page statement. A materialized candidate-page CTE applies search,
datasource filtering, cursor ordering and the requested-plus-one limit before
receipt, latest-sample, recent-window and linked-SLO enrichment; those projections
therefore execute for at most 201 candidate rows. Any enrichment SQL error fails
the page rather than silently omitting fields. Keep existing session, role and
revocation checks.
Optional projection fields are validated/required only for list pages; detail and
create responses do not need to synthesize them. CLI list supports the same query,
datasource filter, cursor and page behavior through the API. Keep the accepted 10 MiB
response cap by returning the largest fitting prefix and a cursor after its last row;
the requested limit is an upper bound. Measure encoded rows once with exact envelope
accounting. Projection completeness and exact values are never reduced to fit the byte
cap. The single-row size is far below the cap under existing query/name bounds.

The receipt-time `last_observation_at` projection uses a narrow partial index on
`(sli_id, recorded_at DESC, interval_start)` for observed/known-empty coverage, with
the existing retention predicate and `ORDER BY recorded_at DESC LIMIT 1`. This adds
a migration and write/storage cost on accepted coverage rows. The coordinator will
inspect the real query plan and behavior in the isolated fixture; the index definition
alone is not performance evidence. A second index on
`almanac_slo_definitions(sli_id, revision, slo_id)` supports bounded linked-SLO lookup
by SLI; it adds storage and write cost on SLO definition changes.
