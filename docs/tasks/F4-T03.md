## Outcome

An outstanding historical observation INSERT must not block unrelated live agent
authentication merely because both reference the same immutable agent ID.
Disabling, revoking or rotating authority must remain serialized with access.

## Evidence and plan

The corrected 200-SLI experiment recorded ingestion p95 111–117 ms against an
ingestion-only 15.8–16.6 ms, even without browser work. One 198.842 ms trace spends
166.980 ms in `LockAgentAccessAgent`. The query requests FOR UPDATE, which conflicts
with the KEY SHARE lock taken by canonical observations' agent foreign key.

1. Reproduce using a real uncommitted canonical-observation insert and concurrent
   `AuthenticateAgentCredential`; expect access to complete before the insert commits.
2. Change the implicated immutable-reference locks to FOR NO KEY UPDATE and regenerate SQLC.
   Verify disablement/revocation ordering, cancellation and unchanged credential
   checks; no authority check or data constraint is removed.
3. Run focused agent-access/ownership/ingestion cases because the lock is shared by
   authentication, assignment and ingestion. Re-run corrected contention with
   baseline metrics and actual browser navigation; retain traces on failure.
4. Publish a dependency PR and continue the alerting plan. This is a routine
   implementation correction inside existing contracts, not fallback adoption.

PostgreSQL's [row-lock compatibility](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-ROWS)
defines the intended distinction: NO KEY UPDATE still conflicts with authority
updates and deletion while allowing concurrent foreign-key references.

The fixture's earlier fresh-count assertion was also invalid: it required intervals
starting after load began to have arrived before their settling/dispatch/completion
deadlines. It did not establish collection lag. Preserve those raw counts but now
assert phase-end presence of every interval becoming due during the phase under
ADR-0043's fixed clock, 60-second settling, SHA-256 dispatch phase and cadence
allowance. The query compares receipts with phase end, not each interval's own
deadline: a late receipt arriving before phase end passes. This establishes final
coverage, not per-interval punctuality, which remains unverified. It does not
change product deadlines. The measured ingestion-handler
latency regression and failed navigation evidence remain valid independently.

The integrated 200-SLI run completed in 5.6 minutes (contention 3.3 minutes) and
**failed** the broader gate. [Sanitized evidence](../evidence/alert-calculation/2026-11-13-bounded-contention.json)
records 149 completed paired batches/596 exact matching windows, both query workers

renders took 7.376–9.671 s. Ingestion p95 was 106.076–111.380 ms versus
16.612–17.443 ms baseline; four requests failed and 9/400 due intervals were missing
at the cutoff. The corrected due oracle establishes lateness here, not permanent loss.
The application image and both modified SQL source hashes are in the evidence.

This correction is verified for the reproduced immutable-reference lock defect;
it does not fix or waive the complete workload failure. A slow ingestion trace now
spends 2.997 s advancing the per-SLI source generation; the previous broad agent
