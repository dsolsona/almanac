## Outcome and acceptance

An administrator registers an agent, starts `make agent` and privately pastes its
credential. The agent runs separately using the selected Compose application's
network and public certificate. Its status must become connected and its assigned
datasource must test and collect. Ctrl-C removes the launcher's container and
temporary inputs without disturbing the app or data. A protected file supplied via
`AGENT_TOKEN_FILE` supports noninteractive operation. Refuse unsafe input and report
rejected credentials and ownership conflicts without exposing credentials. Container
startup alone is not evidence of connection.

## Scope and verification

Makefile, launcher script and README startup guidance. No automatic identity
registration or backend behavior changes. The existing isolated Compose acceptance
journey must invoke this launcher, prove real collection and inspect cleanup, secret
exposure and failure paths. The coordinator integrates and independently verifies
the combined candidate. Only the coordinator may mark this task done.

## Worker handoff

The launcher streams only the token and public certificate to a private container
tmpfs, runs as nonroot UID 10001, and shares the app's network namespace to
verify the existing localhost certificate. It validates the opened source file and
the agent checks its copied file's type, mode and size. The supplied file remains untouched.

`make verify VERIFY_MODE=compose` passed on the macOS/Colima candidate: PTY and
fake-Docker checks, real agent connection, datasource collection, the observed
99/100 SLI, interruption cleanup and Compose cancellation cleanup. Evidence is
`.local/compose-check-Qn9rYf`. Integrated and Linux verification remain outstanding.

First Compose attempt failed on a test-harness JavaScript syntax error, corrected.
The next ran three fake-Docker cases but lacked installed Playwright. After web
setup, the isolated real journey timed out before the launcher container appeared;
its cleanup then encountered an already-exited child. Diagnostics were retained at
`.local/compose-check-s5zz1s/diagnostics.json`. The launcher output was not captured,
so the startup cause remains unresolved; the harness now records it and handles
early exit. A subsequent pass cannot erase this first failure.

The PTY check then reproduced a prompt race: the prompt appeared before echo was
disabled. The launcher now disables echo first. The next two attempts timed out
waiting for the PTY child after SIGINT, and the sandbox denied process-group SIGKILL
in test cleanup. These failures preceded the revised process handling and successful
PTY and real Compose checks.
The coordinator-directed `pty.fork` rewrite passed prompt cancellation and echo
restoration but the post-submit case still timed out after Ctrl-C; its fake Docker
attach then waited in `sleep 30`. This result did not establish whether the
real Docker attach behaves the same way.
The prompt cancellation passed with `pty.fork`, while Ctrl-C during the synchronous
external attach wait did not complete cleanup within eight seconds. The coordinator
reframed this as an attach-process lifecycle correction: use an interruptible shell
wait and explicitly own and reap the attach process; retain the same test bound.
That change passed the prompt, post-submit cancellation and three fake-Docker cases.
The subsequent real Compose attempt reached startup but Docker rejected the public
certificate bind from macOS `TMPDIR` (`/var/folders/...` was not shared with Colima).
The launcher now creates its temporary files in the project-local `.local` directory;
the failed run's sanitized evidence is `.local/compose-check-LuZeUI/diagnostics.json`.
A further attempt failed because Colima mapped the bind-mounted token owner to a
different UID (`.local/compose-check-vgVjA9/diagnostics.json`). The launcher now
streams the inputs to a private container tmpfs instead of using host binds.

## Coordinator acceptance

Accepted on the integrated candidate documented in [F2-T24](F2-T24.md).
The coordinator's `.local/compose-check-O5ocRH` passed private PTY input, protected
file handling, separate real agent connection, provider queries and collection,
rejected credentials, Ctrl-C cleanup and fixture cancellation cleanup. The full
Linux gate also passed. Operator containers and credentials were preserved.
The prior startup timeout remains an open diagnostic gap; no later pass is claimed
to explain it. Restarting an agent can still wait for the previous ownership lease
to expire, up to one hour; launcher and README guidance disclose that limitation.
