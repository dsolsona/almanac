# F4-T55: Schedule and inspect maintenance in the browser

- Status: in review
- Governing contracts: [SPEC-0016](../specs/0016-maintenance-exclusions.md)
  and [F4-T53](F4-T53.md)
- Implementation plan: [0046](../plans/0046-maintenance-management.md)
- Dependencies: [F4-T52](F4-T52.md), [F4-T53](F4-T53.md), and [F4-T54](F4-T54.md)
- Worktree: `.worktrees/maintenance-ui` on `codex/maintenance-management-ui`

From the authenticated navigation, a viewer can list current revisions in
10- or 20-row pages, inspect bounds and affected SLOs, and open earlier
revisions. An editor or administrator can schedule a window from a form using
the shared search-first picker and UTC schedule controls. Affected SLO labels
load in batches of ten on the detail page.

The form follows the reviewed context, scope and schedule order. Selected SLOs
appear below the search input and custom minutes align with the duration
selector. The explicit-SLO API supplies the scope, validation and scheduling
authority. Lifecycle actions and overlays on the SLO detail timeline follow
this scheduling and inspection increment.

The isolated HTTPS and PostgreSQL browser journey passed in 2.5 seconds
(5.3 seconds including onboarding). It verifies keyboard scope selection,
inline custom duration, exact saved UTC bounds, the linked scope, a dark
360-pixel list, and cursor navigation with 10 and 20 rows.
