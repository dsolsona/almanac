## Outcome and non-goals

Persist only session verifiers. Issue a session after an external password check
only if the user's revision and installation epoch still match; authenticate and
touch sessions with 30-minute idle and 12-hour absolute expiry; revoke/logout with
an atomic audit event. This is internal storage, not a usable login flow. Do not
add public API, cookies, CSRF, password rotation, login throttling, startup wiring,
user administration or session cleanup jobs. Those remain subsequent work.
The application must verify passwords outside database locks before issuance.

```go
type LocalIdentitySnapshot struct {
    Found bool
    UserID, Login, Role, CredentialEpoch string
    PasswordVerifier string `json:"-"`
    Enabled, MustChangePassword bool
    CredentialRevision int64
}
type IssueSessionInput struct {
    UserID, ExpectedCredentialEpoch string
    ExpectedCredentialRevision int64
    Verifier [32]byte
    Now time.Time
    RequestID string
}
type SessionAccess struct {
    SessionID, UserID, Login, Role string
    Restricted bool
    CreatedAt, LastSeenAt, AbsoluteExpiresAt time.Time
    CredentialRevision int64
}
var ErrInvalidSession error
var ErrInvalidSessionInput error
func ReadLocalIdentity(ctx context.Context, databaseURL, login string) (LocalIdentitySnapshot, error)
func IssueSession(ctx context.Context, databaseURL string, input IssueSessionInput) (SessionAccess, error)
func AuthenticateSession(ctx context.Context, databaseURL string, verifier [32]byte, now time.Time) (SessionAccess, error)
func RevokeSession(ctx context.Context, databaseURL string, verifier [32]byte, now time.Time, requestID string) (bool, error)
```

LocalIdentitySnapshot is internal password-check input, never an API/log payload.
Do not format it in error/test messages. Read uses the same `lower(login)` expression
as the unique index; unknown login returns Found=false and no error. Login must be
nonempty valid UTF-8 at most256bytes, otherwise ErrInvalidSessionInput. Preserve
text; no new Go case-folding. A null password verifier returns an empty string so
the future application can deny local login with comparable dummy work. Database
failures must not masquerade as unknown users.

Issue input requires canonical lowercase UUID strings for user/epoch, positive
expected revision, nonzero Now and nonempty valid UTF-8 RequestID at most128bytes.
Authenticate requires nonzero Now. Revoke requires nonzero Now and the same
RequestID bounds. The [32]byte value is a trusted internal digest from the session
primitive; no raw session secret is accepted, returned, logged or persisted here.
Malformed input returns ErrInvalidSessionInput; rejected authority returns
ErrInvalidSession. Operational errors use existing safe bounded storage handling.
Every operation requires current explicitly upgraded schema and performs no DDL.

## Schema and transaction behavior

Migration0003 creates `public.almanac_sessions`: UUID primary `id` default
gen_random_uuid(), `user_id` UUID referencing users(id), unique NOT NULL `verifier`
bytea with octet_length32, positive bigint `credential_revision`, UUID
`credential_epoch`, boolean `restricted`, and timestamptz `created_at`/`last_seen_at`.
All fields NOT NULL; constrain last_seen_at >= created_at. Index user_id for future
per-user revocation. No plaintext or configurable expiry columns. Do not edit prior
migrations. Update sqlc inputs and regenerate through the existing command.

Use one transaction per mutation, with installation row lock before user row lock
before session row lock. Installation FOR SHARE fences epoch/provisioning changes;
user locks fence future disablement/password changes. Use a consistent lock order,
no lock upgrades or hashing under locks. Session lookup may first read the owning
user ID by digest, then must re-read and validate the session after acquiring locks.
Treat missing/deleted rows as invalid authority, never a new account.

Issue validates provisioned installation, enabled user, matching epoch/revision,
and presence of a supported local password verifier before inserting. It does not
perform the external password check again. Restricted=true when the user must
change password OR onboarding is incomplete. Each issuance gets a new session row;
duplicate digest insertion fails without overwriting or leaving an audit event.
Insert `identity.session.issued` success audit in the same transaction, actor and
subject set to user UUID, supplied server Now and RequestID only.

Authenticate checks the current enabled user, matching session/user revision and
session/installation epoch, provisioned state and exact expiry boundaries. Expire
when Now >= LastSeenAt+30minutes OR Now >= CreatedAt+12hours. Reject Now before
CreatedAt; otherwise update LastSeenAt to max(existing,Now), never backwards.
Use PostgreSQL microsecond precision consistently for stored/supplied times.
Return current role, not a stale session role. Restricted is stored restricted OR
current must_change_password OR incomplete onboarding; an old restricted session
cannot automatically gain authority when another session completes onboarding.
AbsoluteExpiresAt is always CreatedAt+12hours, never extended by activity.

Returned SessionAccess is a snapshot, not a lasting authorization lease. Future
protected mutations must validate current session/user/epoch inside their own
transaction; do not add caching or claim this API alone enforces future mutations.
Authentication/touch does not emit a success audit on every read.

Revoke validates the same authority/expiry rules without touching idle time, deletes
only the matching session and atomically writes `identity.session.revoked` success
audit (actor/subject=user UUID, supplied Now/RequestID). Unknown, expired, stale or
already revoked sessions return false,nil without an event; operational errors still
fail. Successful deletion returns true. No unrelated sessions are removed.

## Acceptance checks

1. Upgrade from schema2 to3 preserves initial owner, password verifier, installation
   ID/epoch and audit. Prior migrations remain byte-identical.
2. Case-insensitive local lookup returns the correct internal snapshot; unknown,
   disabled and null-password users remain distinguishable internally without
   disclosure in error strings. Invalid input and DB outages fail as specified.
3. Issuance persists only the digest, returns correct times/current role/restriction
   and commits exactly one audit. Rejected revision/epoch/disabled/unprovisioned or
   malformed input creates neither session nor audit.
4. Duplicate digest and injected audit insertion failure roll back all session work;
   retry with valid unique input succeeds. Fault injection is test-database-only.
5. Test just-before and exact idle/absolute boundaries with explicit server times.
   Activity extends idle only. Backward touches after creation never move LastSeenAt
   backwards; times before creation are rejected.
6. Concurrent touches serialize safely and persist the greatest valid LastSeenAt.
   User disablement, credential revision and installation epoch changes invalidate
   old sessions. Current role is used; restricted sessions do not auto-upgrade.
7. Logout is idempotent, leaves unrelated sessions intact, audits once and rolls
   back deletion if audit insertion fails. Expired/revoked/stale logout is a no-op.
8. Observe a blocked row lock, cancel and verify bounded return/cleanup and retry.
   Use bounded contexts, coordinated starts and bounded completion waits.
9. Missing/pending/newer schema and unavailable database fail closed with safe
   errors that exclude synthetic passwords, verifiers and connection secrets.
