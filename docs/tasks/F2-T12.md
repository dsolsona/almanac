## Outcome and boundary

Provide the reusable machine-authentication boundary needed by agent coordination
and HTTP configuration. Validate the issued opaque token against current PostgreSQL
state and return only its agent/credential identity and effective credential expiry.
This is a prerequisite within the connected-agent checkpoint, not a connected-agent
delivery or an execution lease. It must never create a human session, management
authority, heartbeat, configuration acknowledgement or collection-health signal.

No new dependency, migration, transport, OpenAPI path or UI is needed for this task.
Durable ownership/grants and their wire operations follow separately under the same
accepted contracts. Authentication success is a current-state snapshot, not a
reusable authorization proof for future writes or lease renewal.

## Implementation scope and interfaces

- Add `internal/agentaccess/` for token parsing and a small application service.
  Reuse `identity.AgentTokenVerifier` and constant-time verifier comparison.
  Raw tokens remain transient input and never enter result/error/JSON/log fields.
- Add `internal/storage/agent_access.go` and typed SQL in
  `internal/storage/query/agent_access.sql`; regenerate dbgen through sqlc.
  Existing migration0005/0007 already store all required credential state.
- The service exposes `Authenticate(ctx context.Context, token string)` returning
  a principal with AgentID, CredentialID and ExpiresAt, or a safe typed failure.
  Construct it with database-backed authentication and an explicit clock; use a
  small repository interface only if justified by these actual tests/consumer.
  Private type/constructor names are implementer choices; report the final API.
- Storage consumes canonical credential ID and a fixed-size candidate verifier,
  not the original token. Return the authenticated identity without stored verifier.
  Validate current installation epoch, completed onboarding, enabled agent,
  issued_at <= now, now < expires_at, absent revoked_at and
  (retire_at absent or now < retire_at). Effective expiry is the earlier of expiry
  and retirement. Exact expiry/retirement boundaries deny access.
- Use a bounded transaction and cancellation-aware I/O. Preserve existing relative
  lock order: installation, agent, credential. An initial unlocked lookup may find
  the agent ID but must not authorize it. Recheck all authoritative state after
  locks, including the clock after lock waits. Avoid unnecessary writes on reads.
  Reuse transaction/schema/error helpers and generated SQL conventions.
- Malformed token, unknown credential, wrong secret, epoch mismatch, disabled,
  unissued, expired, retired and revoked credentials share a non-enumerating invalid
  credential outcome. Unavailable storage and cancellation remain distinguishable
  safe failures; never convert database outage into authentication success.
- Do not couple machine access to the enabled state of its original human creator.
  No implicit ownership grant or cached authentication permits a later operation.
- Allowed support edits: fixed Makefile package allowlists, task/testing/plan docs.
  Do not refactor unrelated auth, lifecycle or HTTP implementations.
