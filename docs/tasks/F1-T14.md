## Outcome and boundaries

Make `almanac serve --components=backend` run the actual local authentication API
with PostgreSQL readiness, protected first-owner provisioning, TLS and duplicate
backend startup protection. Verify a real executable/TLS/database login journey.
Existing UI-only mode stays usable. Combined mode, alerts, browser screens, CLI
setup, ordinary management and collectors remain explicitly unimplemented; never
silently ignore selected components. This increment is an executable backend users
can call, not full F1 acceptance.

Own backend runtime/HTTP adapter, command/config wiring, a small storage ownership
resource, certificate-file reading, operational OpenAPI/generated outputs and fixed
test selections. No new dependency, migration, password policy or authentication
route semantics. Coordinator owns docs/Git. Keep existing preview5198 available.

## Configuration

Extend strict JSON config, matching ALMANAC_ environment overrides and explicit flags:

| JSON field | Environment | Flag |
| --- | --- | --- |
| database_url_file | ALMANAC_DATABASE_URL_FILE | --database-url-file |
| initial_admin_login | ALMANAC_INITIAL_ADMIN_LOGIN | --initial-admin-login |
| initial_admin_password_file | ALMANAC_INITIAL_ADMIN_PASSWORD_FILE | --initial-admin-password-file |
| public_origin | ALMANAC_PUBLIC_ORIGIN | --public-origin |
| tls_cert_file | ALMANAC_TLS_CERT_FILE | --tls-cert-file |
| tls_key_file | ALMANAC_TLS_KEY_FILE | --tls-key-file |
| trusted_proxy_cidrs | ALMANAC_TRUSTED_PROXY_CIDRS | --trusted-proxy-cidrs |

CIDRs are a JSON array of strings; env/flag use comma-separated strings. Parse into
copied netip.Prefix values, reject empty/invalid entries. No default trust, including
loopback. Require a protected DB URL file for backend mode, using existing exact
URL validation/whitespace semantics; do not add plaintext DB/password flags. Existing
`db upgrade` environment behavior is unchanged. Configuration errors identify the
field, never its secret-bearing value or file contents.

Require the same canonical HTTPS public origin as authhttp. Direct TLS requires both
cert and key paths; partial pairs fail before binding. Without that pair, require
explicit trusted proxy CIDRs for TLS termination; untrusted/plain HTTP authentication
still fails in authhttp. Health endpoints remain reachable on the listener. TLS1.2
is the minimum; normal certificate verification remains enabled in clients/tests.
UI-only mode rejects these backend-only fields until its secure proxy integration
ships; preserve its existing backend_url behavior. Unsupported component sets
(including the current default with alerts) still fail clearly before listening.

Do not validate/read initial credentials until persisted ownership is checked by
Service.EnsureInitialOwner. Already-provisioned deployments ignore missing/changed
initial files on restart, including before password rotation. Missing/unsafe/weak
initial credentials leave setup readiness false with a safe operator diagnostic;
serve health and authentication-unavailable responses so startup cannot turn into
an unauthenticated administrator claim. Correct the files/config and restart to
retry provisioning. Other bootstrap/storage/schema errors stop startup before binding.

## Certificate input

Load/parse certificates before provisioning or binding. Read the private key through
secretfile.Read with its protected regular-file checks and16384byte bound. Add the
fixed-purpose `secretfile.ReadCertificate(path string) ([]byte,error)` for a public
regular certificate chain, bounded at65536bytes, permitting normal0644 mode. Reuse
the nonblocking opened-target reader privately; do not weaken Read or expose an
arbitrary permission-bypass option. Parse with tls.X509KeyPair. No PEM contents or
paths in error diagnostics. Nonregular/oversized files and mismatched pairs fail.

## Backend ownership lifecycle

In storage, add `AcquireBackendOwner(ctx context.Context, databaseURL string)
(*BackendOwner,error)`, `Done() <-chan struct{}`, `Err() error`, and idempotent
`Close() error`. The acquisition context bounds acquisition only; this is an owned
resource that the command must close and join on every exit path. It owns a dedicated
schema-compatible connection, never a pool borrower or application transaction.

Use nonblocking session advisory lock namespace0x414c0003/key1 (two signed integers),
separate from login-account/source and bigint schema locks. A healthy duplicate
returns ErrBackendAlreadyRunning before provisioning/listening. Set the connection's
application_name to `almanac-backend-owner` for operational identification; never
log its URL. No automatic schema upgrade or reconnect/reacquire loop.

Monitor the owned connection every1second with a1second probe deadline. One goroutine
owns its I/O. Unexpected probe/connection loss records ErrBackendOwnershipLost and
closes Done immediately, before bounded connection cleanup. Normal Close cancels,
joins and releases the resource with no loss error; it must not race pgx I/O.
All cleanup is bounded (at most5seconds), with errors redacted.
Close after a recorded loss preserves ErrBackendOwnershipLost; it must never turn
that failure into a normal shutdown or clear the recorded cause.

Hold ownership until normal server shutdown has drained or forced closed requests.
Do not release merely because SIGTERM arrived. Ownership loss instead cancels the
HTTP base context, stops acceptance and force-closes the server, then exits nonzero;
never continue serving or automatically reacquire. Startup checks and this fail-stop
lifecycle are not general transaction fencing or backend HA. This authentication-only
increment has no agent commands or application workers; their accepted lease/epoch
fencing must be implemented before those workloads are enabled.

Keep signal notification separate from HTTP BaseContext cancellation: ordinary
SIGTERM stops acceptance and drains requests with their contexts live; only owner
loss or forced shutdown cancels them immediately. Monitor owner loss throughout
startup and graceful draining. A loss concurrent with normal shutdown wins the
exit status and must still produce a nonzero exit.

## Serving and readiness

Add `backendhttp.LoadTLSConfig(certFile, keyFile string) (*tls.Config,error)` for
the bounded certificate loader (both empty returns nil for trusted termination).
Add `backendhttp.New(ctx context.Context, cfg config.Config,
service *authentication.Service, databaseURL string, tlsConfig *tls.Config)
(*Server,error)` with the actual Serve(net.Listener), Shutdown(context.Context),
Close() lifecycle. New clones prepared TLS/configuration and prepares routing but
never binds or provisions; do not reread credential files during Serve.

Startup order is explicit: validate config/read DB URL/load TLS; acquire ownership;
construct the authentication service/server; provision initial ownership; bind/serve.
Monitor loss during initialization and check ownership/cancellation immediately before
listening. Every failure, including constructor/provisioning/listen failure, closes
and joins the ownership resource and any already-created server. The constructor's
HTTP base context must follow the separate signal/loss rules above.
Use a small lifecycle interface in command only if both actual servers consume it;
do not introduce a generic component framework.

Serve `/livez`, `/readyz` and the four exact authentication routes. Unknown routes
remain404 and unsupported methods405, with no path-cleaning redirect around the
auth boundary. Extend generated HealthResponse component enum with `backend`.
Liveness reflects the running process. Readiness is200 only while ownership is held,
schema/database are reachable and initial ownership is provisioned; mandatory
password rotation may still be pending. Use a2second readiness context and safe
503 on failure. Pending rotation does not enable ordinary APIs/workers.

Before forwarding authentication requests to authhttp, require provisioned initial
ownership and healthy ownership context; DB/setup unavailability returns the safe
authentication problem503 with a request ID, no cookies or password work. Preserve
authhttp's origin/source/CSRF checks. A restricted owner can reach only authentication
context, password change and logout, as already enforced by the available routes.
Use a separate2second preflight context for DB/schema/setup on every auth request,
including anonymous context calls that otherwise require no service database read.
Do not rely on the current cookie or cached startup readiness to perform this check.

Server bounds: ReadHeaderTimeout5s, ReadTimeout10s, WriteTimeout40s, IdleTimeout60s,
MaxHeaderBytes32KiB. The existing handler's body deadline5s remains tighter; middleware
must support ResponseController.Unwrap. Default graceful shutdown remains30s, with
forced close and joined serving/ownership goroutines. Propagate request cancellation.
Log safe component/address/start/stop/failure metadata, never credentials or payloads.

## Acceptance and checks

1. Configuration precedence/type/unknown-field and incompatible-mode tests cover
   every new field; unsafe public origin, partial TLS and missing trust fail before
   binding. UI-only no-DB behavior and existing operational smoke remain intact.
2. Real PostgreSQL ownership tests prove one healthy owner, immediate duplicate
   rejection, release/reacquisition after Close and incompatible-schema rejection.
   Observe the specific owner PID/pg_locks before contention/loss tests; no guessed
   sleeps. Use only disposable fixture databases and constant test administration SQL.
3. Real owner-connection termination cancels admission/server requests and produces
   nonzero process exit. Normal SIGTERM drains/closes before releasing ownership;
   no background reconnect, listener or monitor remains. Startup failures release it.
4. A real executable with trusted test TLS certificate and PostgreSQL provisions once,
   reports readiness and completes context→restricted login→rotation→normal context
   through HTTP. Restart with removed/changed initial files never resets ownership.
5. Missing/weak/unsafe initial credentials leave liveness available/readiness503 and
   authentication503 without a usable session or partial owner. Database outage after
   startup fails readiness/auth safely; schema incompatibility never auto-upgrades.
6. Certificate tests cover public0644/private0600, private permission rejection,
   opened symlink targets, nonregular/FIFO, byte limits and mismatched pairs. Never
   print test secrets on failure. Preserve existing protected-file and URL tests.
7. Direct TLS and explicitly trusted termination exercise the same auth handlers;
   spoofed metadata/untrusted plaintext cannot bypass security. No browser evidence
   is claimed; no test disables TLS, cookies, CSRF or authentication to pass.
8. Generated contracts reproduce, ordinary unit loops stay fast, and the actual
   binary is built by the existing gate before process acceptance. Extend fixed
   unit/race/integration selections only for real packages (backendhttp, command
   where needed). Integration `all` remains explicit serial packages; ensure missing
   embedded assets are built before command-package test discovery. No arbitrary
   passthrough flags or new shell runners. Preview5198 is untouched.

Use the installed Modern Go1.27.3 guidelines before edits. No new command approvals,
escalations, direct compilers/formatters, Git mutations or nested agents. Use exact
known make invocations; if a check cannot run, report it and continue independent
work. The coordinator owns the sole PostgreSQL runner and its saved exact invocation.
Report first failures, all acceptance mappings and measured checks, then freeze.
