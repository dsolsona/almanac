## Approved design

Return successful create/update saves to the policies list with a brief confirmation.
Keep failed or uncertain saves on their reconciliation flow. Match the policies
table to shared resource tables, including mobile labelled rows and an enclosed
pager. Put Active/History in the occurrence toolbar and Policies beside the page
actions. Retain server pagination and filtering.

Show supplied burn values, windows and threshold as the reason an alert is open.
Acknowledgement records actor/time without implying assignment. Keep current
evidence visible, with original evidence, calculations and revision metadata under
one collapsed details section. Explain reduced chart detail near the plot in plain
language, preserving real missing-data warnings. Engine semantics stay unchanged.

### CodeRabbit correction: repeated success notifications

The review of `cae4991` contains one actionable finding, inline comment
`4602263186`: the same success message repeated while still visible keeps its
original dismissal timer. Source inspection confirms both production and catalogue
consumers can set the same string without changing any timer dependency.

Each success now increments a notification ID in both consumers. Toast restarts
its timer on that ID while retaining pointer/focus pause state. Its live region
stays mounted; keyed message content changes for repeated announcements without
remounting the dismiss button. Dismissal still clears the message and pause flags.
The visual layout is unchanged; previous source-bound captures remain valid for
their recorded revisions.

The five-second regression fails before the correction, then passes with all five
toast cases in 946 ms:
`make shell CMD='cd web && npm run typecheck && npm test -- tests/toast.test.tsx'`.
The browser case repeats an identical message after four seconds, requires it to
remain visible for another 4,999 ms, then observes dismissal at 5,000 ms. The first
version exposed an automatically advancing test clock during browser interactions;
freezing the clock fixes that fixture without relaxing its time boundary. Original
failed traces are preserved privately in `.local/alert-ui-evidence/repeated-timer-failure/`.

`make shell CMD='cd web && npx playwright test browser/alert-ui-evidence.spec.ts --grep "reading time|feedback floats"'`
