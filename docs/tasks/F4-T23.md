## Outcome and plan

Prepare one fresh existing 200-SLI baseline control per CI placement. `shared`
puts server containers and client descendants on the first two available Linux
CPU IDs; `split` puts clients on the next two. Require at least four available
CPUs before any command or mutation. Record logical CPU topology/model and memory;
this is a same-host diagnostic sharing memory, I/O and kernel, not off-machine
acceptance or proof that logical CPU IDs are independent physical cores.

- [x] Write focused failing tests for host refusal, noncontiguous placement,
  container ownership, post-seed agents, assignment verification, failure cleanup,
  original workload commands and artifact secrecy.
- [x] Implement only `scripts/alert-cpu-control.py`: fixed CLI and injected command
  boundary; fresh isolated stack, pin/restart app/readiness, seed, repin/verify all
  running owned containers, original observer/baseline workload, bounded export,
  cleanup in finally with truthful exit status and safe staged evidence.
- [x] Run `make shell CMD='python3 scripts/alert-cpu-control-test.py'` and focused

`--check-host --placement shared|split` is read-only and never touches Docker or
creates artifacts. `--run` is explicit and intended inside the socket-enabled

## Evidence boundary

Upload only `.local/alert-cpu-control-artifacts/{placement}`. It contains typed,
allowlisted profiles, workload metrics/counts/timings/outcomes, observer streams
and sanitized bounded trace spans with completeness/error counts. Raw Playwright
reports/ZIPs, auth state, seed/workload logs, SQL, headers/bodies, command errors and
exception text must never be copied there. Private subprocess logs remain under
`.local/alert-cpu-control-private/{placement}`; original helper artifacts remain
private. A fresh run refuses existing artifacts instead of silently replacing them.

Profiles retain the original host CPU set/topology, requested and effective client
affinity, verified initial/pre-seed/measured/final server assignments and image
digests, revision and source hashes, expected workload constants, and each command's
index/stage/deadline/duration/exit code. They contain neither argv nor environment.
Ingestion-only baseline start/end timestamps and loaded before/after timestamps
are staged for reproducible trace filtering. Raw failures use fixed error codes.

Review corrections require every ingestion, due-coverage and live-arrival field
before declaring evidence complete. Explicit null histogram bounds or maximum
receipt delay retain their unavailable meaning; absent/nonnumeric counts fail
completeness. Failed performance values are preserved rather than filtered out.
Timeout cleanup kills remaining members of its owned process group even when the
direct child exits first, so a TERM-ignoring descendant cannot outlive that command
and interfere with evidence capture. Both cases have focused regressions.

Trace export allows at most 256 requests, 16 MiB per response, 128 MiB sanitized
output and 500,000 unique spans. It divides capped 10,000-row pages, deduplicates
by trace/span IDs, and stops initiating work after 120 seconds (an in-flight read
has at most the existing ten-second socket wait). Export timestamps and queried
range are recorded. `complete` means **query pagination completed**, not that all
asynchronously exported OTLP spans have arrived. `ingestionLagNotEstablished:true`
and an explicit no-flush/drain-barrier limitation preserve that evidence gap.

Setup is bounded to 1,800 seconds; seed wrapper to 1,860 seconds (existing
60-second onboarding plus 1,800-second seed test); observer wrapper to 390 seconds
(existing 300-second Playwright workload and 370-second observer timeout plus
sampler cleanup). App restart/readiness and final teardown each have bounded
commands. No underlying test timeout changes. The primary's CI outer job deadline
must leave room for build/setup, seed, evidence export and cleanup.

All direct Compose calls receive the same fixed E2E port environment exported by
`scripts/e2e.sh`; a child shell's exports cannot configure its parent. Verification
after restart/readiness refuses an app recreation that lost cpuset before seeding.
Since the existing teardown script tolerates Compose failures, cleanup additionally
checks that no running **or stopped** E2E/owned containers remain. Inspection errors
fail cleanup. An earlier seed/workload exit code remains primary, with cleanup
codes recorded separately.
