# F4-T57: Manage maintenance lifecycle in the browser

- Status: review
- Governing contracts: [SPEC-0016](../specs/0016-maintenance-exclusions.md)
  and [F4-T53](F4-T53.md)
- Implementation plan: [0046](../plans/0046-maintenance-management.md)
- Dependency: [F4-T56](F4-T56.md)
- Worktree: `.worktrees/maintenance-lifecycle` on `codex/maintenance-browser-lifecycle`

Expose cancellation before the window starts and prospective early end while
the window is active. The administrative correction lives in a separate
disclosure with a consequence confirmation. Withdrawing removes this
window's exclusion from both successful and failed events. Other
maintenance exclusions still apply. Historical revisions remain available.

Each write uses the record's strong ETag and an idempotency key. A stale write
keeps the reason and requested change in the dialog. The operator can load the
latest revision and explicitly confirm the change. A retry after an uncertain
response preserves the original key while the request stays unchanged.

The isolated HTTPS/PostgreSQL browser journey passed in 4.0 seconds, with 7.1
seconds including onboarding. It exercises exact early-end bounds, successful
administrative correction, prior revision reads, and cancellation after a
concurrent revision with the reason retained. See the
[deployed correction dialog](../design/mocks/maintenance/production/maintenance-historical-correction-dark.png).
The alternate-role browser journey and seeded-fleet timing are separate checks.

The lifecycle follow-up preserves a draft when its window crosses a boundary.
A fresh server-adjusted time and the latest reviewed revision gate submission,
and editing the relevant field clears its local validation error. Escape
closes the focused calendar while the parent confirmation keeps its draft.
An accepted mutation cancels any older in-flight detail read. The 21 focused
component tests and TypeScript check passed. The deployed journey used calendar
Escape and selected the shared picker's displayed date before confirming the
early end. Both deployed checks passed in 10.1 seconds of Playwright time.

An uncertain save can be checked using the latest revision in the same
confirmation. That read updates the detail and its timer, shows the latest
affected SLOs, and preserves the draft. Revision reads are bounded and
cancel when the confirmation closes. Closing an expired action restores
focus to the detail heading. Early end accepts seconds for aligned shorter
cadences.
