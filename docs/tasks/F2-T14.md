## Outcome and non-goals

Register agents using the current administrator session through UI/API/CLI,
without repeated password entry. Diagnose registration failures and supply
useful recovery while preserving uncertain-outcome and one-time token semantics.
Application navigation and collector ownership are separate tasks. Credential
lifecycle operations retain existing reauthentication behavior.

## Required context

Read AGENTS.md, ways of working, testing strategy, ADR-0019 and the governing
specs. F2-T03, F2-T06, F2-T08 and F2-T11 document the earlier implementation;
ADR-0019 supersedes their password requirement for registration only.

## Interfaces and edit scope

- Remove registration `current_password` from OpenAPI and regenerate clients;
  remove the UI field and CLI create password-file requirement. Lifecycle inputs
  remain unchanged. Reject obsolete unknown input fields consistently with the
  strict API; document the changed CLI usage.
- Add an explicitly session-based registration authorization path. Do not make
  `ProveAdministrator` accept an empty password for other operations. Reuse
  current session/identity checks and transaction authority checks; no synthetic
  reusable password proof or weakened storage authorization.
- Preserve bounded requests, auditing, receipt keys, one-time output and token
  secrecy. Validated unavailable responses and transport/response failures must
  retain useful safe cause information without promising non-commit.
- Keep recovery user-facing: registration not confirmed, observed cause, and
  deliberate retry with the retained request. Do not dump implementation jargon
  or raw server responses. Qualify stale/empty list data while a create is pending.
- Edit registration/authentication service, relevant storage authorization,
  HTTP/API/generated clients, CLI, web registration/client, acceptance harness
  and their tests/docs. No broad unrelated refactoring or new dependencies.

## Acceptance and expected cases

1. Real browser registration succeeds against HTTPS/PostgreSQL, issues one token,
   persists one agent, survives reload and has no password field. CLI parity uses
   the same service and no extra password input.
2. Missing/revoked/expired/restricted/nonadmin authority and CSRF/origin failures
   remain denied. Verify authorization again on receipt replay and under storage
   locks, including concurrent authority invalidation.
3. Response loss after a committed registration remains recoverable using the
   same key, returning no token on replay and creating no duplicate.
4. Unavailable service, disconnected backend and invalid response produce
   distinguishable safe feedback and no automatic POST retry. Existing lifecycle
   authentication and unknown-outcome handling remain correct.
5. Record whether the reported baseline failure was reproduced and its evidence;
   improved copy alone does not establish that the reported failure is fixed.
