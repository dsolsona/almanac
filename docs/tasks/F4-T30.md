## Outcome and implementation scope

Migration 0056 and SQLC sources persist policies/revisions, due cursors, fenced
claims, unique evaluations, occurrences, transitions and exact range records.
Backend operations use existing bounded Runtime pools. Stop/restart cannot lose
due work or duplicate an occurrence; pending preserves the original boundary.
Policies sharing an SLO remain independent. Keep one feature candidate through
API/UI integration, not a PR per internal layer. Production activation stays gated.

Registration receives explicit first boundary and validated limits; claims receive
explicit tick/lease/batch inputs. No public defaults are invented. Internal
registration is not a public management entry point; later public commands enforce
session/role, expected versions, audit and replay receipts.

Claims use indexed SKIP LOCKED and least-recent dispatch, once per policy per tick.
Commit locks follow SLI→SLO→exclusion→policy→cursor→occurrence; validate meanings,
source/exclusion generations, canonical calculation string, epoch/token/deadline
and expected boundary. Missing source rows are fenced by the held SLI authority
lock, conflicting with first ingestion; existing source rows are locked explicitly.
Do not insert invalid generation-zero placeholders. Persist evidence, lifecycle and cursor together.
Re-reduce against latest locked acknowledgement. No computation holds a claim
transaction. Record repeated cutoffs, administrative cancellation and horizon gaps
explicitly. Same-facts maintenance comparison is part of adapter admission.
