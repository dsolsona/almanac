## Outcome and acceptance

Declare the full later-backfill validity interval before seeding only one day of
observations. Record the changed initial missing coverage and fixture version.
Fail before workload mutations if any planned range begins before the actual
measurement or SLO validity bound, is reversed, or is not cadence aligned.

`ALERT_CALCULATION_MODE` selects `paired` (default), `baseline-only`, or
`candidate-only`. Unknown values fail before setup. Single modes must not run the
other calculation or the raw oracle. Profiles/results distinguish their actual
work and explicitly withhold an equivalence claim. Paired mode retains its existing
exact comparison, alternating order and workload. All modes preserve the same
ingestion, due-interval, API and browser gates and preserve every failure.

The operator starts each mode with a fresh isolated disk-backed seed, then runs
that mode once. Previously measured fixtures are rejected. The operator's own
stack, credentials and preview remain untouched. No UI behavior changes.

The corrected fixture validates calculation eligibility. Historical observations
still enter through direct SQL with fixture provenance, bypassing historical
grants, agent backfill buffering and ingestion/admission priority. Live collection
uses the real agent. This task makes no historical-protocol acceptance claim.
