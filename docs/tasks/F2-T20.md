## Outcome and boundaries

Administrators can manage assigned Prometheus datasources, including explicit
secret actions, through API, CLI and UI. Administrators can run unsaved connection
tests; Editors and Administrators can run saved-source PromQL previews. Both execute
only on the assigned connected agent. Diagnostic results are bounded, correlated,
cancelable and never enter production ingestion.

Do not add SLI definitions, scheduled/live queries, production observations,
backfill or another provider. Do not let the backend contact a datasource. Preserve
preview 5198. Keep this one integrated increment across storage, API, protocol/agent,
UI and CLI; no commits, pushes, PRs or Crit.

## Interface baseline

Build on the connected-agent and source-secret adapter contracts in
[F2-T17](F2-T17.md), [F2-T18](F2-T18.md),
[SPEC-0002](../specs/0002-agent-behavior.md),
[SPEC-0009](../specs/0009-agent-protocol-and-ownership.md),
[SPEC-0010](../specs/0010-api-and-cli.md),
[SPEC-0015](../specs/0015-datasource-providers.md), and
[ADR-0017](../adr/0017-recoverable-secret-encryption.md). Stable resource IDs, names,
`display_name`, canonical decimal-string versions/ETags and timestamps; provider
`prometheus`, configuration format `prometheus-http-v1`; HTTP(S) endpoint without
userinfo/fragment; polling default 60s/minimum 15s; fixed 60s settling delay;
verified TLS by default, explicit visible insecure flag, optional CA; auth `none`,
`basic`, or `bearer`. Redacted responses expose only secret-presence flags. Create
and update require explicit per-field `replace`/`retain`/`clear` secret actions;
secrets remain Tink envelopes bound to installation, datasource, field and positive
secret revision. Source settings and assignment advance datasource and agent config
revisions; diagnostics and health do not.

Advertise only `connection_test` and `query_preview` for this increment, not
`live_query`. Agents must revalidate capability, assignment, session generation,
deadline and destination policy. Diagnostics have 30s end-to-end and 20s provider
deadlines, 24h terminal receipts, 256KiB control messages, 64KiB inline and 1MiB
maximum separate HTTPS results. Reject larger payloads. Never allow metadata-service
targets by default; apply allowlists, DNS/redirect revalidation and origin-bound
credentials. Permit private endpoints. Do not implement a generic job framework.

CLI secret input is protected file/stdin only, never flags/positionals. Keep clean JSON stdout/stderr,
stable error codes, redaction and explicit cancellation/deadline behavior.

The public route inventory is `GET /api/v1/providers?agent_id`, paged
`GET /api/v1/datasources?limit&cursor`, `POST /api/v1/datasources`,
`GET /api/v1/datasources/{datasource_id}`, `PUT /api/v1/datasources/{datasource_id}`
with strong `If-Match`, `POST /api/v1/datasources/connection-tests`,
`POST /api/v1/datasources/{datasource_id}/query-previews`,
`GET /api/v1/diagnostics/{diagnostic_id}`, and
`POST /api/v1/diagnostics/{diagnostic_id}/cancel`. Diagnostic creation is `202` with
`Location`; diagnostic reads and cancellation never extend a fixed 30-second
end-to-end deadline. Admins own writes and unsaved tests; Editors and Admins may
preview saved sources; current authorization is rechecked for every operation.
Create uses one idempotency key; update uses the resource-specific ETag.

CLI parity uses `datasources list|get|create|update`, `datasources test`,
`slis test`, and `providers list`. JSON secret input comes from a protected file or
stdin. Datasource responses never contain plaintext. Diagnostic input/output is
strictly bounded and preview output is never presented as production observation
data.
