## Interfaces and edit scope

The coordinator reviewed the additive OpenAPI projection/history contract on
2026-10-29; generation passed before UI handoff. Existing definitions and evaluation
routes remain compatible. New operations are `GET /api/v1/slos/overview` and
`GET /api/v1/slos/{slo_id}/operational`, with exact schemas in `api/openapi.yaml`.
Overview supplies backend-owned global urgency order/counts and a frozen paginated
projection bound to actor/session/role/filters/limit, including signed next and
previous cursors so returning to page one reuses the same snapshot. Detail supplies independent
current and 1 h/6 h summaries plus attainment, rolling-budget and selected-burn
history, exact represented sample values and authorized definition context.

Snapshot expiry is two minutes; admission allows four live per actor/session and
64 installation-wide. Resource bounds are 10,000 matching definitions, 16 MiB stored
projection payload and 2,500,000 actual canonical coverage rows across distinct
SLI/revision streams per request. These are explicit resource errors, never hidden
truncation or a 100-SLO product limit. History supports aligned ranges up to 365 days,
with at most 1,500 samples per series and disclosed first/last/min/max reduction
and gaps; overview sparklines retain at most 120 samples across 30 buckets.
No per-point SQL query or expansion of every absent cadence tick is permitted.
Numeric strings and urgency comparisons retain the accepted exact-arithmetic policy.

Backend and UI/client workers use separate isolated worktrees at `fb648c3`; generated
types transferred before UI implementation. Any wire change requires coordinator
review and explicit transfer to both consumers before further implementation.

Backend owns OpenAPI/generation, canonical calculation and storage/query changes,
HTTP and backend tests. UI/client owns `web/src/slos/`, reviewed shared UI/chart
extensions and catalogue, generated-contract consumers, CLI and user journeys.
Coordinator settles command dispatch ownership and disjoint files before dispatch.
No collector behavior changes or new source queries are required for SLO reads.

## Acceptance and expected cases

- At target 99%, good 9850/10000 yields allowed 100, remaining -50 events,
  remaining fraction -0.5 and full-window burn 1.5; meter drawing does not clamp text.
- At target 99%, a complete 1 h 990/1000 gives burn 1; complete 6 h 5990/6000
  gives burn 1/6 (serialized 0.166666666667). Never substitute one window for another.
- At exact target, performance remains met with zero budget remaining. Test every
  accepted urgency boundary independently of display rounding and incomplete quality.
- Verify zero traffic, known-empty, missing, expiry, pre-validity, cadence mismatch,
  definition boundaries and late observations. Rolling-budget history is evaluated
  at each point; interval budget is not a substitute for objective-window budget.
- Test filters across page boundaries, snapshot/cursor expiry, stable ties, read
  failures, cancellation, role restrictions and session expiry. One request per row
  from the browser is not an accepted list projection.
- Inspect the real reference journey early; preserve original first failures and
  investigate them rather than rerunning to claim unexplained success.
