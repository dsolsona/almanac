## Interfaces and behavior

Identity provides `NewAgentToken() (AgentToken, error)`,
`AgentTokenVerifier(string) (string, [32]byte, error)` and
`VerifyAgentToken(token, expectedID string, verifier [32]byte) bool`.
`AgentToken` has ID, Token and Verifier fields; the latter two exclude JSON output.
The wire format is `almanac_agent_v1_<canonical UUID>.<43-character raw-base64url secret>`.
The public UUID and 32 random secret bytes are independent. SHA256 covers decoded
secret bytes. Parsing bounds length and rejects wrong role/version, noncanonical
UUID or base64, whitespace, padding and malformed input. Authentication compares
the verifier in constant time. Errors never contain supplied credentials.
Use the existing pinned UUID dependency if appropriate to the installed toolchain;
generation must return errors instead of panicking. No dependency version changes.

Add `authentication.Service.ProveAdministrator(ctx, AdministratorProofInput)`
returning the existing `storage.AgentAdminProof`. Input contains session secret,
current password (both excluded from JSON), source address and request ID.
Reuse bounded password verification and shared login throttling. Require a current,
unrestricted administrator session and bind proof to the password-verified identity
snapshot. Do not issue a session, hold database locks during password hashing, or
publish a reusable proof token. Storage rechecks authority under its own locks.

`agentmanagement.New(databaseURL, authService, now)` constructs trusted dependencies
for `Service.Create(ctx, CreateInput) (Issuance, error)`. Input includes proof inputs,
idempotency key, name, display name and lifetime. Issuance contains safe storage
creation metadata and a JSON-excluded Token. The authentication and management
services must use the same database and coherent clock; composition is trusted,
never caller supplied. Mutable test clocks must be concurrency safe across services.
Bound creation to 30 seconds, prove authority, generate a candidate, then call
guarded storage creation. Return the token only after a fresh successful commit
whose credential ID matches the candidate. Replay returns metadata with no token.
Every error, including uncertain commit outcome, returns zero issuance. Preserve
safe sentinel and throttling errors for subsequent HTTP mapping.

## Acceptance and verification

- Unit tests cover strict token grammar, fixed verifier vectors, wrong ID/secret,
  role separation and JSON exclusions without printing secrets.
- Real PostgreSQL/password tests prove valid administrator issuance and matching
  persisted verifier, fresh authorization on replay with no token, body conflicts,
  wrong password, invalid session, restricted users and other roles.
- Shared throttling prevents proof work and preserves retry information.
- Injected audit and receipt failures produce no agent, credential or receipt and
  no returned token. Authentication admission and valid session touch effects are
  allowed; they are not successful agent writes.
- The coordinator runs full integrated and real database gates, including existing
  browser journeys. Worker checks cannot substitute for these gates.
