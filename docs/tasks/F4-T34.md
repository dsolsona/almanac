## Outcome and scope

Authenticated catalogue reads return paginated alerts with policy and SLO names
separate, latest committed condition evidence, global filtered totals, optional
SLO grouping and processing lag distinct from lifecycle. Filter active/history,
state, severity, SLO, service and literal search in PostgreSQL. Group counts cover
the entire filtered relation, not the page. Support newest/severity ordering with
stable ID ties; grouping adds a stable SLO key. Cursors bind filter/group/sort
identity, permit page-size changes and do not promise a frozen cross-page snapshot.

Read transitions in sequence order and exact gap/cancellation ranges, preserving
actor/cause/request and separate effective/detection clocks. Read per-policy
processing status without calculating windows. No N+1 counts, live recalculation,
public default choices or production registration. Explicit page sizes stay
within the existing management ceiling of 200; UI callers use 10/20.
Include saved-policy pagination and enabled/severity/SLO/literal filters so a
new policy is visible before any firing occurrence exists.

## Acceptance and verification

- More than one page, identical timestamps and different SLOs: no repeats/omissions
  on an unchanged dataset; global filtered/group totals remain complete.
- SLOs may share an SLI; grouping never groups by source or mutates state.
- Literal `%`/`_` search is not SQL wildcard search. Cursor/filter mismatch and
  malformed cursors fail; search/filter does not leak unauthorized resources.
- Row evidence explains matching/unavailable conditions with the same immutable
  evaluation identity as detail. Last state and pending processing remain distinct.
- Transition sequence pages and explicit ranges never imply gaps were healthy.
- Viewer reads; invalid/restricted/revoked sessions cannot read. No credentials
  or datasource queries appear in records.
- Adapt affected upgrade fixture for any new view without broad schema deletion.
