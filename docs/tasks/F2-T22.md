## Outcome and non-goals

An authenticated operator creates a Prometheus count-based SLI using an existing
datasource, the assigned remote agent collects canonical intervals, and UI/API/CLI
show persisted exact good/total values and truthful collection health.
Deliver one usable vertical increment, including tests and actual deployment evidence.
Direct-producer identities/ingestion remain a subsequent F2 increment. Do not claim
F2 completion. SLO calculations, OpenSLO import, historical jobs/repair, new providers,
and release-wide restore acceptance are outside this task.

The first native flow supports good/total interval-count queries. Other count
conversion modes and typed measurement kinds must be rejected explicitly until
implemented, never silently interpreted as interval counts. Preserve their future
representation and the accepted provider contract. Ordinary metadata changes preserve
measurement meaning. Do not expose measurement edits or datasource cadence changes
that can silently reinterpret active SLI history; either implement accepted prospective
revision transitions or reject the affected operation with an actionable conflict.

## Acceptance and expected cases

- Create `Request success` / `request-success`, choose the existing Prometheus
  datasource, enter explicit interval-count queries producing 99 good / 100 total.
  Show the saved revision and scheduled activation. Collection executes only on
  the assigned agent, at datasource cadence, after source settling delay.
- Each evaluation at interval end e represents [e-d,e). Minimum cadence 15 seconds,
  default cadence/settling 60 seconds, as in SPEC-0015. One scheduled live interval
  per execution; missed history remains missing, not an implicit catch-up rewrite.
- Persist and display exact decimal counts without floating-point loss; use
  numeric(38,12), decimal-string wire values, UTC microseconds and strict precision.
  Reject 101/100, negative/nonfinite/overprecision values and misaligned intervals.
  Good/total components must align; multiple series require explicit aggregation.
- Distinguish 0/0 zero traffic, explicit complete empty coverage, incomplete/missing
  components, failed queries, unacknowledged delivery and missing executions. Never
  synthesize zeros or label heartbeat reachability as healthy collection.
- Same delivery/content returns its durable outcome after current authorization;
  changed delivery content conflicts. Another delivery with identical canonical
  values is duplicate; 98/100 for existing 99/100 conflicts and preserves 99/100.
  Per-item observation/coverage/receipt/dirty-work writes are atomic, including a
  two-item batch where one is invalid. Crash/lost response after commit is safe.
- Enforce agent, assignment, measurement revision, configuration and lease bounds
  under stable lock ordering. Test revoked credentials, copied-token ownership,
  stale/fenced generations, wrong SLI, invalid effective bounds and replay expiry.
  Rotation of the same still-authorized identity does not change producer identity.
- Use monthly partitioned observations/coverage and independent canonical uniqueness,
  400-day retention cutoff and seven-day delivery replay eligibility. Prepare current
  admitted partitions server-side; missing partitions fail visibly. No cleanup process
  may silently erase replay safety. This is not full retention/restore acceptance.
- Live collection remains independent of heartbeat/diagnostic work. Bound query
  concurrency (8 agent/4 datasource), timeouts by remaining execution authority,
  live submissions (2), item/request sizes (1 MiB/4 MiB; 1,000 observations/item),
  and live result memory (64 MiB including in-flight serialization and metadata).
  Oldest-result eviction is observable and does not stop collection. Stable delivery
  IDs survive retries; late acknowledgements cannot remove newer ring contents.
- Disconnect continues only within the existing one-hour execution lease; expiry
  cancels queries. Reconnect reconciles before new dispatch; buffered authorized
  results keep original intervals. Cancellation and shutdown are bounded.
- UI list/create/detail/history and CLI parity use the actual API. Invalid fields
  are actionable, stale edits conflict, loading/errors are visible without blanking
  the shell, history/reload and keyboard focus work, exact values are literal text.
- Early real journey: actual TLS backend, PostgreSQL, executable agent and a bounded
  deterministic provider fixture, followed by real browser creation/readback.
  Final acceptance repeats the flow through isolated normal Compose deployment,
  preserving the maintainer deployment/data. Inspect light/dark and mobile pages.
