## Outcome and scope

Provide the bounded password-verifier and session-secret operations needed by
the upcoming local bootstrap/login service. They are internal building blocks,
not a login endpoint or a claim that onboarding works. Keep database migrations,
HTTP/cookie/CSRF behavior, user administration and server modes unchanged.
Common-password rejection belongs to the subsequent application policy and must
exist before login/onboarding delivery; text validation here is explicitly only
the accepted Unicode/length policy. Do not add a token/role framework, encryption
adapter, configurable algorithm registry or general credential abstraction.

Use `golang.org/x/crypto/argon2` v0.58.0, checked against the
[Go package documentation](https://pkg.go.dev/golang.org/x/crypto@v0.58.0/argon2).
This implements the already accepted Argon2id choice; the recoverable-secret
library decision remains deferred and is not needed for password verifiers.
The accepted 19 MiB / two iterations / one lane floor matches the
[OWASP guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
Record this as a tested initial cost, not a universal production recommendation.

## Password behavior

- Creation accepts valid UTF-8 containing 15–128 Unicode code points inclusive.
  Reject invalid UTF-8 and more than 512 bytes before expensive work. Do not trim,
  truncate, normalize Unicode or impose composition rules. Spaces are significant.
  Validation errors never contain the password, an excerpt or its encoded bytes.
- Hash uses Argon2id version19, memory19456 KiB, iterations2, parallelism1,
  a fresh cryptographically random 16-byte salt and a 32-byte derived key.
  Encode exactly `$argon2id$v=19$m=19456,t=2,p=1$SALT$KEY`, with canonical
  unpadded standard base64 salt/key. Persisted verifiers contain no plaintext.
- Verify accepts only that exact initial parameter/version encoding, bounded
  before splitting or decoding. Reject oversized input, extra fields, changed
  work factors, invalid/noncanonical base64, wrong salt/key lengths and unsupported
  algorithms before invoking Argon2. Do not let stored data allocate arbitrary
  memory or CPU work. Future cost upgrades require explicit parser changes and
  evidence; no configurable cost is introduced here.
- Valid encoded verifiers with a wrong password return false,nil. Verification
  does not enforce the creation minimum: short/empty candidate passwords still
  perform the same fixed derivation for future non-enumerating login behavior.
  Invalid UTF-8 or candidate input beyond 128 code points / 512 bytes returns
  false,ErrInvalidPassword without deriving. Compare derived keys in constant time.
- Permit at most two concurrent derivations per shared hasher instance (38 MiB
  Argon2 work memory, plus runtime overhead). Admission waits on the caller's
  context and returns cancellation/deadline errors; it must not spawn a goroutine
  to hide a still-running hash after cancellation. Check cancellation before work
  and after derivation. The library computation itself is finite but cannot be
  interrupted mid-call; document that limit. Release slots on every return path.
- No global mutable entropy source or test-only production bypass. Use the
  standard cryptographic random source, not math/rand or time-derived salts.

## Session-secret behavior

Generate 32 random bytes and return their canonical unpadded URL-safe base64
encoding (43 characters). The verifier is SHA-256 of the decoded 32 bytes.
The future store persists the verifier only; issuance returns the secret once.
SessionSecretVerifier rejects padding, whitespace/newlines, alternate spellings,
wrong size, invalid alphabet and oversized input without logging it. Do not add
machine-token prefixes, public IDs, epoch fields, expiry or persistence to this
stateless session helper. The future service owns those session lifecycle checks.

## Acceptance and fast checks

1. Add failing tests for 14/15/128/129-code-point boundaries, four-byte Unicode,
   invalid UTF-8, significant leading/trailing spaces and distinct Unicode forms.
   Validated text must arrive at hashing unchanged.
2. Prove hash/verify round trip, wrong/short/empty candidate rejection as false,
   fresh salts for repeated hashing, exact initial encoding, malformed/oversized
   stored verifiers, strict base64 and safe errors. Never lower Argon2 parameters
   just to speed tests.
3. Prove pre-cancelled work does not derive, queued work respects cancellation,
   and a slot is available after failure/cancellation. Use bounded contexts and
   explicit coordination; no unbounded waits or sleep-based synchronization.
4. Prove session entropy size/encoding and digest with an independently calculated
   known-byte SHA-256 vector, issuance/verifier round trip and malformed-input cases.
