## Outcome and non-goals

Observations live in `almanac_sli_observations` with the primary key in access
order and no stored interval end; the ingestion function marks the source
generation, dirty hour and extrema (or repair) cursor explicitly; both triggers
and the two old tables are gone. No change to any value shown to a user.

## Interfaces and edit scope

- Staged upgrade, since the runner commits each migration with its history
  record in one transaction: a first migration creates the table, partitions for
  every existing month, the partial observed index and the all-outcome
  `(sli_id, interval_start)` index, and fences legacy writes; the copy of
  coverage joined to values runs partition by partition in bounded committed
  batches with per-partition count and value verification, resumable after
  interruption; a final step drops the old tables, both triggers and their
  indexes after verification. Test interruption and resumption through the
  upgrade command.
- Document the SPEC-0013 maintenance sequence: backup, backend drain/stop,
  explicit upgrade (rerun after interruption), compatible backend restart. The
  copy fence persists across interruption; ingestion remains unavailable until
  upgrade finishes. Finite agent buffers and leases can leave missing intervals;
  preserve their quality state and document best-effort repair.
- Observation identity moves to the delivery receipt; the SLI list, observation
  history and duplicate responses join it from there, and receipts are retained
  for the life of their observation.
- `IngestAgentObservation`: only successful canonical acceptance advances the
  source generation, upserts the dirty hour and widens cursors in its transaction.
  Allocate the generation before the canonical insert to avoid a second row
  write; a failed insert rolls the allocation back. Duplicates, conflicts and
  failed/incomplete attempts mark no derived work. Attempts retain their row and receipt.
- `prepareSliPartitions`: one table. Retention partition handling: one table.
- Every query rewritten against the new table; `interval_end` computed from the
  cadence where needed.
- Allowed paths: `internal/storage/**`, generated sources and existing CLI/perf
  raw-data fixtures that consume the replaced tables; no product UI changes.

## Acceptance and expected cases

- Accepting an observation produces exactly the generation, dirty-hour and
  cursor effects the triggers produced, verified by comparing table state before
  and after against the pre-change build on the same fixture.
- A duplicate or conflicting delivery changes no canonical row and marks no
  derived work; a duplicate with a new delivery ID still records its receipt.
- Failed and incomplete executions leave source generations, dirty hours and
  extrema cursors unchanged while retaining their attempt and receipt records.
- All existing integration tests on ingestion, aggregates and retention pass.
- Migration rehearsal on a copy of the preview database: row counts and values
  match per partition; current statuses match; old tables are gone.
- A revision with 200,000 rows migrates in bounded transactions under the 5 s
  statement timeout; killing the upgrade mid-copy and rerunning it completes
  without duplicate rows.
- `EXPLAIN` of the SLI list's latest-interval lookup on the merged tree uses an
  index and does not sort the SLI's retained history.
