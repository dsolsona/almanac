## User acceptance

- SLI/SLO lists become usable in <1,000 ms, preferably <=500 ms.
- SLO detail/range/burn actions finish in <500 ms.
- Exercise 10, 100 and 1,000 SLOs, one year of history and ten concurrent users.
- UI pages default to 20 records, offer 10, and never append unbounded rows.
- Normal navigation reads maintained results and bounded edges without graph-job polling.
- Exact counts, extrema, gaps, urgency and immutable table pages remain accurate.
- One unavailable objective cannot block unrelated rows or appear falsely Healthy.
- Preserve live collection, authorization, restart/shutdown and the operator preview.
- Prove rendered journeys and VictoriaTraces; API-only timings and suite counts are insufficient.

## Implemented continuation

Detail navigation reuses its validated definition response's server clock with a
monotonic elapsed-time anchor, avoiding a second serial request. SLI and SLO lists
use 20/10-row controls. SLI pages replace rows, preserve cursor navigation and
reset cursors on filter/size changes. Shared controls and table geometry remain.

SLO snapshots store metadata and immutable content-digest references. Counts,
ordering and filters cover the full matching scope; only requested page payloads
are decoded. Publication archives validated payloads atomically, preserving old
cursor values across current/sparkline updates. Pending, source-failed and
calculation-failed rows disclose unavailable values with existing Watch
classification, without fabricated numbers or current success.

Retained points persist interval attainment, rolling budget and supported burns.
Version/lease-fenced maintenance builds stable UTC-hour/day tiles, preserving
exact extrema and quality transitions. Durable cursors bootstrap and correct
historical endpoints independently of current publication. Canonical coverage
invalidation commits with ingestion; clock-driven changes have separate work
versions. Dependency waits and serialization conflicts preserve failure budgets.
Late repair preserves a stored window's known prefix after raw expiry, adding
only intervals newer than that point's committed source generation. The existing
insert-only ingestion trigger records per-interval generations; duplicate no-op
inserts do not advance them. Exact decimal totals and coverage are recomputed
through the shared evaluator. Migration/index cost and real database behavior
remain to be measured.

A detail response-cache miss composes retained tiles and bounded exact edges
directly, then pins an immutable response for table pagination. Shorter ranges
use hourly tiles, longer ranges daily tiles. Boundary fallback is bounded; no
normal detail/list read admits graph jobs. Background overview discovery uses
the existing admission caps and retained series. Explicit legacy job failures
remain inspectable and cannot block maintained detail results.

Historical edges now read durable endpoints rather than recomputing their totals
against today's raw retention cutoff. Expired regions render explicitly, without
waiting for deleted tiles. Reads cap transferred and decoded tile/edge payloads
at 20 MiB per detail composition. Tile and repair work appear in the existing
authenticated preparation diagnostics, with revision/lease-fenced finite retries
and atomic audit events. Exhausted source dependencies retain a distinct reason.

Snapshot/archive cleanup has an independent runtime-owned schedule sharing the
existing two-active-query derived pool, bounded cancellation and joined shutdown.
Removed the unused interval-write queue, uncalled single-range aggregate worker,
and obsolete all-row overview loader with their exclusive generated queries.

The logical canonical retention constant, currentness checks, queue keys,
reference scope and metrics now agree on 365 days. The boundary regression uses
literal 365-day expectations across a leap day. Read-only partition impact
preview validates actual UTC monthly bounds/names, rejects partial/unsupported
partitions, reports physical bytes and labels optional row estimates honestly.
It proposes value partitions before their referenced coverage. A staged worker
commits impact previews separately, then revalidates relation identities/bounds
and admitted-work dependencies before transactional removal without CASCADE.
It has finite failure budgets and audit outcomes. Runtime maintenance now
discovers scopes each minute and resumes bounded application/cleanup batches.
Expired source/history work receives a fenced, nonretryable outcome; active
leases block deletion. Calculated cleanup caps each table at 1,000 rows per
transaction, saves cumulative affected counts and yields before scanning points
while a full batch of prerequisite work remains. Monthly canonical removal and
calculated cleanup have separate durable checkpoints. Hourly partition preparation
keeps ingestion ready across month boundaries without another user action.
Real PostgreSQL late-repair/retention and live-isolation evidence remain outstanding.
No operator observations have been deleted.

The normal Compose telemetry check enforces rendered page-load budgets and rejects
preparation responses during normal navigation, after retaining connected
VictoriaTraces evidence. The controlled browser check uses <500 ms for detail
loads and range/burn completion and checks every measured load. Normal-container
execution still fails page speed; the connected traces are diagnostic evidence.

Embedded JS/CSS/HTML now use cached gzip representations created once at startup,
with negotiation, byte ranges, HEAD and immutable asset caching preserved. Public
route modules start loading during session checks; protected data remains gated
by authorization. Chart initialization draws once, and the initial unchanged-size
notification does not redraw it. Data, theme and actual size changes still update
the chart. These changes require fresh rendered latency evidence.

The controlled workload now defines independent 10/100/1,000-SLI/SLO fleets,
365-day retention and 20-row pages. It separates explicit import/recovery
maintenance from single-attempt normal visits, counts first-request latency,
rejects preparation/admission responses under load and exercises both burn

Migrations 0024–0033 implement retained points, tiles/work, repair cursors, response
