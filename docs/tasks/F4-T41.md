## Outcome

`latest_receipt_at` is the maximum receipt over observed and known-empty
contributions, or absent. Failed/incomplete receipts never supply it. Correct
new raw/hour/batch reads, quarantine untrusted legacy receipt metadata, and
repair existing hours in bounded background work. Preserve good/total,
observed/empty/zero counts, coverage, freshness, burn, source generations and
retained numeric marks. Never rebuild expired measurements to repair metadata.

The existing partial investigation in `.worktrees/canonical-receipt-freshness`
is evidence only. Its three predicate changes fail on all-failed hours because
the aggregate column is non-nullable. Do not merge that partial patch.

## Schema, SQL and repair protocol

- Migration 0061 makes hourly `latest_receipt_at` nullable. Add nullable
  `receipt_source_generation bigint` and `certified_receipt_at timestamptz`.
  A trusted stored receipt requires the certificate generation to equal the
  aggregate's source generation and its certified value to equal the stored
  latest receipt using null-safe comparison. Legacy rows have no certificate.
- Both new aggregate publication and repair write that certificate atomically.
  An older writer updating only old columns invalidates it whenever source
  generation or receipt changes. A version flag alone is insufficient because
  an old `ON CONFLICT UPDATE` would preserve that flag while changing the receipt.
- Add a partial index ordered by `(hour_start DESC,sli_id,measurement_revision)`
  containing only uncertified/mismatched rows. New correct writes do not enter
  this queue; old writes remain safely untrusted and eligible for repair.
- Restrict raw receipt maxima to observed/known-empty outcomes in single, hour
  publication and retained batch queries. Do not change count predicates.
- Hour contributions never expose an uncertified receipt. If a window includes
  an eligible population with unknown receipt metadata, return absent for its
  maximum rather than presenting a known lower bound as the actual maximum.
  A no-eligible-population hour does not contaminate another known contribution.
- SQL interfaces: bounded `ListLegacyReceiptHours`; shared SLI authority lock;
  `LockLegacyReceiptHour` with `FOR UPDATE SKIP LOCKED`; one-hour raw population
  read capped at 3,601 starts; and conditional `UpdateCanonicalReceiptMetadata`
  touching only the receipt/certificate columns under the captured row generation.
  Generated row types are the storage consumer contract. Finalize them before
  the primary writes their caller; regenerate SQLC from source.
- Repair discovers a bounded candidate, locks SLI authority before the aggregate,
  and reads its raw hour in the same transaction. Exact retained populations can
  restore the valid maximum. Absent, partial, over-limit or nonmatching retained
  populations produce an explicitly unknown receipt, never reconstructed counts.
  Cancellation/concurrent publication rolls back or fences the write.
- Keep an unknown result certified as absent; consumers still propagate unknown
  when observed/empty counts are nonzero. It must not remain a permanently
  retried head. Do not touch dirty-hour queues, source generations or numeric data.
- The primary integrates one bounded low-priority repair after normal derived
  work, at most once per second. Input clocks, cancellation and work limits are
  explicit. No extra public configuration, source preparation barrier or page wait.

## Persisted response compatibility

Use private `_receipt_metadata_version: 2` on receipt-owning quality, sample and
extrema-mark objects in newly persisted current/history/extrema/budget/compliance
containers. Local markers survive existing SQL extraction of arrays/value pages;
a root-only marker would not. Retained tiles are currently in-memory consumers. Missing
or unknown markers mean the receipt field is untrusted: suppress only that field
when decoding. Keep all numeric/state/quality/freshness/provenance fields intact.
Do not bump the mathematical calculation version or force a year-wide rebuild.
New private markers must not appear in public typed API responses.

Inventory every persisted path before editing. Current source facts can restore
metadata prospectively; legacy history with expired raw inputs may remain absent.
Preserve immutable stored history and never recalculate old alert decisions.

## Acceptance and verification

- Reproduce observed+failed, empty+incomplete, all-failed and mixed valid rows
  against an independent raw oracle. Exact counts/quality/freshness/burn agree;
  only the previously incorrect receipt changes. Zero traffic still has a valid
  observation receipt; no observation never becomes a successful measurement.
- Fresh and populated 0060→0061 upgrade preserves every numeric value and ledger.
  Existing all-failed hours remain rows with null receipt metadata.
- Legacy canonical/current/history/tile payloads cannot expose a failed receipt.
  Known and unknown hour contributions combine without inventing a maximum.
- An old-column-only writer after certification invalidates trust and re-enters
  the bounded queue. Correct current publication restores trust atomically.
- Repair with expired/partial raw data preserves sentinel historic counts and
  emits unknown; cancellation, concurrent publication and lock contention cannot
  corrupt counts or block normal work. Repeated turns eventually drain a finite
  legacy set; the partial index bounds the selected scan under new traffic.
- Both real API metadata and the normal container journey retain fast usable
  rows/graphs. Match tests to changed behavior; CI owns broad suites. Run no
  capacity/optimization loop or unrelated source edits.
