## Outcome and non-goals

Pixel-parity implementation of approved refined B using real operational values.
No API, schema, calculation-policy, provider or alerting changes. The backend asset-preload declaration follows the new bundled SVG route.

## Interfaces and edit scope

Existing `sloClient.current` / `operational`, their cancellation and validated
response types; shared UI and chart components; detail stylesheet, focused tests,
catalogue, accepted reference and guidance. No generated source changes.

## Acceptance and expected cases

- Signed-in user opens list → SLO detail: compact verdict, integrated budget
  summary/plot, burn, attainment and completed days; disclosures start collapsed.
- Target .999, total 10,000,000 and bad 8,200 give 10,000 allowance, 1,800 left,
  18% remaining and 99.918% attainment. Backend results are authoritative.
- Bad 12,000 preserves −2,000 and −20%; incomplete coverage labels observed-only
  values and unknown performance, independently of freshness and urgency.
- Hover/keyboard/touch expose exact response values/timestamps; gaps have reasons,
  no invented points. Legend matches day blocks in both themes.
- Refresh/range/burn/timezone, rename, browser history, linked SLI and access-denial
  recovery retain existing behavior. No table controls or empty exact section.
- Compare all panel geometry, typography and colors against B at 360/1024/1440 px
  in light/dark. Review controls are not product content.
- Real isolated deployment verifies persisted SLO counts and navigation;
  performance checks measure usable plots, first visits and changed ranges.
