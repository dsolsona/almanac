## Outcome and non-goals

Observations live in `almanac_sli_observations` with cumulative columns kept
current by one cursor per SLI revision, ingestion marks explicitly, and every
existing reader still works because the hourly aggregate rebuild reads the new
table. Extrema rows and the new read path are F9-T03; dropping the aggregate and
point pipeline is F9-T04.

## Interfaces and edit scope

- Migration `0044_observations_cumulative.sql`: create the table, partitions for
  every existing month, the partial observed index, the new revision columns and
  cursor columns; copy from coverage joined to values partition by partition;
  verify counts per partition; seed `cumulative_through` to each revision's
  earliest `interval_start`; drop both old tables, both triggers and their indexes.
  The migration runner's explicit upgrade semantics apply; it must be safe to rerun
  after an interruption (idempotent copy keyed by the primary key).
- `IngestAgentObservation`: one insert into the new table; then the three explicit
  marking steps of SPEC-0020. Extrema cursor marking (step 3) is added here but
  only writes when the cursor table exists; create the cursor table in this
  migration with no consumer, so F9-T03 only adds the worker.
- `prepareSliPartitions`: one table instead of two.
- Cumulative worker in `RunDerived`: claim, recompute chunk, advance, ADR-0034
  retry and temporary-error rules reused from `derived_temporary.go`; stored
  reasons through `derivedFailureReason`.
- `windowTotals(ctx, q, sli, revision, a, b, cadence)` in `derived_evaluation.go`
  implementing SPEC-0020 "Window totals"; `evaluateDerivedWindow` and
  `evaluateDerivedWindows` keep their signatures and call it. Remove the
  hourly-aggregate readiness logic from these two functions; readiness is the
  pending rule of SPEC-0020.
- `RebuildDerivedBatch`, `ReadRetainedLateTotals`, `ListSliObservations` and every
  other query on coverage/values are rewritten against the new table so the point,
  tile and repair pipeline keeps running unchanged until F9-T04.
- Retention: before dropping a partition, copy `cum(partition end)` to the floor
  columns and set `retained_from`; the preview/audit flow is unchanged.
- Diagnostics: `/preparation` lists the cumulative cursor with stage `cumulative`;
  retry resets it. Regenerate API types only if the enum changes
  (`make shell CMD='make generate GENERATE_MODE=api'`).
- Allowed paths: `internal/storage/**`, `internal/sli/**` (if the observation
  struct needs a change), `api/openapi.yaml` for the stage enum, generated sources.

## Acceptance and expected cases

- AC-01 equivalence: for the focused fixture (one SLI at 15 s for 14 days, one at
  60 s for 56 days) and a randomized fixture with gaps, known-empty, zero traffic,
  fractional and 26-digit counts, every window `[a,b)` at every cadence endpoint
  equals the `slo.WindowSweep` result over raw rows; include windows starting
  before `retained_from`, before validity and before the first row.
- Pending rule: a window ending more than 7,200 rows past `cumulative_through`
  is pending; one ending 100 rows past it is exact.
- Late data: inserting an observation 10 days back lowers `cumulative_through`;
  after the worker runs, every later window is correct and `cumulative_generation`
  equals the generation.
- AC-04: duplicate and conflicting deliveries leave generation, cursor and cumulative
  columns unchanged.
- AC-05: kill the worker after claim, after the first chunk commit and before
  acknowledgment; on restart no row is double-counted and the cursor resumes.
- AC-06: run the migration on a copy of the preview database (take it with the
  local stack's own Postgres container, never the live volume); row counts match,
  current statuses for all SLOs match before and after, old tables are gone.
- Chunking: a revision with 200,000 unprocessed rows is processed in at least four
  transactions, each under the 5 s statement timeout.

User acceptance checklist:

- Starting state: `make run` on a copy of the preview data; migration applied.
- Expected: SLI detail, SLO list and SLO detail show the same values as before;
  collection continues; `/preparation` shows the cumulative cursor caught up.
- Invalid input: not applicable.
- Navigation: unchanged.
- Container journey: `make test-e2e`.
