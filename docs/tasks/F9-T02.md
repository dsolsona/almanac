## Outcome and non-goals

Observations live in `almanac_sli_observations` with cumulative columns kept
current by one cursor per SLI revision. Explicit ingestion preserves both legacy
invalidation effects and adds cumulative/extrema work. Existing readers and exact
hourly fallback remain usable independently of cumulative progress. Extrema and
historical baselines are F9-T03; F9-T04 removes only obsolete pipeline structures.

## Acceptance and expected cases

- AC-01 equivalence: for the focused fixture (one SLI at 15 s for 14 days, one at
  60 s for 56 days) and a randomized fixture with gaps, known-empty, zero traffic,
  fractional and 26-digit counts, every window `[a,b)` at every cadence endpoint
  equals the `slo.WindowSweep` result over raw rows; include windows starting
  before `retained_from`, before validity and before the first row.
- Boundary cases: `T=12:00`, unprocessed 12:00/12:01 rows and window
  `[12:01,12:02)` sums only the latter row; also exercise a window straddling T
  and a nonzero floor followed by a gap. Cover null and stale suffix columns.
- Independence: a 100-day-old insertion rewinds the cursor with >7,200 rows
  ahead of it. A current 1 h and 28 d window remain exact through hourly fallback
  before cumulative repair completes, including continuing live ingestion.
- Late data: inserting an observation 10 days back lowers `cumulative_through`;
  after the worker runs, every later window is correct and `cumulative_generation`
  equals the generation.
- AC-11: a late interval in a closed hour updates aggregate dirty generation,
  rewinds an already completed retained repair cursor and increments its version
  atomically. The existing reader rejects its old tile before any worker runs;
  repaired values match independently computed counts. Repeat with rollback.
- AC-04: duplicate and conflicting deliveries leave generation, cursor and cumulative
  columns unchanged.
- AC-05: kill the worker after claim, after the first chunk commit and before
  acknowledgment; on restart no row is double-counted and the cursor resumes.
- AC-06: run the migration on a copy of the preview database (take it with the
  local stack's own Postgres container, never the live volume); row counts match,
  current statuses and old-reader graphs match before/after, both legacy
  invalidation effects remain, and only replaced coverage/value tables are gone.
  Checkpoint/anchor values and observation/receipt times match the source data.
- Chunking: a revision with 200,000 unprocessed rows is processed in at least four
  transactions, each under the 5 s statement timeout.

## Escalation conditions

The copy verification finds a coverage row without values whose outcome is
observed (the ADR-0034 incident state); report the rows instead of inventing
counts. Any missing historical evidence, global-cursor gate on unaffected reads,
legacy tile accepted after late ingestion, duplicate migration version, or case
where cumulative/fallback totals and the independent sweep disagree.
