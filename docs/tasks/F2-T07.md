## Outcome and non-goals

A bounded, cancellable browser client for the existing seven agent management
operations. Screens, auth reconciliation, CLI, runtime connectivity and encryption
implementation are separate tasks. This task alone does not deliver UI acceptance.

## Required context

Read AGENTS.md, ways of working, testing strategy, F2-T06, the linked spec criteria,
the management paths/schemas in `api/openapi.yaml`, generated web types and existing
`web/src/auth/client.ts` with its tests. The accepted HTTP contract governs behavior.

## Interfaces and edit scope

Own `web/src/agents/client.ts` and `web/tests/agents-client.test.tsx` only. Import
generated schema types; do not edit contracts, generated files or auth behavior.
Reuse the existing auth client's bounded transport approach after reviewing it;
local duplication of small private transport helpers is acceptable for this task.

Export `createAgentClient(fetcher = fetch)` with `list`, `get`, `credentials`,
`create`, `rotate`, `revoke`, `disable`; export typed inputs/results and `AgentFailure`.
Reads accept optional AbortSignal; list/history take bounded limit and cursor.
Get returns `{agent, etag}` after validating strong ETag/body ID/version agreement.
Mutations receive current AuthContext, explicit caller-owned idempotency key,
original If-Match for existing resources, typed semantic input and fresh password.
Neither generate keys nor mutate inputs, retry, refresh auth or store secrets.
The screen will own immutable intents, authority and deliberate retry decisions.

Use same-origin credentials/mode, no-store, redirect:error, 30s total deadline and
a 512KiB response cap. This covers 200 records with 256-byte display names even
under worst-case JSON escaping plus bounded metadata; test a maximum page.
GET sends neither CSRF nor synthetic Origin. POST supplies CSRF, exact key/tag and
JSON. Validate path IDs before constructing URLs. Reject pre-aborted requests
without dispatch. Cancellation after mutation dispatch preserves uncertainty.

Runtime-validate DTOs and page bounds, canonical UUIDs, explicit nullable fields,
timestamps and decimal versions/counts within the API's signed-int64 bounds.
Keep decimal strings exact; never convert versions/counts to Number. Validate
IDs across nested results. Do not infer credential liveness from safe history.
Validate fresh/replay issuance against status and token-state combinations:
fresh has issued/false/nonempty token; replay unavailable/true and no token member.
Keep historical receipt versions unchanged. Malformed/truncated mutation success,
transport failure or untrusted server failure is uncertain, not safe rejection.

AgentFailure exposes kind `rejected`, `unavailable` or `uncertain`, fixed safe code
and message, and optional validated Retry-After seconds. Confirmed documented
problem/status combinations may be rejected; invalid bodies are never trusted.
Never expose raw response messages/bodies/password/token in errors. Management
401 does not itself prove logout; caller handles reconciliation. Mutations have
no automatic recovery request. A lost response must produce exactly one dispatch.

## Acceptance and expected cases

- Verify all method/path/header/body shapes against OpenAPI and exact decimal
  values beyond 2^53, including max int64, mismatched ETags and malformed DTOs.
- Check 0/200 row pages, bounded cursors, explicit null fields, response body cap,
  slow-body cancellation/deadline, pre-abort and late responses.
- Exercise fresh and replay token invariants, including forbidden token:null or
  token:empty on replay, malformed success, rejected proof/conflict/throttle,
  unavailable reads and uncertain post-dispatch failures.
- Assert no second request/retry, no input mutation and no secret-bearing errors.
  Tests prove transport/client behavior only; real API/database/browser acceptance
  remains mandatory with the subsequent screen task.
