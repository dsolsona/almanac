## Outcome and contracts

One internal evaluator reads all requested source windows in one repeatable-read
snapshot. Revision zero preserves the existing canonical batch path. Nonzero
revisions use complete immutable compiled masks, canonical whole hours where
fully eligible/excluded, prepared scoped summaries for partial hours, and bounded
raw boundary edges. Exact populations and indexed coverage flow into the shared
covered-totals evaluator. No alert-only arithmetic or whole-window raw fallback.
The current and last-breaching masks use the same present source inputs and both
count against admission. Missing prerequisites remain due, never silently skipped.

No production consumer or worker is registered by this task before equivalence,
actual navigation and the 100/200-policy gates. SPEC-0020's scoped adoption note
remains distinct from permission to implement this unwired path.

## Concrete implementation sequence

1. Build a pure bounded window planner first. Reuse canonical
   `derivedWindowParams`/common cadence-hour boundaries. Merge/deduplicate whole
   source-hour ranges and raw edges across windows before admission. Charge
   distinct source hours before allocating/enumerating them. Caller supplies
   explicit raw-row/fragment/hour budgets; no experimental production defaults.
   Empty batches do no work; malformed/mixed-grid/clock batches and cancellation
   fail explicitly. Preserve each original window's whole-interval boundaries.
2. Read source readiness, hour generations and exact canonical populations in
   bounded indexed batches. Full canonical interior pending/failure semantics
   remain intact; missing data is not successful data. Partial-hour stored values
   require the same source-hour generation and immutable SLO/mask identity.
3. Read each distinct raw edge population once, with an overflow sentinel before
   outcome filtering. Read intersecting compiled union fragments through one
   predecessor and bounded forward seeks; no growing declaration scan. Partition
   whole starts, never prorate a crossing interval. Bound the combined current/
   historical-mask work. Expired source evidence stays unknown/unavailable.
4. Aggregate exact eligible/excluded populations and receipt unknownness. Obtain
   bounded rank certificates through F4-T44, then call the shared evaluator.
   Preserve its validity, retention, full-exclusion, freshness, zero-traffic and
   unknown-excluded-population rules. Do not relabel reused evidence as a new
   computed revision without an F4-T46 proof.
5. Add source/exclusion publication races and pending→retry→correct-result checks.
   Future production adapters must persist preparation requests and preserve
   policy ordering; a private unavailable result is not completed alert work.

## Acceptance and checks

## Evaluator implementation interface

The evaluator is internal and unwired. The caller supplies its admitted
repeatable-read transaction, one current SLO definition/measurement binding,
explicit evaluation clocks and all work limits. Historical exclusion revisions
are supported; historical SLO-definition evaluation is not added here. Existing
F4-T44 validates coverage against the current immutable definition's cadence.
The evaluator re-reads that binding and its source/exclusion authority in its RR
snapshot rather than trusting caller identity alone.

```go
type maintenanceMaskWindows struct {
    RequestedRevision int64
    Preferred *maintenanceComputedMask // optional original immutable identity
    Windows []slo.WindowInput
}
type maintenanceComputedMask struct {
    Revision int64
    BuildID pgtype.UUID // invalid only for implicit empty genesis revision zero
}
type maintenanceEvaluationInput struct {
    SloID, SliID pgtype.UUID
    DefinitionRevision, MeasurementRevision int64
    Requests []maintenanceMaskWindows
    Limits maintenanceWindowLimits
}
type maintenanceEvaluationResult struct {
    SourceGeneration int64
    Masks []maintenanceEvaluatedMask
    Preparation []maintenanceEvaluationPreparation
}
type maintenanceEvaluatedMask struct {
    RequestedRevision int64
    Computed maintenanceComputedMask
    Proofs []maintenanceCompatibilityProof // per complete requested source window
    Windows []slo.WindowResult
    ReusedHours []maintenanceReusedHour // original row identity and proof
}
type maintenanceReusedHour struct {
    Key maintenanceHourKey
    ComputedRevision int64
    Proof maintenanceCompatibilityProof
}
type maintenanceEvaluationPreparation struct {
    Kind string // mask, compatibility, comparison, source_hour, source_window, scoped_hour
    Comparison *maintenanceEvaluationBuildPair // immutable FirstBuild/SecondBuild
    RequestedRevision int64
    BuildID pgtype.UUID
    Hour maintenanceHourKey // optional source/scoped-hour provenance
    Start, End time.Time // complete proof/source range, when applicable
}
func evaluateMaintenanceWindows(context.Context, pgx.Tx,
    maintenanceEvaluationInput) (maintenanceEvaluationResult, error)
```

`comparison` requests carry both immutable build IDs, deduplicate the pair and
coexist with scoped-hour preparation; a completed different comparison is not
requeued. Canonical revision-zero pending uses an original `source_window`
envelope without adding SQL. The caller retains the input SLO/SLI/definition/
measurement envelope when persisting these requests. Source-hour keys route to
canonical dirty work by SLI/measurement/hour; their cached generation is not a
new immutable source job identity. Scoped-hour keys do require exact generation.
Compiler/compatibility pending joins `ErrDerivedPending`, preserving its specific
cause. Unavailable retained configuration and exhausted source work remain
distinct; a resource refusal is `ErrOperationalResource`, not corrupt intent.

Pending results retain typed preparation requests and source identities but no
partially successful numeric windows. Exhausted source preparation returns the
existing terminal-source error; corrupted facts, cancellation, database errors
and admission refusal preserve their existing error meanings. This helper does
not acquire a pool connection, write preparation rows, start workers or create
production limits.

### Bounded reads and provenance

- Validate the combined window count against the existing canonical 960-window
  ceiling, common clock/cadence, current binding and every explicit work limit
  before allocation or source reads. Keep original request/window ordering.
- Read exact requested completed builds first. These need no intervening-history
  proof. Otherwise use the explicitly preferred original build or at most one
  indexed latest completed build at or before the requested revision; genesis
  zero is the single alternative when no complete candidate exists. A failed
  compatibility proof requests preparation instead of searching older revisions.
- Prove reuse over each complete requested window, including validity/retention
  effects. Preserve requested versus computed revision, original build and proof
  separately. Empty eligible windows require no source or mask preparation.
  Current and last-breaching masks are separate `Requests` within the same
  call, not separate invocations; their aggregate work shares all three limits.
  No production budget profile is selected here. Future profiles must admit all
  accepted eight-condition policies and their recovery comparisons rather than
  leaving a legitimate fixed policy permanently pending on resource refusal.
- The planner deduplicates physical hours and edges. Charge shared source reads
  once and distinct mask/hour or mask/edge processing separately. Canonical
  revision-zero requests retain `evaluateDerivedWindows` and its SQL/query count
  unchanged. Charge a conservative raw-start upper bound from each original
  window edge before invoking it, because a merged union could undercharge
  overlapping canonical anchors. Existing accepted producer-grid constraints
  apply; revision zero adds no raw preflight I/O. Nonzero edge readers retain
  actual overflow sentinels and shared admission.
- Batch source-hour identities/readiness and canonical populations by explicit
  admitted hour arrays. Batch mask rank endpoints to classify each physical
  hour's aligned interval starts as eligible, excluded or partial. A missing
  canonical hour with neither raw starts nor dirty work has explicit generation
  zero and zero observations; it is not a prepared success. Dirty/exhausted rows
  preserve canonical precedence. An unaggregated raw population is pending.
- Exact prepared partial-hour keys are first. At most one indexed older row with
  the same SLO/definition/measurement/hour/source generation may be selected;
  reuse requires a complete owned-start source-range compatibility proof. Keep
  that row's actual build/revision in `ReusedHours`. No revision-prefix scan or
  global-generation invalidation is introduced.
- Raw edges and mask fragments use deduplicated bounded range batches. Bound
  unfiltered input before materialization using admitted aligned-slot bounds
  and one overflow sentinel, not a post-filter count. Fragment predecessor and
  forward seeks are bounded before outcome filtering. All original windows and
  distinct masks consume the same caller budgets.
- Canonical receipt certificates are checked before combining hours. Unknown
  receipt metadata from any eligible contributing hour makes the eligible
  receipt unknown; excluded receipts cannot change it. Partial summaries retain
  exact observed contributions even when the complete excluded population is
  unknown. The F4-T44 rank adapter plus shared covered-totals evaluator supplies
  all quality, freshness and exact arithmetic.

The two approved consumer indexes are implemented in migration 0065: `(slo_id,target_revision DESC) WHERE phase='complete'` on builds for
one candidate without scanning unfinished revisions, and
`(slo_id,definition_revision,measurement_revision,hour_start,source_generation,
exclusion_revision DESC)` on scoped hours for one older exact-source candidate.
They add no mutable state or new preparation protocol. Existing exact-key reads
continue using their primary keys.

The F4-T50 integration review exposed two terminal-preparation paths that could
otherwise exhaust an alert processor or defer a boundary forever. The shared
producer now returns an `Unavailable` reason aligned with each original window;
a successful unavailable slot is a zero `WindowResult`, never a numerical zero.
Usable independent windows keep their original positions and compatibility proofs.
Missing compiler history and terminal queue health are distinguished from ordinary
pending work and database errors. Requested-mask failure can therefore leave an
older proven short window usable while a changed long window is unavailable.

Queue health reads use exact immutable identities. Scoped-hour matching includes
SLO, SLI, definition, measurement, build, physical hour and canonical source
generation. Ready builds, exact populations and completed equal-union proofs take
precedence over old terminal queue flags. A newer source generation does not
inherit an older job's terminal status. Failed compatibility/comparison jobs only
disable that reuse route; urgent exact-hour preparation remains possible. A still
pending comparison can rescue a retained older population after direct preparation
has lost its raw source, so that work remains pending rather than being discarded.
Any remaining recoverable source/hour dependency clears every numerical result
for the boundary, including when another dependency in the same window is terminal.
