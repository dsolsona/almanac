## Migration and state semantics

Add nullable `retire_at timestamptz`, with check NULL or retire_at>=issued_at. It is a scheduled acceptance cutoff, separate from actual explicit revoked_at. Do not shorten expires_at or overwrite explicit revocation. No encryption dependency. Select safe columns explicitly and return normalized UTC metadata.

An active credential is unrevoked, in current installation epoch, issued_at<=now, now<expires_at, and retire_at NULL or now<retire_at. Agent must be enabled. Retired/expired/old-epoch credentials remain historical records. Stored state reads still do not claim machine authentication is implemented.

Lifetime zero=>90 days; explicit whole seconds >0 and <=365 days. Overlap nil=>10 minutes; explicit whole seconds 0..10 minutes. Nil and explicit ten minutes have identical semantics/digest; zero is distinct. Validate IDs/versions/keys/request ID/time as T04 does; no plaintext storage input.

Enabled agent with zero active credentials may rotate to recover from expiry/revocation/epoch invalidation. With one active credential, create replacement and set previous retire_at to min(existing acceptance cutoff, now+overlap), never extending existing expires_at/retire_at. At zero overlap the previous credential is inactive at now, including when issued_at==now. New credential uses current epoch, expires now+lifetime, retire_at/revoked_at nil. Preserve agent ID/name and any future assignments.

With two or more active credentials reject ErrAgentConflict, including requested zero overlap. Do not choose a victim or silently revoke a third token. Admin must explicitly revoke one or wait for expiry, then issue a new command with current version. Disabled agent=>ErrAgentConflict; absent=>ErrAgentNotFound after authorization. Candidate public-ID collision=>ErrAgentConflict and full rollback. An enabled identity with old-epoch credentials can get a current-epoch replacement without reactivating old ones.

Every fresh rotation is a real change: increment shared agent version exactly once and updated_at. No rotation no-op; repeated matching command is receipt replay. MaxInt64 version conflicts. Revocation/disabling remain T04 semantics even for retired credentials: revoking a retired-but-not-explicitly-revoked row changes state/version; disable revokes all null revoked_at rows. Existing explicit revocation timestamps and retire_at remain unchanged. A rotation receipt may describe an enabled agent/credential later disabled/revoked; read current state separately.

## Transaction and receipt ordering

Use T04 installation -> user -> session -> agent -> credential order, never reverse. User lock serializes same-actor receipts; agent FOR UPDATE serializes lifecycle changes across different administrators. Validate current admin authority and request-local proof after human locks, then receipt lookup BEFORE target/version checks. Recheck fresh/nondecreasing clock and proof/session validity before replay commit. Operation is `agent.credential.rotate`, receipt scope actor+operation+key, TTL completion+24h.

Digest fixed-order versioned semantic tuple operation, AgentID, ExpectedVersion, normalized lifetime seconds and overlap seconds; exclude candidate ID/verifier, password/proof, request ID, generated times. Same key/different tuple conflicts. Exact receipt expiry deletes only matching expired receipt and makes this a fresh version-checked command.

After locking agent and relevant credential rows, resample clock and recheck proof/session; validate enabled/current version and now>=agent.created_at/updated_at and changed credential issued_at. Determine active set under these locks with current epoch/time. Since every legitimate credential writer holds agent lock, query at most enough active rows to detect >1 and lock in deterministic public-ID order; don't load unbounded historical credentials into Go. Insert new credential and retire previous if present, update version/time, write audits and receipt atomically. Resample completion time/recheck authority timing before receipt insertion. Preserve cancellation/safe errors; no partial result on error or ambiguous commit.

Audit policy: one `agent.credential.rotated` success event with agent subject and one `agent.credential.issued` with new credential subject; if previous credential exists, one `agent.credential.retirement.scheduled` with its subject, even for zero overlap. These are rotation/retirement events, not explicit revocation. Actor/request/time use T04 conventions; no full submitted body, verifier or token. Receipt stores only versioned AgentRotationResult metadata excluding Replayed. Audit or receipt failures roll back old deadline, new credential, agent version and all audit rows.
