## Outcome

An editor schedules maintenance for selected services, selected SLOs, or all
services. The editor can preview the affected SLOs separately from the selector.
Detail and SLO timeline views show recorded participation. Calculations omit
eligible observations in those intervals and show preparation until the current
membership is proven. Alert evidence retains the cutoff-based decision about
whether a new occurrence opened.

## Interfaces and compatibility

`/api/v1/scoped-maintenance` uses a discriminated `scope` selector, strong
revision ETags and the existing maintenance permissions. Preview is a
paginated, authenticated POST with CSRF protection and no mutation receipt.
Impact is a paginated, revision-specific GET. It distinguishes pending
preparation from an empty result. The SLO timeline endpoint provides per-SLO
participation intervals with the matching window revision and a readiness
indicator. The legacy explicit-SLO API retains its existing representation.

`almanac maintenance preview` and `almanac maintenance impact` expose the
paginated reads. The existing lifecycle, list, detail and timeline commands
accept `--scoped` for the new endpoint and representation.

## Acceptance

- Schedule each scope, preview inventory, and check that the persisted selector
  matches the request. Reject empty, mixed, duplicate and unknown selectors.
- Use two services and independent observations to check eligible totals.
  Verify non-retroactive joins and departures, overlap, half-open boundaries,
  cancellation, shortening, restart and completion of bounded publication.
- Prove that an eligible threshold breach at a covered cutoff retains evidence
  without opening an occurrence. Keep existing acknowledgement and allow
  genuine eligible clear. Check the first eligible uncovered cutoff.
- With a seeded fleet, select through the shared searchable picker, page through
  impact, and inspect the same participation interval on each relevant graph.
  Exercise both themes, keyboard navigation, mobile, and the detail link.
- Exercise the authenticated API on the normal executable and browser workflows
  through the ordinary test stack. Retain screenshots in review artifacts.
