## Outcome

Deliver an installation-wide inactivity timeout under Settings → Sessions with an
eight-hour default. Keep the twelve-hour absolute expiry and apply saved values
on new sign-in or session rotation. Preserve pre-upgrade session expiry.

## Interfaces and edit scope

[Plan 0032](../plans/0032-session-inactivity.md) covers the PostgreSQL migration,
generated queries and API types, shared session authorization, Settings form and
browser reference. GET and PUT `/api/v1/settings/sessions` require an unrestricted
administrator. PUT requires same-origin CSRF protection, whole minutes in
1–720, and the current policy version.

## Acceptance and verification

- Open Sessions as an admin and see 480 minutes. Edit to 360, save, reload and
  see the persisted value. Back and direct navigation open the correct page.
- Reject invalid and stale writes and access by non-administrators.
- At exact expiry, deny a session. Verify issuance, password rotation, and that
  increasing the timeout cannot revive a previously issued expired session.
- Compare Settings with its HTML reference in both themes at 360 and 1440 px.
- Run `make check` and `make test-e2e` against isolated Docker fixtures.
