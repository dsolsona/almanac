## Fixed wire interface

Backend owns OpenAPI source and generation. Before implementing handlers, submit the
schema diff to the coordinator for interface review and transfer to the UI worktree.
After that handoff do not change field names/types without coordinating both consumers.
Use existing JSON envelope/error/ETag conventions, role checks, CSRF, request IDs,
actor-scoped 24h idempotency receipts and authorization on replay. Do not add dependencies.

Operations:

- `GET/POST /api/v1/services`, `GET/PATCH /api/v1/services/{id}`.
- `GET/POST /api/v1/slos`, `GET/PATCH /api/v1/slos/{id}`.
- `GET /api/v1/slos/{id}/evaluation?at=...&timeline_start=...&timeline_end=...`.
- Lists default 50/max 200, stable opaque cursors <=512 bytes. SLO list accepts optional
  service_id bound into its cursor. List definitions without per-row evaluation queries.
- Create service: name and display_name. Metadata patch changes display_name only,
  with exact If-Match; immutable name cannot be renamed. Existing name/display bounds apply.
- Create SLO: name, display_name, service_id, sli_id, target (exact fraction decimal
  string), rolling_window_seconds (integer from 1 through 2147483647), optional evaluation_valid_from
  (UTC microsecond timestamp). Target is `[0,1)` at accepted numeric precision.
  Window uses fixed seconds, must be a cadence multiple; reject rather than prorate.
  Validate duration before time arithmetic and report an actionable limit, never overflow.
- SLO metadata patch changes display_name only, with If-Match. Resource version is
  distinct from immutable definition_revision. Preserve cadence in the SLO definition;
  existing datasource/SLI mutation guards remain intact.
- Resource reads return id, name, display_name, version, created_at and updated_at.
  SLO additionally returns definition_revision, service_id/service_display_name,
  sli_id/sli_display_name, target, rolling_window_seconds, cadence_seconds, activated_at,
  evaluation_valid_from and historical request provenance (actor ID/time when applicable).
  Versions/revisions and decimal quantities are strings; times UTC microseconds.
- CLI parity: services list/get/create/update; slos list/get/create/update/evaluate,
  using existing protected profile/authentication, JSON/text output and exit conventions.
  Create accepts explicit idempotency key; update exact If-Match. No password re-entry.
- Validation uses existing Problem field errors: target/target_invalid,
  rolling_window_seconds/window_invalid, evaluation_valid_from/historical_start_invalid,
  timeline_start/timeline_range_invalid and at/evaluation_time_invalid. Clients map
  these codes to actionable static text and preserve safe drafts.

Evaluation response contains:

- `evaluation_id`, `requested_at`, `effective_end`, `calculation_version` and an explicit
  `snapshot_kind: current_evaluation`. One repeatable-read transaction owns the complete
  response. This is not a retained/replayable historical report or commit watermark.
- `objective`: SLO/SLI IDs and definition/measurement revisions, target, method
  `occurrences`, rolling_window_seconds and cadence_seconds.
- `window`: requested_start, effective_start, end, eligible_start, retention_start,
  activated_at, evaluation_valid_from and historical provenance. Effective end is the
  requested time floored to the canonical grid; do not silently subtract settling delay.
  Eligibility is the whole-interval intersection with SLI and SLO validity. Pre-validity
  is not applicable; older-than-retention eligible intervals are expired, not N/A.
- `quality`: state, expected_intervals, observed_intervals, known_empty_intervals,
  missing_intervals, zero_traffic_intervals, expired_intervals, coverage, first_observation_at,
  last_observation_at, latest_receipt_at and freshness. Interval counts are bounded exact
  integers; coverage is a nullable decimal string. Receipt time is not a commit watermark.
  States distinguish complete, partial, no_data, zero_traffic, expired_history and
  not_applicable. Freshness uses observation time, not agent reachability.
- `performance`: state (`met`, `violated`, `unknown`, `not_applicable`), observed_state
  (nullable met/violated comparison), provisional, reason, good, total, bad, attainment,
  allowed_budget, remaining_budget, consumed_fraction, remaining_fraction, burn and
  budget_unit `events`. Values are nullable decimal strings, never NaN or fabricated zero.
  Preserve observed arithmetic for incomplete coverage with a clear qualification.
- `timeline`: start, end, cadence_seconds, max_intervals=1500, items in ascending order;
  each item has start/end, state, good/total, attainment, burn and received_at. Explicit
  states: observed, zero_traffic, known_empty, missing, expired, not_applicable. No fake
  count values for gaps. Both explicit timeline bounds are required together, aligned,
  within the objective window and at most 1500 intervals; invalid requests explain bounds.
  Default timeline is the latest min(window intervals,1500) canonical intervals. Disclose
  this recent range separately from the full objective window. No downsampling in this
  increment. Exact table paginates the same bounded response locally; a new range creates
  a new complete evaluation, not a continuation claiming the previous snapshot.

The existing SLI history metadata supplies the earliest eligible retained interval,
not a promise of uninterrupted observations. The historical option can propose the
later of that boundary and the aligned rolling-window start. Server validation remains
authoritative; retain the draft and explain a rejected start without silently changing it.

Schema naming can follow existing generated conventions, but the above wire fields and
meanings are the shared interface. Concrete validation/error examples belong in OpenAPI.

## Calculation invariants

Use dedicated SQL over canonical coverage and values, never the paginated SLI history
endpoint or failed/incomplete attempts as successful observations. SUM(numeric) stays
exact beyond individual field width; rational arithmetic rounds half-even only at the
12-decimal output boundary. Status compares exact unrounded values. No dependency
needed for decimal math. Use current supported immutable SLI revision/cadence; reject
unsupported histories rather than silently pooling semantic revisions.

Known-empty contributes collection coverage but no numerical measurement; never treat
it as 0/0. When a result contains unmeasured intervals, preserve observed-only arithmetic
and do not assert full-window met/violated. The UI clarification is that these useful
numbers remain prominent, with a coverage qualification. Explicit 0/0 observations count
as measured coverage, add zero counts, and only make ratios unavailable when all traffic
is zero. All-empty/no-observation results cannot show 100% success.

Expected counts use aligned bounds arithmetically; do not generate millions of interval
rows for summaries. Timeline generation alone is bounded to1500. Use indexed canonical
keys and a consistent transaction for aggregate and timeline reads. PostgreSQL recorded_at
is assigned before commit: never label MAX(recorded_at) a commit watermark. Durable
snapshot/export metadata remains a later F3 reporting task.
