## Outcome and non-goals

The canonical occurrence-window evaluator and exact totals consumer support a
union of aligned exclusion intervals without mutating observations, stretching
windows, double subtracting overlaps or making missing measurements successful.
Results distinguish fully excluded, zero traffic, missing and expired data.

This is not delivery of maintenance exclusions. Persistence, permissions, APIs,
UI/CLI, audit revisions, dirty-work fencing, storage queries, composite/slice
calculators, alert lifecycle integration and production callers remain outside
this task. The engine's performance/adoption gate remains independent.

## Interfaces and edit scope

Add `ExclusionInterval{Start, End time.Time}` and
`WindowInput.Exclusions []ExclusionInterval`. Each input is already resolved to
one SLO and one consistent exclusion revision by its caller. Never apply a mask
globally to its SLI or mutate the caller's observations/mask.

Add `WindowResult.Excluded int64`, `ExcludedGood, ExcludedTotal *string` and
`WindowTotals.Excluded ExclusionTotals`, where the latter carries exact
`Good, Total *big.Rat` and `Observed, KnownEmpty int64`. Existing totals and
observation timestamps describe only non-excluded retained eligible intervals.
Excluded statistics describe only excluded retained eligible intervals. Return
excluded event totals only when every excluded eligible interval is observed
with exact counts; missing, failed, incomplete, known-empty or expired excluded
intervals make those totals null. An empty effective mask leaves new result
fields zero/nil and preserves existing results.

Edit only calculation code/tests under `internal/slo/` and this task/plan.
No generated source or public wire contract changes are required. The primary
reviewed these proposed interfaces before implementation.

## Acceptance and expected cases

- SPEC-0016 AC-01: 900/1,000 retained events plus excluded 100/1,000 gives
  adjusted attainment 90%, allowance 10, failures 100, remaining -90 and burn 10
  at target 99%; evaluating the unchanged observations without exclusions gives 50%.
- AC-02: reject empty/reversed/unaligned masks; union duplicates, overlaps and
  adjacent bounds; clip to effective eligibility and retention without prorating.
- AC-03: missing inside exclusions does not reduce adjusted coverage; missing
  outside does. No-data, zero traffic and fully excluded remain distinct.
- AC-06 foundation: all-excluded has `State`/`Reason` `excluded`, unknown
  performance and null attainment/budget/burn; this task makes no incident decision.
- Freshness compares the last eligible observation against the latest eligible
  expected interval, including a trailing excluded span. A missing eligible
  interval before maintenance remains missing/stale according to ordinary grace.
- Raw and pre-aggregated inputs agree against independently derived expectations;
  inconsistent excluded statistics and timestamps are rejected.
- Reusing observations across two input scopes cannot change the unmasked scope;
  masks are copied before sorting/unioning. Rolling evaluations retain snapshots.

User acceptance is a deterministic library fixture: unchanged source observations
and two independently scoped window inputs produce the specified raw/adjusted
values. Invalid masks return calculation errors and require corrected whole-grid
bounds. No UI navigation, deployment persistence or production integration is
introduced; those acceptance checks belong to later maintenance delivery.
