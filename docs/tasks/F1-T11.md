## Outcome and boundaries

Provide shared PostgreSQL admission for password checks: at most five account
failures and20 source-address failures in a rolling15-minute window. Reserve a
slot while password work runs so simultaneous checks cannot overshoot both limits.
This is internal storage only; application login, current-password proof, HTTP
Retry-After, cookies/CSRF and public routes remain unimplemented.

Own `internal/storage/login_attempts.go`, focused tests, new immutable migration0004,
query sources and generated dbgen output. Update migration-version assertions and
sqlc inputs without weakening existing tests. No dependency changes or edits to
earlier migrations. Coordinator owns docs/Git. Reuse existing transaction bounds,
safe errors and explicit schema compatibility checks.

```go
type BeginLoginAttemptInput struct {
    Login string
    Source netip.Addr
    Now time.Time
}
type LoginAdmission struct {
    Allowed bool
    AttemptID string
    ExpiresAt time.Time
    RetryAfter time.Duration
}
var ErrInvalidLoginAttemptInput error
func BeginLoginAttempt(ctx context.Context, databaseURL string, input BeginLoginAttemptInput) (LoginAdmission, error)
func FinishLoginAttempt(ctx context.Context, databaseURL, attemptID string, succeeded bool, now time.Time) (bool, error)
```

Input login is nonempty valid UTF-8 at most256bytes, same bounds as local lookup.
Source must be valid, unzoned IP; canonicalize IPv4-mapped IPv6 with Unmap(). Reject
unspecified/multicast addresses. Now must be nonzero; use UTC microsecond precision.
Finish requires a canonical lowercase UUID ID. Invalid input returns the sentinel;
operational errors remain safe errors, not throttled or successful results.

## Persistence and lock order

Migration0004 stores attempts, without requiring a matching user: UUID primary ID,
account_key bytea32, source_key bytea32, started_at/expires_at timestamptz and state
`pending` or `failed`, all NOT NULL; expires_at > started_at. Index account_key and
source_key with expires_at for count/read operations, and expires_at for cleanup.
Only digests of canonical keys are persisted; no raw login, IP or password in rows.

Account key is SHA256 of UTF-8 PostgreSQL lower(login), exactly matching the existing
database local-user comparison. Source key is SHA256 of the canonical unmapped IP
string. Compute the former through a generated SQL expression/query; never replace
database lowercase semantics with Go Unicode folding. No pgcrypto dependency is
needed for PostgreSQL's [built-in SHA256 bytea function](https://www.postgresql.org/docs/18/functions-binarystring.html).
Verify SQLC generation.

Use PostgreSQL transaction advisory locks before reading counts/mutating attempts:
account domain then source domain. Use two-int advisory namespaces `0x414c0001`
and `0x414c0002`, respectively; the second int is the first four digest bytes read
big-endian and converted to int32. PostgreSQL's [two-int advisory key space](https://www.postgresql.org/docs/18/functions-admin.html#FUNCTIONS-ADVISORY-LOCKS)
is separate from the existing schema upgrader's bigint key. A hash collision may
serialize unrelated keys but must never
merge their rows/counts: queries always compare all32bytes. Do not create permanent
lock-key rows. Bounded advisory waits use the existing transaction lock timeout.

Finish may first read immutable keys by ID, then acquire the same account→source
locks, re-read the attempt FOR UPDATE and validate it. Never acquire advisory locks
while holding an attempt row lock. All operations use READ COMMITTED transactions;
counts occur after locks so another process's committed attempt is visible.

## Admission and completion

An active attempt has expires_at > Now. Pending reservations last one minute;
failed attempts expire15minutes after failed completion. At an exact cutoff an
attempt no longer counts. Count active pending AND failed rows independently for
the same account and source. A pending slot is bounded admission, not a recorded
password failure; concurrent successful checks can temporarily consume capacity.
The later application must bound password work within the lease and cannot grant
authentication from an expired result.

When both counts are below5/20, insert one pending row, return Allowed=true, UUID
AttemptID and ExpiresAt=Now+1minute; RetryAfter=0. When limited, return Allowed=false,
empty AttemptID/ExpiresAt and positive RetryAfter. For each blocked dimension find
the expiry that brings its count below its limit, and take the maximum delay if
both dimensions block. This is a snapshot retry hint, not a future capacity promise.
No denied attempt row is inserted and no existing expiry is extended.

Finish accepts only a pending attempt with started_at <= Now < expires_at under
locks. A successful check deletes its reservation, without clearing earlier failure
rows. A failed check changes it to failed and sets expires_at=Now+15minutes once.
Return true after commit. Unknown, already finished, expired and pre-start attempts
return false,nil with no mutation. Duplicate failure completion must not extend the
window or add a second event. The application must receive true before allowing
the checked result to proceed; existing session issuance separately fences user
credential revision/epoch. No session is issued by these functions.

Prune at most100 expired rows per Begin transaction, after advisory locks, using
ordered bounded selection with FOR UPDATE SKIP LOCKED. Never prune live rows or wait
for another operation's row locks. Expired rows may remain until later requests;
do not claim a background retention service. No hashing of passwords or network
work under locks. Never log complete inputs or persisted keys.

## Acceptance checks

1. Schema3→4 preserves users, installation, sessions and audits. Constraints/indexes
   are present; old migration bytes unchanged. Unknown logins use the same path and
   limits as known logins; no user-existence lookup is involved.
2. Fifth account failure is recorded; sixth Begin is denied. Twentieth source failure
   across accounts is recorded; twenty-first is denied. Same account across sources
   shares its budget. Different accounts/sources do not share counters.
3. PostgreSQL-case-equivalent logins and mapped/unmapped IPv4 addresses share keys.
   Invalid input fails before DB work. Rows store digests only, with no raw inputs.
4. Concurrent independent connections cannot reserve beyond either threshold.
   Successful completion frees only its slot; earlier failures remain. Failed
   completion consumes its reserved slot without increasing the active count.
5. Exact failure/reservation expiry boundaries, duplicate completion, pre-start
   completion and expired completion behave as above. Denials do not extend windows.
   Assert RetryAfter for each dimension and both together, using explicit times.
6. Bounded pruning removes at most100 expired rows, preserves live rows and skips
   an intentionally locked expired row. No unbounded collection/SQL IN list.
7. Observe advisory-lock blocking, cancel, verify bounded return/cleanup and retry.
   Failure while inserting/updating rolls back; injected faults are test-DB-only.
8. Missing/pending/newer schema and outage fail closed with safe errors and no DDL.
   Add direct new-operation boundary cases using existing fixture patterns.
