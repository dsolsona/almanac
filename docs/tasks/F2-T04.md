## Validation and bounded reads

Validate canonical UUID target IDs, nonnil clock, positive ExpectedVersion,
existing RequestID rules and existing printable-ASCII idempotency-key bounds.
Read Limit zero=>50, otherwise 1..200; reject negatives/over-limit. No filters.
Cursor at most 512 ASCII bytes, canonical unpadded raw-base64url of fixed versioned
JSON containing list kind, normalized microsecond timestamp, canonical UUID and
AgentID for credential lists. Decode with bounded input, reject unknown fields,
unsupported version, malformed/zero timestamp, noncanonical encoding or UUID,
wrong list kind/agent. Cursor is an opaque position, not authorization; signing or
new secret management is unnecessary. Limit may change between pages. No offsets.

SQL uses strict tuple `>` and ORDER BY timestamp,id with LIMIT requested+1.
Return at most requested items; next cursor is the last returned item only when
the extra row exists. Empty Items is a nonnil empty slice. Equal timestamps use ID
tie-breaks. Keyset traversal is not a snapshot across independent calls: concurrent
inserts after the position may appear; do not invent a stronger guarantee.

Reads use connectCurrentSchema, bounded transaction, installation -> user -> session
locks and current normal enabled Administrator checks, with no password proof and
no session touch. Sample/normalize Now after authority locks. InspectSession then
an unrelated read is insufficient. Get locks the target agent FOR SHARE; credential
list locks its agent FOR SHARE before querying safe credential columns. Lists of
agents use one ordered SELECT under the same authorized transaction. No SELECT *
from credential tables. Final nonzero/nondecreasing clock reading must still satisfy
session timing before commit/return. All failures return zero results.

## Mutation lock, timing and receipt sequence

Reuse registration's trusted request-local proof and its 30-second bound. Keep
installation -> user -> session -> agent -> credential order. Installation FOR SHARE,
user/session FOR UPDATE as today; agent FOR UPDATE. All lifecycle writers, including
future rotation, must share the agent lock. Revoke locks its target credential after
agent; disable locks unrevoked credential rows in ascending ID order before changes.
Never acquire another human/installation lock after an agent/credential lock.

Outside locks validate fields and compute SHA256 of a fixed-order versioned semantic
JSON tuple: operation, AgentID, CredentialID for revoke, ExpectedVersion. Exclude
proof/session/requestID/clock/computed times. Fixed operations are
`agent.credential.revoke` and `agent.disable`; do not alter agent.create receipts.

After authority locks sample Now, normalize UTC/microseconds and enforce existing
invalidSessionState plus normal Administrator, proof user/epoch/revision binding,
and `VerifiedAt <= now < VerifiedAt+30s`. User lock serializes same-actor commands.
Read actor+operation+key receipt before target lookup/version checks. A valid,
unexpired same-digest receipt returns recorded historical safe metadata with
Replayed=true, even when its version is now old or target later disabled. Different
digest conflicts. At exact expiry delete only that matching expired receipt and
treat as fresh; no global cleanup. Replay must not extend expiry or add audits.
Recheck nondecreasing clock and proof/session timing immediately before replay commit.
Malformed stored receipt is a safe internal error, never partial/default success.

For fresh commands lock target agent/credential rows, then resample time and recheck
proof/session timing: target-lock waits can invalidate previously valid proof/session.
Require now>=agent.created_at/updated_at and every credential issued_at that will be
changed; reject backwards command time as ErrInvalidAgentInput, rather than choosing
a future revocation timestamp. ExpectedVersion mismatch=>ErrAgentConflict. A change
at MaxInt64 conflicts without overflow; a genuine no-op at MaxInt64 may succeed.
Use current post-lock timestamp for writes/audits. Before receipt insertion sample
completion time, require nondecreasing time plus valid proof/session, then store
created_at=completion and expires_at=completion+24h. State, version, all audits and
safe versioned receipt commit atomically. Every error/commit ambiguity returns zero.

A private concrete authority/timing helper is justified by these callers; extract
only what is actually shared, preserving registration regressions. No transaction
callback engine, command registry or generalized receipt framework.

## State changes, no-ops and audit policy

Revoke affects exactly the requested credential belonging to the agent, including
expired/old-epoch credentials; enabled state is irrelevant. If revoked_at is null,
set it to now, increment agent.version once, update agent.updated_at, Changed=true,
RevokedCredentialCount=1 and return safe affected credential. Keep identity and other
credentials unchanged. Emit one `agent.credential.revoked` success audit with
credential subject. Already explicitly revoked: preserve timestamp/version/updated_at,
Changed=false/count0 and emit `agent.credential.revoke.noop` success audit instead.

Disable sets enabled=false and revokes every credential with null revoked_at,
including expired/old-epoch credentials, preserving prior revocation timestamps.
If enabled was true OR any credentials changed, increment version once and updated_at,
Changed=true; return Credential=nil and actual changed count. Emit `agent.disabled`
with agent subject only for enabled->disabled, and `agent.credential.revoked` with
credential subject for each newly revoked row. Use bounded bulk SQL statements
(e.g. INSERT SELECT over changed rows), not a per-row network loop or an unbounded
credential result in Go. If already disabled with no changed credentials, leave
version/time intact, Changed=false/count0 and emit `agent.disable.noop` once.
If already disabled but inconsistent unrevoked rows exist, revoke them and audit
those changed credentials; this is a real versioned repair, not a no-op.

Every fresh successful command, including no-op, gets its own safe receipt. Stale
version still conflicts for no-op; only a matching authorized receipt precedes it.
All audit rows use the current user actor, supplied RequestID, success outcome and
relevant public UUID subject. No success audit occurs on rollback/replay.

## Meaningful acceptance

- Real PG normal-admin detail/list/credential history reads; denied invalid,
  revoked/expired/restricted, disabled user and viewer/editor sessions, with no
  target disclosure. Reads do not touch session. JSON and SQL safe-column checks.
- Pagination default/max, invalid limits/cursors, wrong scope/kind, equal-timestamp
  boundaries, empty/end pages and no duplicates across stable dataset. Credential
  histories larger than page size remain bounded. Identity reads include disabled.
- Revoke identity preservation, other credential untouched, wrong pairing not-found;
  disable all unrevoked credentials including expired/old epoch; previous timestamps
  preserved; exact version/audit/count/receipt assertions for changes and no-ops.
- Stale version and MaxInt64 cases, backwards clock and exact proof/session expiry.
  Two administrators racing same version yield one success/one conflict. Same
  actor/key/body concurrency yields one mutation plus replay; operation/actor
  isolation, changed body/version conflict, historical replay after later mutation,
  original receipt expiry and exact24h fresh behavior. Fresh session same actor can
  replay; revoked authority cannot. Not-found/conflict failures leave no receipt.
- Block on user lock and separately on target agent/credential lock, advance clock,
  prove post-wait checks deny with zero lifecycle mutations. Keep proof fresh when
  isolating session expiry. Actual logout/password-change/epoch/role invalidation
  ordered first denies. Cancellation releases locks and produces no lifecycle rows.
- Inject failure of state-change/no-op audit and receipt insertion after writes:
  version/enabled/revoked_at/audits/receipt fully roll back. Reads and replays fail
  safely on cancellation/commit error. Existing CreateAgent and auth regression
  assertions remain valid. Preserve first failures; do not rerun-to-green or weaken.
