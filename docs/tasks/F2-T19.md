## Outcome

An administrator can inspect an agent's actual reachability, reported capabilities,
configuration application and collection progress from the existing Agents detail
view and CLI. Use the accepted application shell and shared visual components.
Do not create new destinations, dashboards or fabricated activity.

## Shared interface and edit boundary

Consume the optional nullable `Agent.runtime` in the generated management API.
Absence means never connected. Present connected, unreachable and incompatible
states distinctly; an administratively disabled agent must not appear operational
merely because its last heartbeat is recent. Runtime contains protocol/software,
provider capability tuples, last heartbeat, desired/applied revision strings,
scheduler health, separate collection progress and nullable query timestamps.
`collection_explanation: no_assignment` must explain why no collection occurs.
Revision `0` means configuration has not been applied, not revision zero success.

Own browser client validation, Agents presentation, shared-component usage and
their focused tests; CLI agent detail rendering/validation and tests. Do not edit
OpenAPI, generated files, protocol, storage, backend handlers, runtime or dependency
files. Report required contract corrections to the coordinator. Keep exact decimal
revisions as strings throughout. Do not confuse last heartbeat, last query success
and backend-accepted observation freshness; the latter is not available yet.

Keep existing registration, one-time token recovery, lifecycle operations,
pagination and navigation intact. Refresh must preserve pending mutation state.
Provide accessible labels and readable empty/error states with existing design
tokens. Unsupported or corrupt runtime data fails visibly, never silently reads
as a healthy/no-capability agent. Do not add polling without cancellation or
unbounded background requests. Reuse the existing refresh flow for this increment.

## Acceptance and checks

- Never-connected, connected, unreachable, incompatible and disabled examples.
- Desired revision differs from applied; applied zero; no assigned sources;
  empty capabilities; unknown/malformed fields; missing query timestamps.
- CLI detail exposes the same actual fields and preserves machine-readable exact
  values and existing noninteractive behavior. No secrets/grant IDs are displayed.
- Component/client checks verify states and original flows; real backend plus
  separate agent journey is required before final acceptance, coordinated with
  F2-T17. Mocked component evidence alone is not completion.
- Inspect actual detail views in light/dark themes at desktop/mobile widths and
  keyboard navigation after real integration. No token-bearing screenshots.

Use exact approved operations from [commands](../commands.md); no new approval
requests, arbitrary selectors/wrappers or direct compiler/formatter commands.
Known focused checks are `make verify VERIFY_MODE=unit TEST_FILE=tests/agents-page.test.tsx`
and `make verify VERIFY_MODE=unit TEST_FILE=tests/agents-client.test.tsx`.
Coordinate port 5199 before the exact full verification wrapper. Read Modern Go
guidance before CLI Go edits. Do not commit, push, invoke Crit or dispatch agents.
