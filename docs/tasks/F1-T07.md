## Outcome and non-goals

Persist the initial administrator, provisioned marker and success audit event in
one transaction. Concurrent startup attempts produce one owner and one audit event;
repeated calls return persisted state without resetting passwords or reopening
onboarding. This is an internal persistence boundary, not a startup command or
working authentication flow. No HTTP routes, password files, denylist, cookies,
sessions, token issuance, offline recovery or onboarding completion in this task.
The later application service must enforce the full password policy and hash before
calling this boundary; no password hashing while holding database locks.

```go
// internal/storage
type InitialOwnerInput struct {
    Login string
    PasswordVerifier string
    Now time.Time
    RequestID string
}
type InitialOwnerState struct {
    Provisioned bool
    AdministratorID string
    OnboardingComplete bool
}
type InitialOwnerResult struct {
    State InitialOwnerState
    Created bool
}
var ErrInvalidInitialOwner error
func ReadInitialOwnerState(ctx context.Context, databaseURL string) (InitialOwnerState, error)
func ProvisionInitialOwner(ctx context.Context, databaseURL string, input InitialOwnerInput) (InitialOwnerResult, error)
```

Results never contain password verifiers, submitted credentials or raw database
errors. Read requires an explicitly upgraded compatible database and performs no
DDL. Provisioning also requires the current schema; it must not silently upgrade.
Both operations use the existing safe connection/error handling and bounded
connection/statement/lock/cleanup patterns. Missing or incompatible schema fails
closed; do not return apparently unprovisioned state on a query failure.

Provision locks the singleton installation row in its transaction before checking
the marker. If already provisioned, return its persisted state with Created=false
without validating or applying input (including empty input), so a removed initial
password file can be handled by the future caller. On a fresh installation, validate
Login as nonempty valid UTF-8, at most256 bytes; preserve supplied text. Require a
valid supported password verifier, nonzero Now, and nonempty valid UTF-8 RequestID
at most128 bytes. Validation failures use the safe sentinel and leave no state.
These are internal storage bounds, not the future public login-name policy.

## Schema and transaction decisions

Do not edit migration0001. Migration0002 creates:

- `public.almanac_users`: UUID `id` default gen_random_uuid(), `login` text,
  `password_verifier` text nullable for future pending/external users, `role` text
  constrained to viewer/editor/administrator, `enabled` boolean,
  `must_change_password` boolean, positive bigint `credential_revision` default1,
  `created_at` and `updated_at` timestamptz. Required columns are NOT NULL except
  the verifier. Enforce bounded nonempty login storage and a unique expression
  index on `lower(login)` using PostgreSQL's database collation. Application
  lookups must use that same expression; this does not introduce separate Go
  normalization or password normalization.
- `public.almanac_audit_events`: UUID `id`, `actor` text, `subject_id` uuid,
  `action` text, `outcome` text, `occurred_at` timestamptz, `request_id` text.
  Required fields are NOT NULL. This task only writes actor=`system`,
  action=`identity.bootstrap.provision`, outcome=`success`, subject_id=new user ID.
  No submitted login/password/verifier, database URL or arbitrary changes payload.
  Audit has no user foreign key, so future account deletion cannot erase history.
- Installation columns `bootstrap_admin_id` uuid nullable referencing users(id),
  `bootstrapped_at` timestamptz nullable, `onboarding_completed_at` timestamptz
  nullable. Constrain admin ID and bootstrapped_at to be both null or both set;
  completion requires provisioning. Preserve installation ID and credential epoch.

The initial user is enabled administrator, must_change_password=true,
credential_revision=1. Its creation/update times, provisioning time and audit time
are the supplied Now converted to UTC (PostgreSQL microsecond precision applies).
Insert user, audit and provisioning marker in one transaction; do not set completion.
Use generated SQL for ordinary reads/writes. Update sqlc schema inputs to include
bootstrap metadata plus migration files, then regenerate, never hand-edit generated
code. Generated persistence models must not be used as public responses.

## Acceptance and verification

1. Strict verifier validation accepts generated values and rejects malformed values
   without a hash; existing identity checks remain intact.
2. Fresh schema upgrade creates the tables and preserves installation identity.
   Explicit upgrade from version1 to version2 works; migration0001 is unchanged.
3. Fresh state is unprovisioned. Provision creates one restricted initial owner,
   persisted timestamps and one redacted success audit. State reads expose only
   the three fields above and do not complete onboarding.
4. Concurrent calls with distinct valid inputs produce one Created=true and the
   same administrator ID for every successful caller, one user and one audit event.
   Use bounded contexts, coordinated starts and bounded completion waits.
5. Repeat with changed or empty credentials returns the existing owner and changes
   neither verifier, role, revision, timestamp, audit count nor onboarding state.
6. Inject a database audit-insert failure in a disposable test database; verify
   rollback removes the user and marker and permits a successful retry. Do not add
   a production bypass or fault-injection flag.
7. A blocked singleton-row lock honors cancellation, releases resources and can
   retry. Observe lock acquisition/wait with bounded coordination, not blind sleeps.
8. Malformed input, unavailable database, missing/pending schema and raw PostgreSQL
   errors fail closed without exposing synthetic passwords, verifiers or URL secrets.
9. Case variants of an existing login cannot create a second user through SQL;
   verify constraints for invalid roles, empty login and inconsistent markers.
