## Outcome and scope

Expose all seven existing agent-management API operations through noninteractive
CLI commands, with the same authority, optimistic versions, safe receipts and
one-time-token rules as the UI. No new backend operations, direct database access,
agent connectivity, providers, ingestion or automation-token model.

All commands require `--profile-file`, allow `--timeout` (30s default, positive,
maximum2m), and `--output=text|json`. Use explicit named flags for IDs; reject
unexpected positional arguments. Names below are the concrete implementation scope:

| Command | Additional flags |
| --- | --- |
| `agents list` | `--limit` (default50, maximum200), `--cursor` |
| `agents get` | required `--agent-id`; return exact strong ETag |
| `agents credentials list` | required `--agent-id`; limit/cursor |
| `agents create` | required `--name`, `--display-name`, `--current-password-file`, `--idempotency-key`; optional `--lifetime-seconds`; explicit token sink |
| `agents credentials rotate` | required `--agent-id`, `--if-match`, `--current-password-file`, `--idempotency-key`, `--confirm`; optional lifetime/overlap seconds; explicit token sink |
| `agents credentials revoke` | required agent/credential IDs, if-match, current-password-file, idempotency-key and confirm |
| `agents disable` | required agent ID, if-match, current-password-file, idempotency-key and confirm |

Create/rotate require exactly one of `--token-file` and `--show-token` before
dispatch. Ordinary output and errors never contain a token. With show-token, only
the deliberately requested fresh result may include it; replay always omits it.
Token files are new private regular files in a checked user-owned parent, opened
without following symlinks or overwriting existing data. Check/reserve the sink
before dispatch, atomically complete and sync the owned file, and distinguish
post-commit token-write failure from known rejection. Never automatically repeat
issuance, overwrite an existing token, or pretend a lost token is recoverable.
Only clean up artifacts created by this command. Replay may use show-token to
obtain its metadata without requiring a new output file.

## Interfaces and implementation ownership

Worker owns the entire feature: new `internal/agentclient/`, command routing and
agent commands/tests under `internal/command/`, a minimal authenticated generated-
client boundary in `internal/setupclient/`, protected token output under
`internal/secretfile/` if needed, and affected README/spec/task/testing docs.
Read directory instructions first. Do not edit backend services, storage schemas,
OpenAPI or web product code. No new dependencies or general-purpose execution tools.

Reuse `cliprofile.Open/Load/Save/Close` and `setupclient.NewSession/Context/Session`.
Hold the profile lock across fresh context, one generated API operation and any
session persistence. Preserve exact origin/CA trust and the whole deadline.
Add only the session access needed by the actual agent client: prefer a narrow
typed generated-operation interface using the existing HTTP client/cookie jar and
Origin/CSRF editor. Do not expose a raw cookie jar, arbitrary URL request API or
duplicate TLS/authentication logic. Routine private helper layout belongs to Luna;
bring any public contract or architecture conflict to the coordinator.

Generated DTOs in `internal/api/generated.go` and `api/openapi.yaml` define the
wire contract. Review `web/src/agents/client.ts` for strict response invariants,
512KiB response cap, canonical IDs, decimal int64 strings, bounded cursors and
strong ETags. Do not hand-edit generated files or trust generated decoding alone
for required fields, token discriminants, target identity or exact version rules.

One bounded page per read; no hidden auto-pagination. Send each mutation once,
with caller-owned original idempotency key and exact If-Match; no implicit fresh
version fetch or retry. Fresh passwords may change on deliberate replay without
changing semantic intent. Preserve uncertain outcomes on connection/body loss,
malformed success or server-side failure; safe errors retain valid request IDs and
bounded Retry-After. Use established exit classes, adding not-found4 where needed.
Never pass server messages, raw decoder errors, paths or secret material through
diagnostics. Text output must safely render externally supplied names.
