## Observable outcome

Noninteractive `almanac auth login`, `auth context` and `auth logout` use the same
HTTPS authentication API as the UI. A deliberately selected protected profile
persists a session for subsequent processes. No direct database access, automatic
login retry, automation-token model, default-profile discovery or credential vault.
Agent management CLI commands follow this shared authentication boundary.

Login accepts `--profile-file`, `--backend-url`, `--login`, `--password-file`,
optional `--ca-file`, `--timeout` (default30s, maximum2m), and `--output=text|json`.
Context/logout use the profile's exact origin and CA trust with the same timeout
and output options. Passwords never appear in command arguments or normal output.
Plaintext session credentials exist only in the protected profile and transport.
Profiles contain no password, role cache, CSRF cache or agent token.

Obtain fresh context/CSRF for each process. Restricted sessions remain restricted
and direct the operator to existing setup; no implicit password change. Login
must not silently replace an active profile session or log it out. Explicit
logout clears the local session only with a reported server outcome; uncertain
logout keeps recoverable local state and reports uncertainty. After a lost login
response, perform at most one bounded context reconciliation, never another login.
Persist any recovered valid session before reporting its state, but keep the
mutation outcome unknown when it cannot be established. Remote success plus local
persistence failure is not reported as success.

Use versioned JSON envelopes and established safe exit/error conventions. Never
print raw HTTP/parser/filesystem errors containing credentials or profile data.
Use the generated API operations and review existing setupclient transport,
cookie/CSRF validation and fault tests for reuse. Do not change setup semantics.
All HTTP reads and profile operations share the whole-operation cancellation and
deadline. Reject redirects, noncanonical/non-HTTPS origins and untrusted CA input.

## Profile interface and ownership

Worker owns only `internal/cliprofile/` and focused tests there. Coordinator owns
all other packages, commands, documentation and real-stack verification. Interface:

```go
type Record struct {
    SchemaVersion int    `json:"schema_version"`
    BackendURL    string `json:"backend_url"`
    CAPEM         string `json:"ca_pem"`
    Session       string `json:"session"`
}
func Open(ctx context.Context, path string, create bool) (*Locked, error)
func (l *Locked) Load() (Record, bool, error) // bool=false for absent allowed file
func (l *Locked) Save(Record) error
func (l *Locked) Close() error
```

Export fixed sentinel errors `ErrInvalid`, `ErrUnavailable`,
`ErrCommitUncertain`, `ErrUnsupported`; preserve context cancellation/deadline
identity for timeout handling. `ErrCommitUncertain` distinguishes a failure after
atomic replacement from a known pre-commit failure. No path/profile/secret content
in error strings. Close is safe to call repeatedly. Calls after Close fail safely.

The profile is strict bounded JSON, schema1, maximum96KiB. BackendURL is nonempty
UTF-8 and at most2048bytes; CA PEM at most64KiB; session is empty or bounded
ASCII cookie-safe text at most4096bytes. The HTTP client separately validates the
canonical origin, actual CA and session-cookie grammar before any network use.
Reject unknown/duplicate JSON members and invalid field types; no silent repair.

Resolve relative paths without changing process working directory. The immediate
parent must already exist, be owned by the current user, and not be writable by
group/others; it need not hide filenames from other users. Profile and lock files
must be owned regular0600 files. Reject symlink destinations, unsafe file types,
insecure modes/ownership and unbounded inputs without blocking on FIFOs/devices.
Anchor operations to a checked directory handle and revalidate opened objects;
do not rely on check-then-open paths alone. Do not create arbitrary directory trees.

Hold a bounded per-profile OS lock from Open through Close, including caller HTTP
work. Independent processes cannot interleave read/network/save and restore stale
sessions. Cancellation interrupts lock acquisition. Keep a stable lock-file inode;
do not unlink/recreate it on each unlock. Atomic saves use a private same-directory
temporary regular file, sync, atomic replacement and directory durability where
supported. Pre-replacement failures leave the existing profile unchanged. Clean
only owned temporary artifacts. Fail explicitly on platforms lacking the required
ownership/no-follow/locking guarantees; do not pretend Unix mode checks protect all
platforms. Add no dependency without coordinator review.
