## Outcome and scope

Locate the remaining cold-list delay before another application correction.
The latest full workload has cold-list p95 1,530.8 ms and no API/ingestion errors.
Loaded ingestion at 87–92 ms passes its absolute limit but fails relative isolation;
it is a secondary guardrail, not a higher priority than unusably slow lists.

Hypothesis: the synthetic historical writer materially contributes to list latency
through database/background pressure. It bypasses historical ingestion admission
and its fixed batch count produces different offered rates as processing improves.
Run one explicitly labelled no-backfill diagnostic with unchanged application,
live ingestion, 800 baseline queries, ten API clients and 80 browser journeys.
This removes work and cannot establish full-load capacity or calculation adoption.
Separately inspect retained individual browser/server traces to locate the cold
list critical path; do not subtract independently computed percentiles.

Changes are limited to the experiment harness, focused harness tests and evidence.
Default backfill stays enabled. Unknown/empty mode values fail before setup.
The omitted diagnostic must launch no backfill SQL process and record zero planned
batches and ineligibility for capacity evidence. All existing latency, due-work and
exact-value assertions remain intact. No production APIs, defaults or budgets change.
