## Outcome and non-goals

The SLO list and SLO detail match `docs/design/mocks/slo-list.html` and
`slo-detail.html` using today's API, with exact values, urgency semantics,
performance budgets and the real journey unchanged.

List: page header (title, mono summary, Updated, Refresh, New SLO), toolbar
(search with `/`, service select), triage band (clickable urgency counts plus
soonest exhaustion and not-reporting callouts for the loaded page), urgency
groups with uniform rows: status mark with a reason line, name with service and
SLI context, Target · window, budget sparkline, remaining percentage and meter,
burn 1 h with 6 h context, exhaustion, and a shared pager.

Detail: back link, title, body-font status line, mono context line, actions
(Refresh, Edit SLO, Mute disabled); a full-width status band (budget hero and
meter, reasons in words, facts, coverage) with the calculation disclosure; the
existing timeline card with its four lanes, controls and exact tables; a
definition card with facts and both queries. Edit SLO opens a dialog limited to
the display name.

Out of scope, kept in the mocks: Events lane and annotations, Mute action,
description, revision history and a separate edit page (needs a Go route change
and the revisions contract), sort control (no API sort parameter), the "+n more"
reason overflow beyond a title and screen-reader list.

## Acceptance and expected cases

- AC-11: side by side with both mocks in both themes at 360/1024/1440; recorded
  differences limited to deferred elements.
- AC-12: groups, counts, sparklines, meters and 1 h/6 h burn come from the
  overview projection; triage counts are the server group counts; filters and
  pagination keep working through the URL.
- AC-13: four lanes, reference lines, range/timezone/burn controls, exact tables
  and the status/definition content are present in the single-column layout.
- AC-14: last-known rows show Stale with their evaluation time and never a
  Healthy label; provisional, zero-traffic, no-data and not-applicable states
  keep their qualifications in the status band and lanes.
- Performance: list and detail journeys remain under the SPEC-0019 budgets on
  the real stack; evidence from the slo-journey timings and traces.

User acceptance checklist:

- Start on `/slos` with the acceptance fixture: ten SLOs across groups.
- Click the Needs attention tile → URL gains `urgency=needs_attention`, only
  that group renders, tile shows pressed; click again → cleared.
- Type `/`, search "checkout", Enter → `q=checkout`; service select → `service_id`.
- Open a row → detail: status line, band, lanes, definition; `90 d`, `Local`,
  `6 h`, table toggles and Refresh behave as before; back returns to the list.
- Edit SLO → dialog with Display name; save → title updates; Escape restores
  focus to Edit SLO.
- Invalid: empty display name → inline error, no request.
- Reference comparison: `slo-list.html` / `slo-detail.html`.
- Container deployment: the real SLO journey (`VERIFY_MODE=slo-journey`).
