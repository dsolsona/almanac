## Outcome and non-goals

The SLO detail endpoint serves graphs, daily compliance and pinned exact-value
pages from extrema rows plus live edges, with samples identical to the retained
path at the same generation. The old path still runs until F9-T04 removes it;
current status and the list are unchanged in this task.

## Interfaces and edit scope

- Migration `0045_slo_extrema.sql`: `almanac_slo_extrema` and the cursor table's
  worker columns if F9-T02 left them out; seed every SLO cursor with
  `built_through = eligible start`, `dirty_from = dirty_to = NULL`.
- Extrema worker in `RunHistory` replacing `repairRetainedSeries` turn order: claim
  cursor, build hours, build closed days, advance; ADR-0034 rules; spans named
  `slo.extrema.build` with `almanac.work.key`.
- `extremaReader` implementing the `rolling`, `attainment` and `daily` function
  signatures used by `buildSloOperationalDetail`, so the assembly code is reused.
  Mark values are turned into `api.SloOperationalSample` by evaluating the mark's
  counts with `slo.EvaluateOperationalTotals` at the endpoint time; never copy a
  stored percentage.
- `loadRetainedSloHistory` uses the extrema reader; keep pinned-payload publication
  and `ReadSloHistoryValues`; compute the pinned payload digest at insertion only.
- The API sample and detail shapes are unchanged. `history_preparation` reports
  ready/total seconds from the cursor's `built_through`.
- Allowed paths: `internal/storage/**`, `internal/slo/**` (helpers only), generated sources. No `web/` changes.

## Acceptance and expected cases

- AC-02 equivalence: on the perf seed (20 SLOs, 35 days) and on a 365-day seed,
  for each SLO and each of `7d`, `90d`, `1y`, `window`, with burn 3600 and 21600,
  the samples, `display_coverage`, `retained_extrema` labels, compliance days and
  summary from the extrema reader deep-equal those from the retained reader at
  the same generation. Run both readers in one test transaction.
- Open hour: a request at 12:07 includes endpoints 12:01 to 12:07 evaluated live;
  the 1y request evaluates at most 7,200 live endpoints and reads at most 400 extrema rows.
- Transitions: an hour with 61 state changes keeps all transitions; a lane with
  1,600 transitions across the range drops them and sets `display_coverage`.
- Ties: two endpoints with equal attainment keep the earlier one as minimum.
- Late data (AC-03): an observation 3 days back widens `dirty_to` by the window;
  after the worker runs, only hours in `[t, t+W]` have new `published_at`.
- AC-05 crash points for the extrema worker.
- AC-09: a failing cursor shows in `/preparation` with its reason; retry resets it.

User acceptance checklist:

- Starting state: seeded stack; detail page at 7d.
- Expected: identical graphs and exact tables to the previous build; range and
  burn changes under 1,000 ms, preferably 500 ms; gaps shaded as before.
- Navigation: all four periods and both burn windows; exact-value pagination.
- Container journey: `make test-e2e`; `make test-perf PERF_DAYS=35` and `PERF_DAYS=365`.
