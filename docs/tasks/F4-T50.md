## Outcome and scope

Produce canonical alert evidence for nonzero maintenance revisions through the
shared window evaluator. Current and last-breaching masks read the same present
facts in one repeatable-read transaction and share explicit work admission.
Retain actual computed mask/hour identities and compatibility proofs in immutable
evidence. No alert-only arithmetic, raw whole-window fallback, changed policy
meaning or notification delivery is introduced.

An explicit internal maintenance option connects preparation and the processor;
nil retains the existing gate pending production adoption.
Preparation returns its authenticated source scope and typed resource requests on
pending, with no partial numeric evidence. The subsequent pending-publication
transaction must capture resource pins before policy/cursor locks and atomically
enqueue/defer the original cutoff under the existing claim and authority fences.
F4-T48 supplies that queue seam. No production defaults are selected here.

## Acceptance

- A future exclusion immediately reuses proven-compatible revision-zero counts;
  actual computed zero and requested nonzero provenance remain distinguishable.
- A relevant compiled mask produces exact eligible counts through shared math;
  a missing mask/hour stays pending at the original cutoff with executable work.
- An open acknowledged occurrence retains acknowledgement across exclusions.
  Current clear evidence compares the last breaching mask using the same present
  facts; ordinary recovery and maintenance-related recovery remain distinct.
- Unavailable, fully excluded, stale and incomplete populations cannot manufacture
  recovery. Exhausted source work remains per-window calculation-failed evidence,
  preserving usable independent conditions.
- Source/definition/exclusion/claim changes fence publication. Enqueue failure or
  rollback cannot release a parent as though its preparation requests were saved.
- Legacy evidence and zero-revision processing remain compatible. No worker is
  registered before normal-deployment, correctness and 100/200-policy gates.
