## Outcome and boundaries

`almanac db upgrade` upgrades an explicitly selected PostgreSQL database using
embedded ordered SQL. A first migration establishes installation identity and
credential epoch; no accounts, credentials, observations or tenant records are
created. Backend/alert modes remain unsupported. Serving never runs migrations.
This establishes real persistence verification, not backend readiness or onboarding.

Use pgx/v5 and generated sqlc metadata queries as the accepted ADR specifies.
Implement a small adapter for transactional, forward-only SQL; no additional
migration framework or DSL. Restrict this first runner to transactional migrations.
The coordinator selected this implementation detail to keep the existing dependency
boundary; revisit an additional package through an ADR if requirements exceed it.

## CLI and connection contract

- Add `almanac db upgrade [--database-url-file=FILE] [--timeout=30s]
  [--output=json]`. Missing/unknown subcommands, flags and positional arguments
  return exit2. Default output is a concise human result; JSON is a single document
  with schema_version1, operation `db.upgrade`, database_schema_version and applied
  count. A repeated upgrade reports applied0 and preserves identity.
- Connection source precedence: explicit `--database-url-file`, then
  ALMANAC_DATABASE_URL_FILE, then ALMANAC_DATABASE_URL. An explicitly empty selected
  source is invalid, not fallback. A selected file contains a connection URL,
  at most16KiB, with surrounding whitespace trimmed. Require a regular file with
  no group/other permission bits; report a safe field error if invalid. No URL
  flag, password prompt or connection-string logging. The raw environment option
  is intended for local automation; document protected files for deployment.
- Reject unsupported URL schemes/missing database before I/O; pgx parses the
  remaining connection parameters. Preserve TLS verification settings. Default
  command deadline30s, positive and at most2m; cancellation propagates through
  connect, lock acquisition and SQL. Exit0 success,2 configuration,6 cancellation/
  timeout,1 database/compatibility failure. JSON failures contain schema_version1,
  operation and error {code,message}; stdout has exactly one result document,
  diagnostics stay on stderr. Errors never expose URL/password/SQL contents.

## Schema and migration invariants

- Own persistence code in internal/storage/. Embed bootstrap metadata SQL and
  migrations; filenames have positive contiguous numeric versions starting1.
  Reject malformed/duplicate/gapped inputs before connecting. Applied SQL becomes
  immutable; record version, filename, SHA-256 checksum and applied_at.
- Hold one advisory session lock on a dedicated pgx connection across inspection
  and the upgrade. Choose one documented constant key for Almanac, not a per-user
  or tenant key. Always release the lock by explicit unlock/connection close on
  success, error and cancellation; no pooled session may retain it.
- Bootstrap the schema-history table only inside the locked administrative path.
  Each migration and its history record commit in the same transaction. Reject
  altered/missing applied migrations and database versions newer than this binary.
  No automatic rollback/down command, schema creation per user or startup DDL.
- First application migration creates one singleton installation record:
  installation_id UUID, credential_epoch UUID, created_at timestamptz. Generate
  initial UUIDs using PostgreSQL's built-in generator; repeated upgrade never
  changes them. This is metadata only, not credential issuance or recovery.
- Expose a read-only compatibility check for future backend readiness. It must
  distinguish missing/pending/current/newer/inconsistent history without changing
  schema. Do not enable backend mode just to consume it in this task.
- Use UTC connections, bounded connection/statement/lock waits and cancellation.
  SQL values are parameters; identifiers and migration SQL come only from embedded
  trusted sources. Typed metadata queries come from sqlc; never edit generated Go.

## Verification and carried review findings

Prove empty-to-current upgrade, idempotence and preserved identity; two concurrent
upgraders apply once; deliberately failing transactional SQL leaves neither its
DDL nor history; changed checksum/newer schema are rejected; cancelled lock wait
and failed migration release resources. Use bounded deadlines and unconditional
cleanup of blocker connections. Exercise connection precedence, protected files,
redaction and real command outputs; decode JSON rather than count braces.
