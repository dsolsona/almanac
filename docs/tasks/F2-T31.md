## User acceptance

- Run `make agent` with a registered credential, collect data, stop with Ctrl-C,
  and immediately run the same command with the same credential. It connects and
  collects without waiting for the old one-hour lease or requiring a new token.
- Repeat after killing the agent container/process and after restarting the backend.
  Use the same agent and datasource; preserve accepted observations and their cursor.
- Start a replacement while the prior process is connected. The replacement succeeds,
  the old process reports that it was replaced and exits, and only the replacement
  can save data. No automatic takeover loop or hidden invalid-credential retry.
- Invalid/revoked/expired/disabled credentials remain denied. An incompatible hello
  cannot replace an owner. Delayed old hello/resume/heartbeat/results cannot reclaim
  authority or change accepted observations.
- User-visible launcher text accurately describes replacement and cancellation;
  remove the instruction to wait for a previous lease. Never expose credentials.
- Reproduce the reported normal-container path in the isolated Compose fixture;
  do not substitute mocked UI evidence or use the operator's agent/token/database.

Keep existing hello envelopes: generation 0 with a fresh unpredictable proof means
new process; positive generation means same-process resume. Under the existing
per-agent transaction lock, current-proof replay returns the same valid generation;
superseded proof is terminally denied; a never-used proof acquires latest+1 immediately.
Use an indexed lookup of retained per-agent proof history to fence delayed generation-0
hellos. A nonunique history lookup index avoids rejecting existing history on upgrade;
do not rely on chance uniqueness or scan all history per heartbeat. Retain current
expired-proof rejection, clock monotonicity, generation exhaustion and auth checks.
Regenerate SQL outputs from queries using pinned sqlc. If adding migration 0017,
update schema expectations and preserve gap=current+2 versus future=current+1 fixtures.

Publish sessions atomically by identity with monotonic generation. A later-completing
older handshake must not replace a newer registry entry, including after the newer
connection disappears. Remove only the exact control that owned an entry. Route
configuration/diagnostics to the current generation, and close superseded connected
controls using an actionable terminal reason. Define current-generation reconnect
replacement consistently; do not hold registry locks during network writes/close.
Current backend is single-active; durable generation validation remains authoritative.

Classify the replacement/fencing close in both handshake and established-session
read paths. A fenced client cancels/drains its own work and exits without resetting
generation or proof. Bound shutdown and propagate cancellation. Do not turn network
loss into replacement, or revoke offline execution on ordinary disconnect.
Intentional replacement prints a clear stopping message and exits zero; the launcher
must not present it as a credential failure. Keep genuine start failures nonzero,
and cover both terminal message and process status in real executable acceptance.

Validate existing ingestion/diagnostic current-generation checks rather than relaxing
them. Keep historical grant evidence and accepted observations. Replacement grant
starts now; do not backdate grants to accept old results. Persisted collection cursor
prevents deliberate duplicates; an uncommitted old attempt must not advance it.
Datasource reassignment and definition changes retain their separate drain semantics.
