## Outcome and non-goals

`scripts/verify.py` is the one verification script. It owns the mode table
(`ordinary`, `unit`, `browser`, `go`, `go-race`, `auth-bench`, `integration`,
`performance`, `journey`, `compose`, `providers`, `smoke`), the selector
validation, the fixture identity and its live check, the dependency-based
integration case selection with per-case pass reuse, the source-bound
receipts, the task budgets (`init`, `report`, `handoff`) and the timing
ledger. Every receipt and integration report records the platform: OS,
architecture, Python, the dev image id and the Git revision with a dirty
flag; the ledger shows them. The integration runner no longer needs a Make
target: it runs the preflights, the fixture check and the build itself. The
tooling tests (`scripts/tests/test_verify.py`) run as the last step of the
ordinary gate instead of a separate mode.

The Makefile is thin at the top: `make verify [MODE=…]` enters the dev
container from the host (or runs the script directly when already inside)
and `make shell [CMD=…]` uses the same entry; `VERIFY_MODE` stays accepted as
an alias of `MODE` until the command catalog is re-approved (F7-T04). The
check recipes themselves (`_verify_web`, `_verify_go`, `_verify_go_race`,
`_verify_auth_bench`, `_verify_journey`, `_verify_performance`, the generated
and smoke checks) stay in the Makefile where they were readable before; the
retired `_verify_integration` and `_verify_go_portability` recipes are gone.

`MODE=compose` and `MODE=providers` run from the dev container through the
host daemon: `compose.dev.socket.yaml` adds the daemon socket (with the
socket's group), the checkout at its host path and the daemon host's
network, and the dev image carries the pinned Docker CLI, Compose and buildx
packages. With the host network the deployment under test is reachable at
`localhost:18086` exactly as before, so the Compose verifier, its
certificate (`localhost`, `127.0.0.1`) and its port-occupancy checks are
unchanged; ADR-0029 decision 6 is amended accordingly (the stack-network
alias design was not needed).

Deleted: `scripts/verification-controls.py`, `scripts/integration-runner.py`,
`scripts/select-integration-tests.py`, `scripts/summarize-integration-tests.py`,
`scripts/setup-database.sh`, `scripts/verify-linux.sh`, `deploy/verification/`
and the two previous tooling test files. The task-specific modes (`slo-unit`,
`slo-integration`, `slo-journey`, `agent-lifecycle`, `verification-tools`,
`linux`, `linux-sli`, `go-portability`) no longer exist; their selections are
`unit`/`integration INTEGRATION_TEST=…`/`journey BROWSER_SCENARIO=…`.

Not in this task: the documentation rewrite and the command catalog
(F7-T04); the Linux-host evidence; the controlled performance entry's run.

## Acceptance and expected cases

- Inside the dev container, every mode except `performance` passes on this
  host through `make verify MODE=…` from the host: ordinary (with the
  tooling tests), unit, go-race, auth-bench, smoke, integration, journey,
  browser, providers and compose.
- `make verify MODE=compose` runs the four Compose checks from the
  container through the host socket and leaves no owned resources behind.
- A receipt records `platform.os`, `platform.arch`, `platform.image_id`
  and `platform.git_revision`.
- `compose` and `providers` refuse to run without the socket; unknown
  modes, escaped `TEST_FILE` values and unknown journeys fail before any
  command runs (tooling tests).
- `python3 scripts/check-image-pins.py` covers exactly the three
  Dockerfiles and the two Compose files.

## Implementation evidence

- Candidate: working tree on `3bdfbe6` (committed as the next revision); host
  macOS arm64, Colima 8 CPU/16 GiB, Docker CLI 29.0.0 and Compose 2.40.3
  inside the dev image; every mode entered from the host with
  `make verify MODE=…`.
- Green from the host: ordinary 28.1 s (362 web, 509 Go, 31 tooling cases,
  build, generated drift, smoke), unit 13.2 s, go-race 4.3 s (Go reported
  every package `(cached)` from the earlier in-container run; the target has
  no `-count=1`, as before), auth-bench 1.8 s, smoke 1.6 s, journey `slis`
  30.9 s, providers 16.2 s through the socket overlay, browser 126 cases in
  1 min 21 s, integration 173 executed, 0 failed in 14 min 13 s. Receipts
  record `platform` (for example `linux/aarch64 3bdfbe61f35a+`) and the
  ledger shows it per run.
- First attempts that failed and were fixed: integration discovery raised on
  `agentcmd`, which has no integration cases (the previous runner only
  validated storage and command; restored); the launcher fixtures' fake
  Docker lacked the `image inspect` call the F7-T01 launcher makes
  (`scripts/local-agent-tty-test.py`, `web/scripts/check-local-agent.mjs`);
  the browser matrix failed once with `EACCES` writing a Playwright trace
  file on the bind mount (all artifacts are owned by the dev user; passed on
  the rerun, cause not established); `make stop` from F7-T02 also ran
  `compose down` on the dev file, and Compose tears a project down by name
  when the named file is missing, which removed the Compose verifier's own
  project inside its build context (now `make stop-dev`).
- Compose mode (`MODE=compose`), four attempts, no owned containers or
  volumes left behind by any of them:
  1. failed in the launcher TTY test (fake Docker, above);
  2. failed at "daily start after port released" (`make stop`, above);
  3. 6 min 8 s, failed at the tracing stage: the slowest enabled `sli.list`
     sample's trace (`.local/compose-check-1PJeOS/network-0ms/`
     `container-trace-sli.list-0.json`) held 44 backend spans and no
     browser spans after 40 s of lookups. The verifier closes each sample's
     tab within milliseconds of ready; only `first` samples flushed the
     browser exporter explicitly, the rest relied on the page-hide flush
     winning that race (a user keeps the same tab, so the outbox replays
     for them). `web/scripts/check-telemetry-runtime.mjs` now flushes every
     enabled sample before closing its tab; the measurement is taken before
     the flush, so no budget changes. The 100 ms cohort of the same run
     passed.
  4. 56 min 35 s, failed environmentally before the verifier fix was
     applied: a 35-minute stall between the SLI journey and the tracing
     stage, then 5 s page loads that missed the SLO detail lanes. At that
     time the Mac data volume was at 100 % (3.9 GiB free), the host had
     about 60 MiB of free memory while the Colima VM holds 16 GiB, and the
     VM's Docker disk held 58.6 GB of images of which 56 GB were unused
     (other projects) plus 9.9 GB of build cache. Not rerun under those
     conditions.
  5. 6 min 47 s on the recovered host (Docker images pruned to 8 GB, build
     cache cleared, 60.8 GiB trimmed back to the Mac, Colima restarted): every
     stage up to the tracing comparison passes and every container trace is
     now connected in both cohorts, with no page over budget (maxima 234 ms
     and 626 ms). The run fails the verifier's 5 % p95 tracing-overhead
     allowance: enabled versus disabled p95 for `sli.list` is +9.8 % at 0 ms
     added latency and +7.9 % at 100 ms, `slo.detail` +6.3 % at 0 ms
     (`.local/compose-check-CWsF8P/network-*/telemetry-runtime.json`).
     Attempt 3 had already measured +9.6 % for `sli.list` at 0 ms before its
     own failure. Inside the VM the pages load faster than from the host
     (`sli.list` p95 around 135 ms disabled), so the roughly constant cost of
     tracing is a larger fraction; the allowance is a product budget and is
     not changed here. Receipt `1793872… compose failed` carries the
     platform record `linux/aarch64 8cfee7630dd0`.
- Remaining: the maintainer's decision on the overhead allowance under the
  faster in-VM measurement (keep, add an absolute floor, or accept the
  measured values), then a green Compose run; the Linux-host evidence; the
  performance entry (not run).
