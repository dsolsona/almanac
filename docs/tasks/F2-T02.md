Proof is trusted in-process output of the future application service's throttled
current-password verification, never decoded from HTTP. This storage task doesn't
claim to verify a password. It must revalidate proof binding and current database
authority atomically with its write. `Now` must be present and called AFTER acquiring
authorization locks so lock waits cannot use stale time. Accept nonzero returned
times and VerifiedAt in any zone/precision, then normalize UTC/microseconds internally.
Reject zero/backwards or >=VerifiedAt+30s proof, matching the existing service bound.
Service must create VerifiedAt after proof succeeds, no reusable public proof token.

Errors: reuse ErrInvalidSession for invalid authentication; new ErrAgentForbidden
for valid but nonadmin/restricted sessions, ErrInvalidAgentInput for malformed fields,
ErrAgentConflict for name/credential collision or receipt/body conflict. Errors must
not contain input names, credential data, SQL or database details. Preserve cancellation.

Validation: Name ASCII lowercase slug `[a-z][a-z0-9-]{0,62}`; DisplayName valid UTF8,
1..256 bytes with no control characters; preserve exact text (no trim transform).
CredentialID/UserID/epoch canonical UUID. Lifetime zero=>90*24h, otherwise whole
seconds >0 and <=365*24h. IdempotencyKey mandatory1..128 printable ASCII characters
33..126, requestID existing rules. No caller-supplied actor role. Candidate credential
verifier is a fixed32-byte SHA256 value; storage never receives the plaintext secret.

Schema: almanac_agents with UUID default, unique immutable name, display_name,
enabled, version positive bigint default1, created_at/updated_at. almanac_agent_credentials
with public UUID id, FKagent, verifier bytea32, credential_epoch UUID, issued_at,
expires_at>issued_at, revoked_at nullable. Appropriate FK/indexes; no token retrieval.
almanac_management_receipts actor_id FKuser, operation, key, digest32, result jsonb,
created_at/expires_at, unique(actor_id,operation,key), expiry index. Safe result only
AgentCreation metadata without Replayed and without verifier. Fixed operation agent.create.
Do not modify existing migrations. Generate dbgen from query source.

Transaction sequence: validate fields outside locks; connect current schema; identify
session's user by verifier; Begin with bounds; lock installation, user, session using
existing lock order; validate invalidSessionState plus enabled Administrator,
onboarding complete and nonrestricted, proof UserID/epoch/revision equality, proof
timing. No touch of session on rejected input/authz. User lock serializes same-actor
receipt commands. Check receipt key after current authorization. At now>=receipt expiry,
delete only expired matching receipt and treat request fresh. Valid matching digest
returns recorded safe result with Replayed=true; different digest=>ErrAgentConflict.
Digest is SHA256 of fixed-order versioned JSON semantic tuple name/displayName/
normalized lifetime seconds; exclude proof, candidatecredentialID/verifier, requestID,
currenttime and computedexpiry. Same omitted/default lifetime must match.
Fresh request inserts enabledagent/version1, itscredential bound to currentepoch,
two success audits agent.created + agent.credential.issued with user actor,
agent/credential respective subjectUUID and supplied requestID. Insert safe receipt
expires completion time+24h. Sample Now a second time immediately before receipt insertion,
require nonzero and nondecreasing relative to authorization time (fixed clocks valid),
recheck proof/session expiry at that time, then commit, then return Replayed=false. No success
or candidate token after commit error. A failed audit/receipt rolls everything back.
On Replayed=true the future service MUST discard any newly generated candidate secret;
never associate that unused secret with recorded credential metadata. Lost output
requires explicit replacement issuance, never retrieval.
Future rotate/revoke/disable are deliberately separate tasks and cannot be exposed yet.

## Coordinator acceptance

Implemented guarded registration, verifier-only credential storage, atomic success
audit and actor-scoped safe receipts. The application service, HTTP/CLI/UI and
credential lifecycle are not exposed by this task.

Full verification passes 73 web and 105 Go unit tests, generated-code consistency,
build and process checks. The real PostgreSQL integration lane passes 75 tests,
including nine agent-registration tests covering authority denials, concurrent
receipts, exact expiry, audit/receipt rollback, and observed lock ordering against
logout and password changes. Existing browser authentication journeys also pass.
Independent task review approves the final code and tests.

First failures were retained and corrected: stale migration-count/future-schema
fixtures, an original-versus-replay verifier assertion, and a database timestamp
assertion that confused client display location with stored instant. The session
expiry race now keeps password proof fresh so it independently checks session
validity after waiting for a lock. These are test corrections, not relaxed product
authority or receipt guarantees. Worker unit results alone were not accepted as
evidence for transactional behavior.
