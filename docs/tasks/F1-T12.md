## Outcome and scope

Connect existing password policy, hashing, initial-owner persistence, shared login
admission, sessions and password rotation into one backend application service.
Demonstrate real bootstrap→restricted login→permanent password→normal session→logout.
This task does not expose HTTP, cookies/CSRF, runtime configuration, UI or CLI. Those
must use this service in the next delivery; Google, tokens and recovery stay deferred.

Own `internal/authentication/`, a small shared `internal/secretfile/` adapter, the
existing command secret-file caller/tests where extraction requires changes, and
an integration-tagged `internal/testpostgres/` fixture helper. Extract only reusable
database lifecycle from storage integration helpers and keep all acceptance tests.
Update fixed Makefile package selections for these actual tests. No migrations,
dependencies, password parameters or public API contracts. Coordinator owns docs/Git.

Constructor validates database URL and nonnil clock, creates one shared bounded
PasswordHasher and one supported dummy verifier from random input. No database
mutation or plaintext dummy persistence. A private Hash/Verify interface is allowed
for meaningful comparable-work unit tests; real integration uses the real hasher.
Never add a public bypass/test mode. Every public operation caps its context at
30seconds, respecting earlier caller cancellation. No detached authentication work.
Read the supplied clock at each stage after expensive work; never reuse a start
timestamp to authorize expired work. The clock must be safe for concurrent callers.

Validate RequestID as nonempty UTF-8 at most128bytes, and login as nonempty UTF-8
at most256bytes. Candidate passwords allow0–128 Unicode codepoints, at most512bytes,
valid UTF-8: wrong short passwords still undergo verification. New passwords use
the full existing ValidateNewPassword policy, including the common-password list.
If exposing identity's existing candidate validator avoids duplicating bounds,
allow that small named helper without changing Hash/Verify semantics or parameters.
Source validation/canonicalization follows F1-T11 before database mutation.

Map rejected authentication/authority to ErrUnauthenticated without identity details.
Return a typed RateLimitError when Begin denies admission, with its exact positive
retry duration. Finish=false after an otherwise valid password proof returns
ErrAttemptExpired and never creates a session. Preserve safe operational/context
errors as failures; do not turn DB outages into credential denial or success.
Policy errors may use existing identity sentinels; error strings never contain
passwords, verifiers, session secrets, URLs, file contents or credential-bearing
input structs. Do not log inside this service.

## Bootstrap and protected files

EnsureInitialOwner first reads persisted state. If already provisioned, return
Created=false and that state without reading/validating login or password-file
configuration, even while onboarding is pending. DB/schema failure returns first.
Otherwise require valid login/RequestID and a protected password file, validate the
complete new-password policy, hash outside locks and call ProvisionInitialOwner
with a fresh time. Its transaction still decides the concurrent winner. Missing or
unreadable/unsafe files return ErrInitialCredentials, without path/content details.

Extract actual common file mechanics into `secretfile.Read(path string, maxBytes int64)
([]byte,error)`: regular file, no group/other permission bits, bounded read and safe
errors. Accept only maxBytes1..16384, read at most maxBytes+1 and reject oversize.
Preserve the existing Unix nonblocking opener so FIFOs cannot hang; inspect the
opened symlink target. Retain platform fallback behavior and existing command tests.
The URL caller still trims URL whitespace; the password caller uses exact bytes,
including leading/trailing spaces/newlines, and a512byte limit. No password from
environment, arguments or logs is introduced by this service.

## Login and rotation

Login validates bounded input, reserves shared account/source admission and reads
the local snapshot. Perform exactly one Verify: use its supported local verifier
for an enabled local user, otherwise dummy for unknown/disabled/null/unsupported
verifier cases. Those paths all return generic rejection after the same work.
Do not apply the new-password denylist to existing password verification.

On completed bad proof, Finish(false) with fresh time, then deny. On completed good
proof, Finish(true) with fresh time must succeed before proceeding. Any error or
expired completion grants nothing; a cancelled/operationally failed check may leave
only the bounded pending reservation, never fabricate a failed password result.
Generate a fresh random secret/digest and call IssueSession with captured user ID,
revision/epoch and fresh time. Return its access plus raw secret only after commit.
If issuance races credential changes, map its rejected authority to generic denial.

ChangePassword strictly parses and authenticates the current secret, then reads the
local snapshot for that session user. Use the same shared admission/proof mechanism
for the current password, including comparable dummy work and fresh completion time.
On good proof require different plaintext and complete new-password policy, hash
outside locks and call RotateLocalPassword with the original session digest,
captured revision/epoch, fresh replacement digest and current time. The storage
transaction rechecks authority; a role/revision/epoch/session change cannot bypass it.
Return a new secret only after commit. New-policy failure does not count as a failed
current-password proof. Other sessions and the old password fail after success.

Authenticate uses strict secret decoding and current storage authority. Logout is
idempotent: malformed/unknown/already revoked secrets return false,nil; valid input
uses RevokeSession with fresh time. Invalid RequestID still returns ErrInvalidInput.
The transport must later clear cookies and enforce CSRF independently.

the combined packages serially (`-p=1`) so only one fixture runner operates at once.
Keep zero-test guards, PG18.6 fixture checks, SQLC drift/build checks and2minute budget;
no arbitrary passthrough compiler/helper flags.

1. Real PG bootstrap with protected file creates one owner and safe audits;
   concurrent/repeated calls preserve the winner, including removed/changed file
   while onboarding is pending and after completion. Missing/unsafe/weak/common
   password input leaves no owner. Exact whitespace survives verification.
2. Real login yields restricted session, different permanent password completes
   onboarding, fresh session authenticates normally, old password and every old
   session fail; logout denies its old secret. Ordinary rotation also works.
3. Unit comparable-work checks count one Verify for known bad, unknown, disabled,
   null/unsupported verifier paths. Real-PG cases prove no session issued; bounded
   malformed input is consistent. Responses/logs/JSON omit synthetic secrets.
4. Real shared account/source limits and retry duration apply to login and current
   password proof. Existing failures survive successful proof. No local fallback.
5. Advance clock past admission lease during a successful proof and assert no
   session; mutate revision/epoch during proof and assert issuance/rotation denial.
   Use deterministic controlled work, not timing guesses or weakened storage checks.
6. New plaintext equality, common/invalid passwords and wrong current password
   cannot mutate credentials; new policy is not applied to checking an existing
   password. Verify all old sessions invalidate only after successful rotation.
7. Cancellation/DB/schema failures produce no usable output, remain bounded and
   redact secrets. Constructor/shared hasher initialization is concurrency-safe.
8. Protected file extraction preserves URL behavior, regular/mode/symlink/FIFO and
   byte-limit cases. Full existing storage/unit/race gates still pass after extraction.
