## Outcome and edit scope

Add an unwired `internal/alert` domain with no database, scheduler, public API or
external dependencies. All time and evidence are explicit inputs. Define concrete
consumer types for policy conditions, canonical window evidence, evaluation
outcomes, open occurrence state and transition actions. Storage will own UUIDs,
claims, snapshots, expected versions and atomic persistence in the next increment.

Validation accepts explicit caller limits rather than silently inventing public
condition-count, threshold precision or body-size defaults. Preserve support for
more than two conditions and deduplicate window durations only as an input reuse
optimization. Exact decimal strings and cross multiplication decide thresholds;
formatted burn values never do. Reject inconsistent evidence instead of fabricating
an unavailable or clear result. Pending work cannot be passed as condition truth.

  143 bad events in either does not. Include fractional counts, exact equality

- Both windows in one condition must match; any matching condition breaches.
  All not matching clears. No matching plus any unavailable is indeterminate.
  A matching fast condition plus unavailable sustained evidence can breach;
  pending calculation defers outside this pure domain.
- Require full configured windows, complete fresh positive eligible traffic;
  preserve distinct missing, partial, stale, zero-traffic, warmup, excluded and
  terminal calculation-failure reasons. Never substitute zero for absent counts.
- Validate positive finite reachable thresholds, ordered minute/cadence-aligned
  windows within 30 days, stable unique condition IDs and coherent cutoff/bounds.
  Include three conditions with shared and distinct window durations.
- Breach opens; continued breach/condition handoff preserves occurrence identity;
  indeterminate preserves firing/acknowledged state; clear resolves. Normal is
  absence of an open occurrence. Terminal occurrences never reopen.
- Acknowledgement is global, preserves the first actor/time, and cannot apply to
  terminal state. Disable/supersede/archive actions retain distinct terminal causes
  without claiming measured recovery. Timeout, notes and assignment are deferred.
- Functions do not mutate caller-owned evidence, policy slices or occurrence state.

## Implemented evidence and limits

The unwired `internal/alert` package evaluates exact decimal counts and returns all
condition evidence. Full-window validity and retention, distinct unavailable
qualities, shared windows and six distinct windows are covered. Its reducer
preserves occurrence identity, first global acknowledgement, indeterminate state
and terminal immutability. Storage assigns IDs and owns durable fences/replay.

Initial decision and lifecycle RED runs fail to compile against their absent
domain types/functions; the implemented decision selection passes in 1.017 s and
the initial complete core in 1.020 s under race. An exploratory leading-zero
decimal case already passed; no existing numeric defect is claimed from it.

Independent read-only review finds three defects: numeric calculation-version
identity disagrees with canonical `occurrences-operational-v1`; administrative
effective/detection clocks are collapsed; maintenance-caused recovery is lost.
The review correction tests first fail against the missing string identity,
separate-clock interface and recovery comparison. The corrected core passes
in 1.022 s. Final `go test -json -race ./internal/alert -count=1` passes all
50 test/subtest cases in 1.024 s after the unknown-maintenance fixture is changed
to use a real Evaluate result rather than manually relabelling its snapshot.

Maintenance recovery compares current facts under current and last-breaching
exclusion revisions. Source generation, cutoff, definitions and calculation
version must agree; differing facts are rejected. A revision change alone is not
causal proof. An old-mask clear result retains ordinary recovery; old-mask breach
or indeterminate means maintenance enabled recovery. The last breaching snapshot
survives intermediate indeterminate evaluations. The future calculator adapter
must admit both populations together and preserve pending work when comparison
cannot complete; it cannot label a recovery from an incomplete comparison.

Caller limits remain explicit test inputs, not adopted public defaults. Runtime,

and integrated 100/200-policy performance are unrun and unimplemented here.
