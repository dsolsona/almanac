## Outcome and scope

Implement durable, authenticated ownership acquisition, same-process resume and
renewal for one agent identity. A copied agent credential alone cannot silently
replace an unexpired owner. Backend restarts retain exclusion evidence. This is the
ownership prerequisite for the connected-agent runtime, not a healthy-collector
claim or permission to execute SLI work.

No WebSocket dependency or endpoint, provider query, datasource reassignment,
ingestion or force-takeover management operation in this increment. Those remain
required connected-agent/datasource work. Do not implement a blanket execution
grant: config and measurement-revision authorization must still be checked by the
future execution-grant operation. Ownership authority alone never authorizes queries.

## State and internal operation contracts

Add an append-only migration following0008 and typed SQL. Store one current owner
per agent, a positive int64 ownership generation, resume-secret verifier, acquisition
time, latest successful renewal time and authority expiry. Preserve superseded owner
records for fencing/history rather than silently overwriting their generation.
Use one-hour maximum ownership validity; future execution grants must not outlive
this authority. Heartbeat reachability remains an independent later runtime signal.

Provide three internal operations with small explicit input/result types:

- **Acquire:** authenticate the current agent credential inside the transaction.
  The live process supplies a newly generated random256-bit resume secret before
  its first attempt and keeps it only in memory. Persist its verifier, never the
  secret. With no unexpired owner, allocate the next generation and commit its
  bounded authority. With an unexpired different resume verifier, return conflict
  and the earliest normal replacement time. The same secret after a lost response
  recovers the existing generation without creating another owner or extending
  expiry merely by replaying acquisition. Reject expired-generation resume as a
  renewal; acquiring a replacement after expiry allocates a fresh generation.
- **Resume:** current credential plus matching generation and resume secret prove
  the same live process. Return the existing owner without extending expiry. A
  newly rotated valid credential for the same identity may resume; a token for
  another identity cannot. Mismatched secret/generation or expired authority denies.
- **Renew:** reauthenticate current credential, require current generation/resume
  proof and a fresh random256-bit request nonce. Commit a new bounded validity and
  return the nonce, server issue time and expiry. Same-nonce replay returns its
  original recorded grant bounds, never an extension. Older/fenced generations and
  expired authority cannot renew. Store enough bounded renewal evidence to reject
  old nonces without unbounded growth; retain the current nonce and reject a replay
  of a prior renewal using an explicit monotonically increasing renewal sequence.
  The client supplies its expected sequence, and the transaction advances once.

For acquire/renew, expiry is at most server-now plus one hour and at most the current
credential's effective expiry/retirement. Never shorten already issued authority
silently on credential rotation; deny renewal that cannot preserve safe bounds and
require a valid replacement credential. Revocation denies new operations immediately;
it does not claim to stop disconnected external queries. Historical authority stays
recorded. Exact expiry boundaries deny resume/renew and permit normal replacement.

Generation/sequence exhaustion fails closed instead of wrapping. All IDs and counters
are exact; validation rejects invalid IDs, empty/incorrect-size proof or nonce,
zero/backward clock, and inconsistent chronology. Secrets/verifiers never appear in
errors, audit payloads or JSON results. Results expose only safe identity, generation,
sequence, nonce correlation and validity metadata; nonce is not an auth credential.

## Transaction and implementation boundaries

Use `internal/agentownership/` for the small application service, storage files and
queries named `agent_ownership`, and generated dbgen output. Reuse strict token
parsing. Refactor F2-T12's private transaction-local credential validation only as
needed to perform authentication and ownership changes under the same locks. Do not
authenticate in a completed transaction and then trust that snapshot for a write.
Preserve installation -> agent -> credential -> ownership lock order; installation
currently uses FOR SHARE. Sample time after authority locks and before committing
an authority extension. Bound cancellation, SQL statements and cleanup.

Routine internal method/constructor names are Luna's choice; report their final
signatures. Do not introduce a general transaction framework or new dependency.
Coordinator implementation choice: caller-generated ephemeral resume secret makes
lost initial responses recoverable without storing plaintext or granting a copied
credential the previous process's ownership. This implements the accepted
unpredictable generation-bound resume proof; no persistent agent resume file.
