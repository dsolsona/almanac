## Outcome and boundaries

Implement the accepted small Tink adapter and protected keyset loader needed by
datasource persistence. This is independent of agent transport. It is not complete
datasource secret management: persistence, authorized release, resumable rotation,
operator commands and restore acceptance follow with their actual consumers.
Do not create public commands, management routes, database tables or new readiness
behavior in this task. No standalone publication merely for this internal layer.

## Interfaces and scope

Own `internal/sourcesecret/` and its tests. Define a small explicit binding type
containing installation/resource IDs, resource kind, field and secret revision;
an envelope with the exact ADR format/keyset/key identifiers and ciphertext; and
loader/encrypt/decrypt operations. Keep caller-supplied trusted binding distinct
from untrusted envelope metadata. Follow the ADR's fixed-order associated data,
size limits, canonical identifiers, TINK prefix consistency, AES256GCM-only keys,
primary/ID/count rules and owner-only regular-file loading. Reuse reviewed protected
file utilities without changing other credential consumers. No secret-bearing errors.

Pin approved Tink Go v2.8.0; inspect resolved graph and licenses. Dependency files
may change on this isolated branch, but coordinate integration with the WebSocket
dependency branch. Any setup changes must be narrowly fixed-purpose, using existing
approved operations. Do not add a generic shell or argument passthrough target.

Encrypt new data with the primary and decrypt using retained keys. Absent secret
is represented by the caller, not conflated with explicitly empty plaintext. This
adapter does not remove keys, provision deployment files, enforce authorization,
reserve cryptographic usage budgets or claim database rotation complete.

## Acceptance and verification

- Round trip empty and maximum-size fields; reject oversized plaintext/envelopes.
- Tampering with ciphertext or any binding field fails closed. Swapping resources,
  installation, field, revision or envelope header cannot decrypt successfully.
- Mixed retained keys decrypt old ciphertext; new encryption uses the primary.
  Missing, duplicate, disabled-primary, unsupported and oversized keysets fail.
- Protected-file checks reject permissive modes/nonregular files and bound reads.
- Errors and public result formatting do not reveal plaintext, key material or
  raw malformed input. No plaintext fallback or implicit key generation.
- Read Modern Go guidance before edits. Use deterministic focused tests, then the
  exact full verification gate after coordinating shared port 5199.

Use only [recorded approved commands](../commands.md). `make setup` prepares tools;
`make generate GENERATE_MODE=go-guidelines` and `make generate GENERATE_MODE=format`
are approved. The full gate is
`/usr/bin/bash -c 'make verify > .local/full-verification.log 2>&1'`.
Do not invent new selectors, wrappers, direct compiler/formatter commands or
approval requests. Report unavailable operations and continue independent work.
No worker commit, push, Crit, subagents or contract changes.
