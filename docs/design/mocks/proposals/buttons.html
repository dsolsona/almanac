Button roles

The design guide lists five variants but not when to use them, so every action defaulted to outline. A button's look should say what it does. The rules below use only existing tokens.

Role
Looks like
Use it for
Primary
The one action the page exists for: create on a list, save on a form, the main action on a detail page. At most one per view. Dialogs: the confirming action.
Secondary
Other safe actions that change or open something: Test connection, Edit, How to run, Cancel next to a primary.
Quiet (ghost, icon)
Utility actions that never change data: Refresh, Copy, Show more, overflow ⋯. Icon-only buttons always have a label and a tooltip.
Inline (link)
Per-row and in-text actions where a full button would dominate the row: Change in a picker summary, Revoke on a credential row. Danger colour when destructive.
Destructive
Starting a destructive action (Disable…, Delete…, Revoke all…). Ends with "…" because it opens a confirmation. Grouped in a danger zone at the end of a detail page.
Confirm destructive
Only inside the confirmation dialog, naming the object. The only filled red button in the product.
Selected
Pressed state of a segmented control, chip or view toggle (teal), never an action.

Proposal for the design guide

  • Add a "Button roles" section with the table above; map roles to the existing Button variants (primary, outline as secondary, ghost as quiet) and add link and danger-outline / filled danger.
  • Lists: one primary in the head, quiet Refresh at the toolbar end. Forms: primary Create/Save with secondary Cancel, right-aligned. Details: at most one primary, secondary actions beside it, destructive actions in the danger zone.
